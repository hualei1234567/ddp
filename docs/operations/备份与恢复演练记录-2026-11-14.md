# 备份与恢复演练记录（2026-11-14）

> 关联：审计 R-4（P1「无备份 / 恢复演练记录」）。
> 结论：**备份可恢复，结构与数据全部一致**。脚本可重复执行：
> `bash scripts/ops/backup-restore-drill.sh`。

## 1. 演练环境

| 项 | 值 |
|---|---|
| 数据库 | `ddp-postgres`（postgres:16-alpine，容器内 healthy） |

| 迁移版本 | `0023`（device and sensor status semantics） |
| 恢复目标 | **独立新库** `ddp_restore_drill`，绝不覆盖源库 |
| 演练日期 | 2026-11-14 |

## 4. 对象存储的边界（重要）

本轮**只验证了 PostgreSQL 的备份恢复**。MinIO 对象数据未做实际恢复验证：

- 当前镜像不含 `mc` 客户端，`mc ls --recursive` 无法执行，脚本据此跳过并显式打印；
- 演练库中 `raw_assets` 等表为 0 行，没有真实对象引用可比对。

**这意味着：数据库恢复成功 ≠ 数据资产完整。** 真实场景下 DB 里的
`object_key` / `sha256` 与 MinIO 中的对象必须成对存在。本项作为**未闭环缺口**
登记如下：

| 缺口 | 影响 | 补齐方式 | 优先级 |
|---|---|---|---|
| 对象存储无备份/恢复验证 | 元数据恢复后发现对象缺失，链路断裂 | 阶段 7 数据平面落地真实对象后，补一次「导出桶 → 清空测试桶 → 回灌 → 逐对象比对 sha256」的演练 | P1（阶段 7 内） |
| 无定时备份任务 | 依赖人工执行 | 阶段 8 工程化时接入 cron/系统定时 + 保留策略 + 告警 | P2 |

## 5. 可重复执行

```bash
bash scripts/ops/backup-restore-drill.sh
```

脚本的安全边界（写进脚本头部注释）：

- 只在本地 `docker compose` 服务上执行，不触碰 staging/生产；
- 恢复目标是独立新库，源库 `ddp` 全程只读；
- 结束时清理临时库与临时目录，不留残留（`trap EXIT`）。

## 6. 顺带验证的迁移事实

本轮同时确认 **迁移 0023 在真实 PostgreSQL 16 上可执行**：

```
INFO  [alembic.runtime.migration] Running upgrade 0022 -> 0023, device and sensor status semantics
```

并且在 `DDP_TEST_POSTGRES_URL` 指向真实 PG 时，后端全量测试
**792 passed / 0 skipped**（此前 SQLite 下 18 条 PG 守卫用例被 skip）。
这是"守卫真的在 PG 上生效"的直接证据。
