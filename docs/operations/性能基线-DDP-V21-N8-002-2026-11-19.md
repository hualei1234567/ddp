## 4. 数据与场景

- 每个规模独立临时库，执行完整 Alembic 迁移（60 个版本）后写入合成数据；表结构与线上一致。
- 每规模：`episodes` = `raw_assets` = `datasets` = 规模值；`raw_assets` 走 `VALIDATING → VALID` 合法状态转移，`datasets` 走 `DRAFT → ACTIVE`，不绕过库内守卫。
- 分页场景：无游标首页 + 50% 位置 + 90% 位置（游标编码与 API 完全同口径）；`limit` 20/100；并发 1/4/8。
- 过滤场景：`episodes?quality_status=PASS&limit=20`，并发 1。
- 视频场景：3 个媒体资产、每个 4 MiB 合成对象；先调用 `/media-assets/{id}/playback` 预签名，再以 `Range: bytes=<offset>-<offset+65535>` 读取首段/中段/尾段；测量前断言 206 与 `Content-Range` 总长。
- 统计口径：最近秩百分位（nearest-rank）；吞吐 = 完成请求数 / 批次墙钟；非期望状态码与传输异常都计入错误。

## 7. 限制与风险

- 结果为**本机开发环境**数值；staging/生产硬件、网络与 PG 参数不同，不可直接外推（`BLOCKED`：staging 主机不可达）。
- 只测只读列表与视频 Range；未测并发写入、导入/标注 Worker、队列积压、长稳与内存增长。
- 单 API 进程、无反向代理、无限流；生产多副本与限流下的表现不同。
- 合成数据没有真实 Episode 的关联行与复杂过滤；10K 以内规划器可能仍选择全表顺序扫描。
- 共享开发机负载会造成 p95 抖动；脚本已记录运行起止负载并在超限时标记 `noisy_environment`，但不能消除噪声。
- 临时库/对象清理已实测生效；若进程被强杀（SIGKILL），可能残留 `ddp_perf_*` 库与 `perf-baseline/` 对象，需要手工清理。
