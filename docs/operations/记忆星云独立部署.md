# 记忆星云独立部署（不依赖 DSH）

> 2026-11-29 ｜ 目标：把 `dsh-memory-nebula` 从 DeepSeek Harness 内嵌插件抽离为**独立常驻服务**，任何进程（DDP 的 `check.sh`、任意 Agent、浏览器面板）都可直接使用。

## 1. 结论先行

| 项 | 值 |
|---|---|
| 上游开源项目 | [yb-zhai/agent-memory](https://github.com/yb-zhai/agent-memory)（`dsh-memory-nebula` v1.3.8） |
| 本机工作副本 | `/Users/hualei/deepseek/agent-memory`（git remote 即上游） |
| 运行方式 | `node server.js`（零依赖，只用 Node 内置模块，无 npm 依赖） |
| 监听 | `127.0.0.1:8898`（本机回环，不对外） |
| 数据目录 | `~/.memory-nebula`（JSONL 四文件：`nodes.jsonl` / `edges.jsonl` / `trace.jsonl` / `index.json`） |
| 进程托管 | launchd `com.local.memory-nebula`（`RunAtLoad` + `KeepAlive`，开机自启、崩溃自动拉起） |
| 启动器 | `~/bin/memory-nebula` |
| 日志 | `~/.memory-nebula/service.log`、`service.err.log` |

**关键事实**：引擎与面板服务本身零依赖、可完全脱离 DSH 独立运行（README §2「作为独立 HTTP 服务」）。此前之所以"离不开 dsh"，只是因为从来没有单独起过它，而是由 dsh desktop profile 通过 `pnpm link` 内嵌启动。

## 2. 部署步骤（可复现）

### 2.1 取源码

```bash
git clone https://github.com/yb-zhai/agent-memory.git ~/deepseek/agent-memory
```

### 2.2 启动器 `~/bin/memory-nebula`

```bash
#!/bin/sh
export MEMORY_NEBULA_DATA_DIR="${MEMORY_NEBULA_DATA_DIR:-$HOME/.memory-nebula}"
export MEMORY_NEBULA_PORT="${MEMORY_NEBULA_PORT:-8898}"
export MEMORY_NEBULA_DISABLE_HINDSIGHT="${MEMORY_NEBULA_DISABLE_HINDSIGHT:-1}"
NODE_BIN="${NODE_BIN:-$(command -v node)}"
[ -x "$NODE_BIN" ] || NODE_BIN="/Users/hualei/.nvm/versions/node/v24.22.1/bin/node"
exec "$NODE_BIN" /Users/hualei/deepseek/agent-memory/server.js
```

> `MEMORY_NEBULA_DISABLE_HINDSIGHT=1`：不依赖可选的 Hindsight 语义增强（未安装时它会后台探测并降级为纯本地，显式禁用可省掉探测噪音）。若将来部署 Hindsight，去掉此变量并设 `MEMORY_NEBULA_HINDSIGHT_URL`。

### 2.3 launchd 托管 `~/Library/LaunchAgents/com.local.memory-nebula.plist`

```xml
<key>Label</key><string>com.local.memory-nebula</string>
<key>ProgramArguments</key>
<array><string>/bin/sh</string><string>/Users/hualei/bin/memory-nebula</string></array>
<key>EnvironmentVariables</key>
<dict>
  <key>MEMORY_NEBULA_DATA_DIR</key><string>/Users/hualei/.memory-nebula</string>
  <key>MEMORY_NEBULA_PORT</key><string>8898</string>
  <key>MEMORY_NEBULA_DISABLE_HINDSIGHT</key><string>1</string>
</dict>
<key>RunAtLoad</key><true/>
<key>KeepAlive</key><true/>
```

注册与启停：

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.local.memory-nebula.plist
launchctl kickstart -k gui/$(id -u)/com.local.memory-nebula   # 重启
launchctl bootout   gui/$(id -u)/com.local.memory-nebula       # 停止
launchctl print     gui/$(id -u)/com.local.memory-nebula       # 状态/pid/exit code
```

### 2.4 数据单一真源

为避免 dsh 插件与独立服务各写一份 JSONL，**只保留一个数据目录**：

```bash
# dsh 旧目录退役并软链到独立目录（保留时间戳备份，可回滚）
mv ~/.dsh/memory-nebula-data ~/.dsh/memory-nebula-data.retired-<ts>
ln -s ~/.memory-nebula ~/.dsh/memory-nebula-data
```

> JSONL 引擎是"启动时全量载入内存、追加写"的模型（上游 README 明确：多进程同时写同一库，彼此看不到实时更新）。**同一时刻只允许一个进程持有该目录**——独立服务常驻后，不要再让 dsh 内嵌实例启动在同一目录。

## 3. 验收（实测记录 2026-11-29）

| 检查 | 结果 |
|---|---|
| `curl http://127.0.0.1:8898/healthz` | `200`，`mode=local`，`ready=true` |
| 面板 `GET /` | `200`（3D 星云可视化） |
| `launchctl bootout` 后 | `000`（服务立即停止，确认不是 dsh 在顶） |
| `launchctl bootstrap` 后 | 自动恢复 `200`（RunAtLoad 生效） |
| `scripts/sync_memory_nebula.py --require-server` | 46 张 ACTIVE 卡片 → 幂等更新 46 / 撤回点亮 4，退出码 0 |

## 4. 与 DDP 的接口契约

DDP 侧只依赖三个端点（`scripts/sync_memory_nebula.py`，全仓唯一调用点）：

| 端点 | 用途 |
|---|---|
| `GET /healthz` | 探活；校验 `service == "dsh-memory-nebula"`（沿用上游标识，不做私有化改名以免与上游断代） |
| `POST /remember` | 幂等写入一张记忆卡（`text/kind/importance/tags/source/meta`），`deduped=true` 表示更新而非新增 |
| `GET /recall?q=` | 召回预热（赫布连边点亮） |

`check.sh` 第 10 步调用 `sync_memory_nebula.py`，服务未运行时**静默放行**（CI/离线安全），不因本机面板未开而红。

## 5. 已知边界

- **单进程写**：不要同时跑 dsh 内嵌实例与独立服务指向同一目录；
- **无鉴权**：只监听回环地址，不要改成 `0.0.0.0`；
- **端口**：8898 被占用时启动器会失败；改 `MEMORY_NEBULA_PORT` 并同步软链/脚本端口探测范围（`DEFAULT_PORTS = 8898..8910`）；
- **Node 版本**：需 Node ≥ 18；本机经 nvm 固定到 v24.22.1，launchd 环境不读 nvm，故启动器里显式回退到绝对路径。

## 6. 卸载

```bash
launchctl bootout gui/$(id -u)/com.local.memory-nebula
rm ~/Library/LaunchAgents/com.local.memory-nebula.plist ~/bin/memory-nebula
# 数据保留在 ~/.memory-nebula；恢复 dsh 内嵌：删软链并把 retired 目录改回原名
```
