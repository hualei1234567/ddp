# 本地开发令牌

## 为什么需要

浏览器端没有登录流程（产品侧尚未实现，登记为 `PLANNED`）。所有 `/api` 请求都要求
`Authorization: Bearer <JWT>`，没有令牌时后端返回 `401 not_authenticated`，界面
表现为整页「加载失败」。

本地开发栈（compose，仅 loopback 可访问）用 nginx 在转发 `/api` 时补上身份，
让界面开箱可用。

## 怎么工作

1. `.env` 里写 `DDP_WEB_DEV_AUTH="Bearer <JWT>"`；
2. `docker-compose.yml` 把它作为 `DDP_WEB_DEV_AUTH` 传给 `web` 容器；
3. `infra/docker/nginx.conf.template` 里的 `map` 只在**客户端没带**
   `Authorization` 时注入它，客户端自己带的令牌原样透传；
4. 直连 `:8000` 不经过 nginx，仍然要求真实令牌（注入只发生在边缘代理）。

令牌为空时渲染成空头，后端把空头视为「未提供」（`extract_bearer_token`），
行为与不注入完全一致。

## 生成令牌

```bash
backend/.venv/bin/python - <<'PY'
import datetime
from pathlib import Path
import jwt

env = dict(
    line.partition("=")[::2]
    for line in Path(".env").read_text().splitlines()
    if "=" in line and not line.startswith("#")
)
now = datetime.datetime.now(datetime.timezone.utc)
token = jwt.encode(
    {
        "sub": "<项目成员 user_id>",          # 必须是对应项目的成员
        "iss": env["DDP_JWT_ISSUER"],
        "aud": env["DDP_JWT_AUDIENCE"],
        "iat": int(now.timestamp()),
        "exp": int((now + datetime.timedelta(days=30)).timestamp()),
    },
    env["DDP_JWT_SECRET"],
    algorithm="HS256",
)
print(token)
PY
```

把输出写进 `.env` 的 `DDP_WEB_DEV_AUTH="Bearer <token>"`，然后
`docker compose --profile app up -d --force-recreate web`。

`sub` 必须是目标项目的成员，否则接口会返回 403/404——签发的令牌本身有效，
只是不属于那个项目。换项目或换用户后需要重签。

## 安全边界

- **只用于本机开发栈**：令牌会出现在 `web` 容器的 nginx 配置里，任何能访问
  `:8088` 的人都会以该身份操作。不要用于共享环境、staging 或生产。
- `.env` 已在 `.gitignore` 中，令牌不入库。
- 令牌泄露等同于身份泄露：它是该用户在平台上的全部权限。发现泄露就重签并替换。
- 关闭：删掉 `.env` 里的 `DDP_WEB_DEV_AUTH` 行并重建 `web` 容器，界面回到需要
  手动在「设置令牌」里粘贴的状态。

## 与「设置令牌」按钮的关系

前端右上角的「设置令牌」把令牌存进 `sessionStorage`（仅当前标签页，刷新新标签
即失效）。两者可以共存：手动设置的优先，nginx 只在客户端没带时才补。
