## 1. 平台是什么

DDP（具身智能数据闭环平台）：从**数据接入 → 处理切片 → 标注质检 → 数据集构建 → 训练消费 → 评测反馈**的全链路数据平台。技术栈：

| 层 | 技术 | 入口 |
|---|---|---|
| 后端 API | Python 3.11 + FastAPI + SQLAlchemy 2 + Alembic | `backend/app`，容器 `ddp-api`（端口 8000） |
| 异步任务 | 10 个独立 Worker 容器（校验/导入/处理/导出/质检/域事件/用量快照等） | `backend/app/workers` |
| 数据库 | PostgreSQL 16 | `ddp-postgres`（仅内网，不对外暴露） |
| 缓存/队列 | Redis 7.4 | `ddp-redis`（仅内网） |
| 对象存储 | 自建 MinIO（S3 兼容，分片直传，>10GB 零云存储费） | `ddp-minio`（9000） |
| 前端 | React 19 + antd 5 + Vite | `apps/web`，Cloudflare Pages `ddp-web` |
| 契约 | OpenAPI（`packages/contracts/openapi.yaml`，当前 1.40.0 / 276 路径） | `--strict` 双向 parity 零漂移 |
| 可观测 | Prometheus + Alertmanager + OTel（`--profile monitoring`） | 告警闭环见 `docs/ops/alerting-runbook.md` |
| 边缘采集 | Edge Agent（纯出站拉取，工作站零入站端口） | `services/edge-agent` |

服务编排一份权威定义：根目录 `docker-compose.yml`（26 个服务，应用容器在 `app` profile，监控在 `monitoring` profile）。

## 2. 部署形态（三选一）

### 2.1 本地开发（日常开发/测试）

```bash
docker compose up -d                    # 只起 postgres/redis/minio/migrate
cd backend && cp .env.example .env      # 本地默认值即可
.venv/bin/uvicorn app.main:app --reload # API 8000
cd apps/web && npm run dev              # 前端 Vite dev server
make check                              # 提交前全量闸口（ruff+pytest+tsc+build+secret+契约+记忆库）
```

### 2.2 路径 A：公网 VPS + Nginx（推荐生产）

```bash
cp infra/deploy/env.production.example .env   # 替换 4 个 <REPLACE_WITH_...> 随机密钥
docker compose -f docker-compose.yml -f infra/deploy/docker-compose.prod.yml --profile app up -d --build
curl -fsS http://127.0.0.1:8000/health
# 宿主机 Nginx + TLS：参考 infra/deploy/nginx-origin.conf.example
```

域名规划（Cloudflare DNS）：

| 域名 | 承载 | 代理状态 |
|---|---|---|
| `www.ddp.online` | Cloudflare Pages `ddp-web` | 橙云 Proxied |
| `api.ddp.online` | VPS Nginx → `127.0.0.1:8000` | 橙云 Proxied |
| `s3.ddp.online` | VPS Nginx → `127.0.0.1:9000` | **灰云 DNS Only**（分片直传必须绕开 CF 100MB 请求体限制） |

### 2.3 路径 B：本机 Docker + Cloudflare Tunnel（零 VPS，已实测）

> 实测记录：2026-11-28 `online_deploy_verify.py` **17/17 passed**；前端 `https://ddp-web.pages.dev/`，后端 Quick Tunnel `https://mitsubishi-walk-already-momentum.trycloudflare.com`（临时域名，每次重启变化）。

```bash
cp infra/deploy/env.production.example .env
export CF_TUNNEL_TOKEN="<Cloudflare Zero Trust → Tunnels 的 Token>"
docker compose -f docker-compose.yml -f infra/deploy/docker-compose.prod.yml \
  -f infra/deploy/docker-compose.tunnel.yml --profile app up -d --build
# 验收
backend/.venv/bin/python scripts/ops/online_deploy_verify.py --skip-offline \
  --api-url https://api.ddp.online --web-url https://www.ddp.online --s3-url https://s3.ddp.online
```

**已知边界**：Cloudflare 免费版 Tunnel 单请求体上限 100MB；DDP 上传走 S3 Multipart（默认分片 5–64MB）不受影响。自定义域名 `www.ddp.online` 已在 Pages 绑定，等域名注册商 NS 切到 `dakota/elinore.ns.cloudflare.com` 后自动生效。

### 2.4 上线自检清单

```bash
# 离线红线自检（.env 弱密钥/占位凭据直接拒绝）
python3 scripts/ops/online_deploy_verify.py --env-file .env
# CI/评审态（不依赖本机 .env）
python3 scripts/ops/online_deploy_verify.py --skip-env
```

数据库迁移自动执行（`ddp-migrate` 容器，Alembic 单 head，当前 0088）。回滚：`alembic downgrade <rev>`；任何 Schema 变更必须可回滚（CLAUDE.md 硬约束）。

## 3. 用户认证与轻量登录

平台当前采用**轻量 JWT 登录**（HS256 Bearer，72 小时有效），面向开源学习/单团队场景；完整 OAuth/注册流程属后续范围。

```bash
# 宿主机幂等建用户 + 签发（推荐）
backend/.venv/bin/python scripts/ops/issue_jwt.py --display-name "开源管理员" --role admin
# 或容器内签发（完整示例见 infra/deploy/README.md §3）
```

前端：打开 `https://www.ddp.online` → 右上角 **「轻量登录」** → 粘贴 `BEARER_JWT` → 「验证并登录」→ 抽屉内一键切换项目。令牌只保存在本机临时文件/浏览器，不入库不入仓。

**轮换/吊销**：JWT 无服务端会话表，吊销靠换 `DDP_JWT_SECRET`（全站失效）或等过期；生产建议 `--hours` 签短周期。

## 4. 模块权限矩阵（服务端强制）

### 4.1 平台角色（JWT claim `platform_role`）

| 角色 | 能力 |
|---|---|
| `member` | 需被加入项目才有任何项目数据可见性 |
| `admin` | 平台级管理（用户登记、平台配置） |

### 4.2 项目角色（`project_members.role`，权威实现 `backend/app/domain/identity/models.py:ROLE_PERMISSIONS`）

| 动作 | viewer | editor | owner |
|---|:-:|:-:|:-:|
| `READ`（读项目内一切业务数据） | ✅ | ✅ | ✅ |
| `WRITE`（上传/导入/建运行/建数据集等） | ❌ | ✅ | ✅ |
| `VALIDATE`（担任标定记录校验人） | ❌ | ✅ | ✅ |
| `DELETE`（删除类操作） | ❌ | ❌ | ✅ |
| `MANAGE_MEMBERS`（成员与角色管理） | ❌ | ❌ | ✅ |
| `MANAGE_EDGE_AGENTS`（边缘代理配对/管理） | ❌ | ❌ | ✅ |

硬规则（不可配置）：

- **未列出的动作一律拒绝**，禁止「未知动作默认放行」；
- **项目必须始终至少有一名 OWNER**（最后一个 owner 不可降级/移除）；
- **`project_id` 隔离由服务端强制**，不信任客户端传入；跨项目访问抛 `CrossProjectAccessError`；
- 前端动作按钮只按服务端返回的 **`allowed_actions`** 渲染——前端不承载权威校验。

### 4.3 Edge Agent 凭据分层

| 通道 | 凭据 | 说明 |
|---|---|---|
| 控制面（heartbeat/lease/assignments） | `ddp_agt_...` Agent Token | 一次性配对码经 `/pair` 换取，与用户 JWT 彻底隔离 |
| 数据面（upload-sessions） | 项目写权限 JWT | 建议专设采集操作员账号签发短期项目 JWT |

详见 `docs/ops/hardware-pilot-runbook.md`（真机采集，当前 A 级证据 `BLOCKED` 待硬件）。

## 7. 事件与告警

- **指标**：`/metrics`（Bearer Token 保护，见 `docs/operations/Prometheus指标抓取与metrics访问控制.md`）；
- **告警**：Alertmanager → `services/alert-receiver`（鉴权/验签/去重闭环，已演练实收）；

- **Outbox**：投递类事件必须有消费者与测试（`scripts/check_outbox_events.py` 闸口）。

## 8. 常见问题

| 现象 | 处置 |
|---|---|
| 公网 401 | JWT 过期（72h）→ 重新 `issue_jwt.py` 签发并轻量登录 |
| 上传 >100MB 失败（Tunnel 路径） | 走 S3 Multipart 分片；确认 `s3.ddp.online` 灰云直连（路径 A） |
| `online_deploy_verify` 红线 | 多为 `.env` 占位密钥未替换；看输出指明的项 |
| 迁移失败 | `docker compose logs migrate`；单 head 校验 `alembic heads` |
| 处理运行某阶段 SKIPPED | 看步骤 `log_summary`：写明缺什么（如「视频解码器未注入」）；SKIPPED≠失败 |
| 训练训练不了 | 训练环境独立 venv（lerobot 0.3.3）；本机 MPS/CPU 已验证，GPU 未验证 |

## 9. 变更与回滚纪律

1. 一切变更走任务分支 + PR（Conventional Commits），`main` 只经 PR 合并；
2. 共享文件（契约/迁移/权限/路由）单一 Owner；契约变更必须 bump `packages/contracts/openapi.yaml` 版本并过 `--strict` parity；
3. 删除类操作：默认拒绝空过滤，dry-run 逐条确认（CLAUDE.md「数据与安全」）；
4. 回滚点：代码 `git revert`；数据库 `alembic downgrade`；前端 Pages 自动保留每次部署的历史版本可一键回退。
