# 演示数据与种子脚本

## 这是什么

`scripts/seed/` 是一套**只走 HTTP API** 的数据种子：按模块把一个真实业务流程从
创建走到终态，把数据留在库里，让界面每个模块都有内容可看。

```bash
backend/.venv/bin/python scripts/seed/run.py            # 全部模块
backend/.venv/bin/python scripts/seed/run.py annotation # 只跑一个
backend/.venv/bin/python scripts/seed/verify.py         # 逐模块核对是否有数据
backend/.venv/bin/python scripts/seed/run.py --list     # 列出模块
```

前置：本地 compose 栈在跑，`.env` 里有 `DDP_WEB_DEV_AUTH`（见
`docs/operations/本地开发令牌.md`）。

## 为什么不直接写数据库

业务规则、状态机、审计、血缘、幂等记录都由服务端产生。直接 INSERT 会造出
「数据库里有、系统里不存在」的假数据：列表能查到，详情点开就崩，审计与血缘
全是空的。种子脚本因此**只调 API**，服务端拒绝就如实报错，不绕过。

唯一例外是 `identity.py`：平台没有注册/用户管理入口（`PLANNED`），
`POST /members` 对不存在的用户返回 404，所以「第二个人」的身份只能由一条
只读查询 + 必要时一条 `users` 插入来准备。

## 模块与覆盖的流程

| 模块 | 文件 | 走完的主链 |
|---|---|---|
| 设备 | `fleet.py` | 机器人/设备/传感器 `PROVISIONED→ACTIVE`，另走 `FAULT→IN_MAINTENANCE→ACTIVE`、`RETIRED`；校准 `DRAFT→SUBMITTED→VALIDATED→ACTIVE`、`REJECTED`、`REVOKED`，复标后旧记录 `SUPERSEDED` |
| 场地 | `locations.py` | `SITE/ROOM/LAB` 创建、改名、按类型过滤、设备挂载 |
| 采集 | `collection.py` | 方案/SOP/场景/动作库 `DRAFT→ACTIVE`；任务 `DRAFT→评审→就绪→指派→进行中→暂停→恢复→提交`；批次同链到 `SUBMITTED` |
| 数据接入 | `datasources.py` | 数据源登记与 `PATCH`；导入 `PENDING→RUNNING→SUCCEEDED`（真实 worker 下载）；质量报告；审核 `PENDING→APPROVED`；另一条 `PENDING→CANCELLED` |
| Episode | `episodes.py` | `PENDING→PROCESSING→READY→QUALITY_CHECKING→ACCEPTED→COMPLETED`、`REJECTED`、`INVALIDATED`、`revision` 新版本 |
| 标注 | `annotation.py` | schema、抽样集、任务（含驳回返工、升级仲裁、取消）、批次、指派、提交、复核、仲裁+投票、金标集+注入+评估、IAA、质检抽样、质量检查、AI 建议 |
| 数据集 | `datasets.py` | 数据集 `DRAFT→ACTIVE→ARCHIVED`；版本 `DRAFT→VALIDATING→READY→FROZEN`；四类策略；跨项目授权 `PENDING_APPROVAL→ACTIVE` 与 `→REJECTED` |
| 导出 | `exports.py` | `QUEUED→RUNNING→SUCCEEDED`，产物清单、下载校验；另一条 `QUEUED→CANCELLED` |
| 训练 | `training.py` | 需求 `DRAFT→SUBMITTED→APPROVED→PLANNED→IN_PROGRESS→SATISFIED`；请求+修订；交付 `DRAFT→READY→DELIVERED→ACCEPTED` 与 `→REJECTED→REWORK→CANCELLED` |
| 模型 | `modelops.py` | 模型 `DRAFT→ACTIVE→DEPRECATED→ARCHIVED`；版本 `DRAFT→READY→RELEASED`；推理服务 `PENDING→DEPLOYING→ACTIVE→STOPPED→RETIRED`；评估、推理任务、反馈、数据缺口 |
| 供应商 | `suppliers.py` | 供应商 `DRAFT→ACTIVE→SUSPENDED→ACTIVE` 与 `→TERMINATED`；到货批次 `ANNOUNCED→…→SCREENING→finalize→CLOSED`；分段决策；验收台账 |
| 治理 | `governance.py` | 四类配额 `PUT` 与版本递增；用量报告 |
| 项目 | `projects.py` | 成员增删改角色（角色恢复到初始值） |

## 纯客户端走不到的终态（产品缺口，不是脚本少走一步）

| 资源 | 终态 | 原因 |
|---|---|---|
| 采集任务 | `DATA_CHECKING` / `ACCEPTED` / `COMPLETED` | `system-data-check` 被排除在公开动作外，系统侧**没有任何触发点**（全仓仅 `state_machines.py:75` 一处定义） |
| Episode | `ARCHIVED` / `FAILED` | `archive` / `system-fail` 未暴露，只在领域迁移表里 |
| 分配 | `EXPIRED` | 只由 worker `expire_due()` 推进，无 HTTP 入口 |
| 评测 / 推理任务 | `SUCCEEDED` | 只能由签名 Adapter 回调推进，本项目未接入 Adapter |
| 训练外部引用 | — | 默认 Gateway 的 `submit` 一律抛 `TrainingAdapterUnavailableError` |
| 数据需求 | `CLOSED` | 要求存在 `SUCCEEDED` 评测，而评测同样依赖 Adapter |

## 种子过程中发现并已修复的缺陷

1. **镜像里没有标定参数契约文件** → 容器内 `POST /calibrations` 必 422（PR #19）
2. **容器 S3 端点被宿主 `.env` 覆盖成 localhost** → 上传/校验/导出 503（PR #19）
3. **配额用量求和返回 numeric** → 配了存储配额后所有上传 422（PR #19）
4. **浏览器端无登录流程导致整页加载失败**（PR #18，nginx 注入本地开发令牌）

## 数据保留

脚本**不清理任何数据**，重复运行只会新增带新时间戳的记录。想回到干净状态需要
单独批准的重置操作（会删数据，不在本脚本范围内）。

已知副作用：`identity.ensure_reviewer` 会在需要时把既有用户加入项目；
`ensure_second_owner` 会把评审人提升为 owner（数据集授权审批需要第二位负责人），
`projects` 模块结束时恢复到初始角色。

## 技术债

- `annotation.py` 1844 行，超过「800 行原则上拆分」。建议拆为
  `annotation_catalog.py`（schema/抽样集）、`annotation_work.py`（任务/批次/指派）、
  `annotation_results.py`（提交/复核/仲裁）、`annotation_quality.py`（金标/抽检/质检/IAA/AI）。
- 各模块重复实现了对象上传 helper，建议下沉到 `client.py`。
