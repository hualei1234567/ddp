## 3. 冻结字段与约束

### 3.1 项目隔离与分页

- 带项目路径的路由由服务端校验成员资格；无路径前缀的血缘/下载端点使用
  `project_id` 查询参数，仓储仍强制项目过滤。
- 跨项目资源 404 `resource_not_found`；非成员 403 `forbidden`。
- `cursor` 不透明，非法 422 `validation_failed`；`limit` 默认 20、范围 1–100；
  分页响应 `{items, next_cursor}`。

### 3.2 `If-Match` 与 `Idempotency-Key`

必须 `If-Match`：CollectionTask/Batch PATCH 与动作；UploadSession `complete`/`abort`；
Episode 动作/`revisions`；IngestionJob 动作。缺失 428，失配 409，格式非法 422。

| 端点组 | Idempotency-Key |
|---|---|
| CollectionTask/Batch 创建与动作 | 可选 |
| UploadSession 创建、`complete`、`abort` | 可选 |
| Episode 创建、动作、`revisions` | **必填**（缺失 428） |
| IngestionJob 创建、动作 | **必填**（缺失 428） |

成功响应按实现返回 `ETag: "<version>"`；创建/完成/动作类幂等端点在重放时返回
`Idempotent-Replayed: true|false`。Collection 端点当前不返回 `ETag`。

### 3.3 上传会话与分片

- `parts/{part_number}/url` 请求体可选；提供 `sha256` 时绑定
  `x-amz-checksum-sha256`，ack 与绑定值不一致返回 409 `upload_part_conflict`；
  省略时保持旧客户端行为。
- `ack` 同分片同 ETag/大小/SHA256 幂等；不同内容 409。
- `complete` 以对象存储 `ListParts` 为权威；缺失 409 `upload_incomplete`；
  大小不符 422 `size_mismatch`；签名不符 422 `file_signature_mismatch`；
  Hash 不符 422 `hash_mismatch`；返回 202，含
  `upload_session.uploaded_parts`、`raw_asset`、`deduplicated`、
  `validation_job_id`、`replayed`。

### 3.4 RawAsset

冻结响应字段：`asset_id`、`project_id`、`code`、`source_type`、`collection_task_id`、
`batch_id`、`upload_session_id`、`original_filename`、`object_key`、`size_bytes`、
`content_type`、`format`、`sha256`、`status`、`captured_at`、`ingested_at`、
`device_ids`、`sensor_ids`、`sensor_snapshot`、`device_time_raw`、`raw_metadata`、
`storage_class`、`retention_policy_id`、`quarantine_reason`、`quarantine_codes`、
`scan_report_key`、`verified_at`、`archived_at`、`tombstoned_at`、
`duplicate_of_asset_id`、`uploaded_by`、`version`、`created_at`、`updated_at`、
`created_by`、`updated_by`。

内容字段创建后不可变；`download-url` 仅对 `VALID`/`ARCHIVED` 签发，否则 422
`asset_not_usable`。

### 3.5 Episode

冻结响应字段：`episode_id`、`project_id`、`episode_lineage_id`、`episode_version`、
`code`、`task_id`、`batch_id`、`robot_id`、`device_ids`、`sensor_ids`、`status`、
`quality_status`、`annotation_status`、`success`、`failure_reason`、`scene_labels`、
`language_instruction`、`start_time_ns`、`end_time_ns`、`duration_ns`、`time_base`、
`canonical_schema_version`、`pipeline_id`、`pipeline_version`、
`segmentation_rule_version`、`frame_count`、`calibration_snapshot`、`manifest_key`、
`manifest_sha256`、`preview_refs`、`supersedes_id`、`attempt`、`max_attempts`、
`version`、`created_at`、`updated_at`、`created_by`、`updated_by`。

创建必填：`raw_asset_ids`、`segmentation`、`time_base`、`calibration_snapshot`、
`canonical_schema_version`、`pipeline_id`、`pipeline_version`。
`raw_asset_ids` 必须引用同项目 `VALID`/`ARCHIVED` 资产；`MANUAL_TIME_RANGE` 必须提供
起止时间，`RULE` 必须提供 `rule_parameters`；`time_base.sync_status` 为
`UNVERIFIED`/`FAILED` 时禁止创建；`calibration_snapshot` 不得为空且每项必须含
`calibration_id`、`calibration_version`、`checksum`、`target_type`、`target_id`、
`schema_version`。

动作约束：`ready` 必须提供 `manifest` 与 `frame_count`，禁止 `quality_status`；
`quality-result` 必须提供 `quality_status`（`PASS`/`WARN`/`FAIL`）；
`reject`/`invalidate` 必须提供 `reason`；其余动作禁止 `manifest`/`frame_count`。

### 3.6 IngestionJob

冻结响应字段：`job_id`、`project_id`、`job_type`、`raw_asset_ids`、
`input_manifest_key`、`idempotency_key`、`status`、`attempt`、`max_attempts`、
`timeout_sec`、`pipeline_id`、`pipeline_version`、`parser_id`、`parser_version`、
`config_hash`、`started_at`、`finished_at`、`error_code`、`error_summary`、
`output_refs`、`log_ref`、`metrics`、`version`、`created_at`、`updated_at`、
`created_by`、`updated_by`。

创建必填：`job_type`、`timeout_sec`（1–86400）；`raw_asset_ids` 与
`input_manifest_key` **至少提供一个**。资产必须同项目且为 `VALID`/`ARCHIVED`
（`VALIDATE` 允许 `VALIDATING`）。`cancel` 必须提供 `reason`；`retry` 仅允许
`FAILED` 且 `attempt < max_attempts`，否则 409 `job_not_retryable`。

## 4. 错误码

| HTTP | 错误码 |
|---|---|
| 401 | `not_authenticated` |
| 403 | `forbidden` |
| 404 | `resource_not_found`、`not_found`、`object_missing` |
| 409 | `state_transition_invalid`、`version_conflict`、`resource_immutable`、`duplicate_resource`、`conflict`、`idempotency_key_reused`、`upload_incomplete`、`upload_part_conflict`、`upload_session_not_uploading`、`job_not_retryable`、`job_timeout`、`episode_overlap_conflict`、`lineage_conflict` |
| 410 | `upload_session_expired` |
| 413 | `file_too_large` |
| 415 | `file_type_unsupported` |
| 422 | `validation_failed`、`filename_invalid`、`file_signature_mismatch`、`hash_mismatch`、`size_mismatch`、`asset_not_usable`、`manifest_hash_mismatch`、`manifest_schema_invalid`、`calibration_not_active`、`episode_time_base_invalid` |
| 428 | `precondition_required` |
| 429 | `rate_limited` |
| 503 | `object_storage_unavailable` |

错误体 `{"error": {"code", "message", "request_id", "details?"}}`；`details` 可选，
客户端按 `code` 分支，未知错误不得默认成功。

## 5. 与草案的差异

1. Episode 无 `PATCH /episodes/{id}`；元数据修改通过 `POST /episodes/{id}/revisions`。
2. Episode 无 `manifest` 下载与 `download-url` HTTP 端点。
3. Episode 动作白名单不含 `retry`/`archive`/`system-*`。
4. RawAsset 无 `revalidate`/`release-quarantine`/`tombstone`/`ingest` HTTP 端点。
5. 血缘与 RawAsset `download-url` 使用 `project_id` 查询参数，无项目路径前缀。
6. 血缘响应 `{items, direction}`，方向 `forward`/`reverse`，深度 1–5，无 cursor。
7. `parts/{n}/url` 的 `sha256` 可选；`complete` 返回 `uploaded_parts`。
8. Episode/IngestionJob 写路径 `Idempotency-Key` 必填；Collection/UploadSession 可选。
9. Episode 创建使用 `task_id`，并要求 `time_base`、`canonical_schema_version`、
   `pipeline_id`、`pipeline_version`。
10. IngestionJob 响应使用 `raw_asset_ids` 数组，不含单值 `raw_asset_id`。

## 6. 版本与变更流程

- 当前 `ddp.stage2/1.0.0`；HTTP 主版本 `/api/v1`。
- 非破坏性变更：更新契约与测试，执行
  `bash packages/contracts/scripts/check-stage2-freeze.sh --check`。
- 破坏性变更：提交影响分析 → 新建 ADR 并获用户批准 → 提升契约版本
  （如 `ddp.stage2/1.1.0` 或 `/api/v2`）→ 更新契约/基线/两端/测试 →
  `--freeze --force` 生成新基线，保留旧基线 → 通知归档。
- `packages/contracts/**` 由 System Architect 单一 Owner；基线/报告未审阅不得提交。

## 8. 风险与回滚

- CI 必须使用整个 `packages/contracts` 目录，否则 `fragments/` 相对引用解析失败；
  或使用 `--freeze` 生成的自包含 bundle 基线。
- 未执行 lint/oasdiff，可能存在语法或引用问题；首次 CI 必须先跑通。
- 旧草案生成的前端类型需切换到 `packages/contracts/openapi.yaml`。
- 回滚点：仅 `packages/contracts`、`docs`、`scripts` 文件变更；不涉及数据库、
  对象存储或生产数据。历史基线不删除。
