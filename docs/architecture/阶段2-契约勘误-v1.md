# 阶段 2 契约勘误 v1

- 状态：草案（与主文档同步生效）
- 日期：2026-11-08
- 适用范围：`docs/architecture/阶段2-采集上传RawAsset-Episode契约-v1.md` 与 `contract-draft/collection/state-machines.v1.json`
- 说明：本文件用于消除几处容易误读的“终态”表述与跨附件章节引用；以本勘误、`state-machines.v1.json` 与 `upload-session.v1.schema.json` 为准。

## 勘误 1：RawAsset 的 ARCHIVED

主文档 §4.4 曾写“`VALID → ARCHIVED（终态）`”，与同节允许 `ARCHIVED → TOMBSTONED` 冲突。现明确：

- `ARCHIVED` 是**归档可用态**，不是绝对终态；
- `ARCHIVED` 仍可被 Episode 引用（存储层归档，不等于失效）；
- 除 `ARCHIVED → TOMBSTONED`（双人审批）外，不得从 `ARCHIVED` 迁出到其他状态；
- 机器可读 `state-machines.v1.json` 的 `RawAsset.terminal` 为 `["TOMBSTONED"]`，并通过 `terminal_note` 说明 `ARCHIVED` 的墓碑例外。

## 勘误 2：REJECTED 的墓碑例外

主文档 §4.4 末句“`REJECTED` 与 `TOMBSTONED` 才是绝对终态，不可再迁移”应理解为：

- `REJECTED` 对业务使用是不可用终态，**不得**迁移到 `VALID/QUARANTINED/VALIDATING`；
- `REJECTED → TOMBSTONED` 是管理性墓碑迁移，允许在双人审批下执行；
- `TOMBSTONED` 是唯一绝对终态，`TOMBSTONED → *` 全部禁止；
- 机器可读 `state-machines.v1.json` 的 `RawAsset.terminal` 仅列 `TOMBSTONED`，并保留 `REJECTED/ARCHIVED → TOMBSTONED` 迁移。

## 勘误 3：IngestionJob 的 FAILED

主文档 §4.5 与状态机均允许 `FAILED → QUEUED` 重试；`FAILED` 不是无条件终态。现明确：

- 当错误可重试且 `attempt < max_attempts` 时，允许 `FAILED → QUEUED`，`attempt+1`；
- 达到 `max_attempts` 或错误不可重试时，`FAILED` 为终态；
- `FAILED → RUNNING` 永远禁止，必须先重新入队；
- 机器可读 `state-machines.v1.json` 的 `IngestionJob.terminal` 只列 `SUCCEEDED`、`CANCELLED`，并通过 `terminal_note` 说明 `FAILED` 条件终态。

## 勘误 4：UploadSession 增加异步校验状态

`complete` 返回 202 后，整文件 Hash/签名/扫描异步执行；命中既有资产时也需要让客户端看到“这次上传是否真实一致”。因此 `UploadSession` 增加：

- `verification_status`：`PENDING/VERIFIED/REJECTED`；
- `verification_error_code`：失败稳定错误码；
- `verified_at`：校验完成时间。

规则：

- 会话创建与分片阶段为 `PENDING`；
- VALIDATE Job 成功且无内容冲突 → `VERIFIED`；
- 实际 Hash/签名/扫描失败或声明内容与既有资产不一致 → `REJECTED`，并写 `verification_error_code`；
- `deduplicated=true` 时，只有 `VERIFIED` 后才允许建立 `raw_asset_links`；`REJECTED` 不得建立使用关系。

## 勘误 5：动作白名单按实体区分

OpenAPI 草案的 `action` 路径参数使用任务动作并集；服务端必须按实体白名单二次校验：

- 任务：`submit-review`、`return-draft`、`approve`、`ready`、`assign`、`start`、`pause`、`resume`、`block`、`unblock`、`submit`、`accept`、`reject`、`rework`、`complete`、`cancel`。
- 批次：`ready`、`start`、`pause`、`resume`、`block`、`unblock`、`submit`、`accept`、`reject`、`rework`、`cancel`。
- Episode：`quality-check`、`accept`、`reject`、`retry`、`complete`、`archive`、`invalidate`。

不属于该实体白名单的 `action` 返回 `422 validation_failed`，不得拼接到 SQL/状态字段。

## 勘误 6：OpenAPI 外部 Schema 引用

`openapi.stage2.v1.yaml` 通过相对 `$ref` 引用同目录 JSON Schema：

- `upload-session.v1.schema.json`
- `upload-complete-request.v1.schema.json`
- `raw-asset.v1.schema.json`
- `episode.v1.schema.json`
- `lineage-edge.v1.schema.json`

校验器必须支持 OpenAPI 3.1 的 JSON Schema `$ref`；若使用的工具不支持外部引用，应先把这些 Schema 打包/内联，而不是跳过校验。
