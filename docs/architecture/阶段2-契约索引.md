## 已冻结端点

- CollectionTasks / CollectionBatches：列表、创建、详情、修改、动作。
- UploadSessions：创建、断点详情、分片列表、`parts/{n}/url`（可选 `sha256`）、
  `parts/{n}/ack`、`complete`（202，返回 `uploaded_parts`）、`abort`。
- RawAssets：列表、详情、`lineage`、`download-url`。
- Episodes：创建、列表、详情、`actions/{action}`、`revisions`、`lineage`。
- IngestionJobs：创建、列表、详情、`actions/{action}`（`cancel`/`retry`）。

未进入本冻结：隔离放行、墓碑、重新校验、Job 日志 URL、Episode Manifest 下载、
通用血缘节点遍历、`raw-assets/{id}/ingest`。

## 关键冻结决策

1. 上传传输态（`UploadSession`）与资产态（`RawAsset`）分离；RawAsset 在完成时登记，
   初始 `VALIDATING`。
2. 分片预签名直传 + 分片确认 + `ListParts` 权威核对；整文件 Hash 异步校验；
   `complete` 返回 202。
3. `parts/{n}/url` 的 `sha256` 为可选绑定；提供时在预签名 URL 上绑定
   `x-amz-checksum-sha256`，ack 不一致返回 409。
4. RawAsset 内容不可变、按 `sha256+size_bytes` 内容寻址；重复上传通过
   `raw_asset_links` 关联。
5. Episode 创建要求 `time_base`、非空标定快照、Pipeline/规则版本；`READY` 起冻结数据字段。
6. Episode 修订创建新 `episode_id`、`episode_version+1`、`supersedes_id`，不原地覆盖。
7. 血缘只追加；查询方向 `forward`/`reverse`，深度 1–5。
8. 所有阶段 2 表带 `project_id`；写路径按端点要求 `If-Match` 与 `Idempotency-Key`；
   状态迁移由领域动作 + DB 触发器双重兜底。
9. 无项目路径前缀的血缘/下载端点使用 `project_id` 查询参数，但服务端仍强制项目过滤。
10. Episode 与 IngestionJob 的创建/动作必须携带 `Idempotency-Key`；Collection 与
    UploadSession 写路径为可选。

## 版本与变更流程

- 当前版本 `ddp.stage2/1.0.0`；HTTP 主版本 `/api/v1`。
- 非破坏性变更：更新契约与测试，执行

  `--freeze --force` 生成新基线，保留旧基线历史。
