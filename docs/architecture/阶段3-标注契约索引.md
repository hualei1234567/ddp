## 2. 关键决策

1. **Schema 版本化与快照**：Schema 发布后不可变；任务批准时冻结 `schema_id + schema_version + schema_sha256`；提交必须引用同一快照。
2. **样本集快照**：样本选择可预览、去重、分层；任务引用后样本清单不可静默变化；变更创建新样本集。
3. **任务/批次/分配分离**：任务表达生产目标，批次表达分层执行，分配表达人员工作量；三者状态独立但受兼容约束。
4. **提交版本化**：提交后不可原地编辑；修订创建新 `submission_version`，旧版本保留；服务端计算 `records_digest`。
5. **复核与仲裁分离**：复核人 ≠ 标注人；仲裁人 ≠ 标注人/首轮复核人；仲裁有法定人数与最终结论。
6. **黄金集隐藏**：`blind=true`，期望答案不进入标注员响应、日志、导出与前端缓存；准确率 ≠ IAA。
7. **IAA 严格要求重叠**：只在同任务、同 Schema 版本、至少两名标注员独立标注的重叠样本上计算；不足返回 `INSUFFICIENT_DATA`。
8. **抽检策略版本化**：随机/分层/风险抽样，策略与理由可追溯；抽检人不得是标注人。
9. **项目隔离与职责分离**：服务端强制 `project_id`；复合外键/触发器兜底；前端隐藏不构成权限。
10. **审计与 outbox 同事务**：状态迁移、提交、复核、仲裁、黄金集访问等写审计/outbox；消费按 `event_id` 幂等；DB 触发器要求 GUC。
11. **血缘只追加**：阶段 3 扩展节点/关系，跨项目禁止、成环禁止（`SUPERSEDES` 线性）；失效追加边。
12. **错误码稳定**：客户端按 `code` 分支；未知 code 不得默认成功；破坏性变更走新 ADR/版本。

## 3. 与阶段 2 的衔接

- 输入：阶段 2 Episode `status in (ACCEPTED, COMPLETED)`、`quality_status in (PASS, WARN)`、`manifest_sha256`、`calibration_snapshot`、血缘边。
- `Episode.annotation_status` 是派生投影：阶段 3 任务/提交/复核变化时由服务端更新；不得由前端直接写。建议扩展映射：`NOT_STARTED → IN_PROGRESS → SUBMITTED → APPROVED/REJECTED`；仲裁中是否新增 `IN_ARBITRATION` 需 Schema 兼容评审，未冻结前保持阶段 2 枚举。
- 阶段 2 血缘 `node_type`/`relation` 是封闭枚举；阶段 3 通过新版本 `annotation-lineage.v1.schema.json` 扩展，不修改阶段 2 文件。实施时需评估 `lineage_node_refs` 约束迁移与契约版本升级。
- 阶段 2 错误码可复用；阶段 3 新增错误码不得改变阶段 2 语义。`resource_immutable`、`version_conflict`、`state_transition_invalid`、`forbidden`、`resource_not_found`、`project_scope_denied` 沿用。
- 阶段 2 `RawAsset/Episode` 只读引用；阶段 3 不修改原始资产与 Episode 数据字段，只更新 `annotation_status` 投影并追加血缘/审计。
