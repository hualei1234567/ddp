### 10.2 Job/领域内部错误码

以下错误码写入 `IngestionJob.error_code`、`RawAsset.quarantine_codes` 或审计载荷，不一定直接作为 HTTP 响应：

| code | 含义 | 可重试 |

| `duplicate_content` | 内容指纹竞争失败/重复 | 否 |

### 10.3 错误码使用规则

- 客户端必须按 `code` 分支，不得只按 HTTP 状态码；未知 `code` 不得默认成功。
- `error.details` 可选，包含字段级错误、`missing_part_numbers`、`expected/actual` 等；不得包含对象存储凭据、跨项目 ID、Token。
- 重试必须区分可重试与不可重试；不可重试错误不得进入无限重试。
- 所有 4xx/5xx 返回 `request_id`；审计记录同一 `request_id`。
- 错误码新增/语义变更必须走契约版本；删除/改名/改语义为破坏性变更。

职责分离：

- 隔离放行：提案人 ≠ 批准人；DE 提案，QI 或 PO 批准；PA break-glass 需额外审批与审计。
- 墓碑：PO + QI 双人；不得同一人完成两次批准。
- Episode 失效：PO + QI；DE 只能提案。
- 采集员不得审批自己的任务/Episode；QI 不得验收自己执行的采集（若同时承担采集角色）。
- 前端隐藏按钮不构成权限控制；服务端以本矩阵 + 项目角色 + 资源授权判定。

必须审计：所有状态迁移、上传完成/中止、下载/预览/日志签名、隔离放行/拒绝、墓碑、Episode 验收/失效、跨项目拒绝、权限拒绝、契约/迁移变更。

## 13. 迁移策略

### 13.1 迁移拆分（建议）

当前已有 `0001`–`0005`。阶段 2 建议：

| revision | 内容 | 依赖 |
|---|---|---|
| `0006_stage2_audit_outbox_idempotency` | 审计、outbox、幂等记录（若阶段 1 尚未落地） | `0005` |
| `0007_stage2_collection_task_batch` | 采集任务、批次、任务设备/传感器分配 | `0006` |
| `0008_stage2_upload_raw_asset` | 上传会话、分片、RawAsset、使用关系 | `0007` |
| `0009_stage2_ingestion_episode_lineage` | IngestionJob、Episode、Episode-RawAsset、血缘节点投影/边 | `0008` |
| `0010_stage2_guards_indexes` | 状态触发器、不可变触发器、部分唯一索引、审计触发器 | `0009` |

- 若实际分支已有审计/outbox（例如阶段 1 后续迁移），`0006` 必须改为幂等检测/合并，不得重复建表。
- 只新增表/列/索引/触发器；阶段 2 无历史采集数据，不做回填。若未来存在历史数据，必须另立回填任务，按 `project_id` 分批、可重入、有进度与失败记录。
- 采用 expand/contract：新表先建，应用双读/切换，观察后再删除旧路径；不删除阶段 1 字段。
- 大表索引使用 `CREATE INDEX CONCURRENTLY`；新表为空时可普通创建。不得长时间锁表。
- 破坏性变更（删列/改类型/改语义/必填化）必须新 ADR + 用户批准；本阶段不包含。

### 13.4 数据库兜底触发器

| 触发器 | 作用 | 失败行为 |
|---|---|---|
| `trg_collection_task_transition` | 校验任务迁移白名单；终态不可回退；要求 `ddp.actor_id`/`ddp.request_id` | 抛错，事务回滚 |
| `trg_collection_batch_transition` | 校验批次迁移；批次不得领先任务 | 抛错 |
| `trg_upload_session_transition` | 校验会话迁移；`COMPLETED/EXPIRED/ABORTED/FAILED` 不可回退 | 抛错 |
| `trg_raw_asset_transition` | 校验资产迁移；`TOMBSTONED` 不可回退；`VALID→VALIDATING` 禁止 | 抛错 |
| `trg_ingestion_job_transition` | 校验 Job 迁移；重试必须从 FAILED 且 attempt < max | 抛错 |
| `trg_episode_transition` | 校验 Episode 迁移；`READY` 后冻结数据字段；终态不可回退 | 抛错 |
| `trg_raw_asset_immutable` | 拒绝修改 `object_key/sha256/size_bytes/content_type/format/asset_id/project_id` | 抛错 |
| `trg_episode_immutable` | `READY` 后拒绝修改数据字段；`ACCEPTED` 后拒绝修改质量结论 | 抛错 |
| `trg_forbid_delete` | 拒绝对 `raw_assets`、`episodes`、`data_lineage_edges`、`upload_parts` 的 DELETE | 抛错 |
| `trg_lineage_append_only` | 拒绝 UPDATE/DELETE 血缘边 | 抛错 |
| `trg_lineage_project_consistency` | 校验节点投影同项目；防止跨项目边 | 抛错 |
| `trg_lineage_no_cycle` | 拒绝成环（`SUPERSEDES` 线性） | 抛错 |
| `trg_audit_state_change` | 状态变更写追加式审计/outbox；缺少 actor/request_id 拒绝 | 抛错 |

应用层事务必须设置：

```sql
SET LOCAL ddp.actor_id = '<uuid>';
SET LOCAL ddp.request_id = '<string>';
SET LOCAL ddp.project_id = '<uuid>';
```

触发器以这些 GUC 作为审计来源；缺失即拒绝，防止后台脚本直写绕过审计。

### 13.5 迁移验证 SQL

```sql
-- 状态枚举完整性
select status, count(*) from collection_tasks group by status;
select status, count(*) from upload_sessions group by status;
select status, count(*) from raw_assets group by status;
select status, count(*) from episodes group by status;

-- 跨项目引用检查（应为 0）
select count(*) from raw_asset_links l
join raw_assets a on a.project_id = l.project_id and a.id = l.asset_id
where l.collection_task_id is not null and not exists (
  select 1 from collection_tasks t
  where t.project_id = l.project_id and t.id = l.collection_task_id
);

-- 内容重复可用资产（应为 0）
select project_id, sha256, size_bytes, count(*)
from raw_assets
where status in ('VALID','QUARANTINED','ARCHIVED')
group by project_id, sha256, size_bytes
having count(*) > 1;

-- Episode 时间一致性（应为 0）
select count(*) from episodes where duration_ns <> end_time_ns - start_time_ns;

-- 血缘跨项目（应为 0）
select count(*) from data_lineage_edges e
where not exists (
  select 1 from lineage_node_refs n
  where n.project_id = e.project_id and n.node_type = e.from_node_type and n.node_id = e.from_node_id
) or not exists (
  select 1 from lineage_node_refs n
  where n.project_id = e.project_id and n.node_type = e.to_node_type and n.node_id = e.to_node_id
);
```

### 13.6 回滚

- 回滚点：`0005` 与阶段 1 契约版本；阶段 2 新表为空时可直接 downgrade 删除。
- 已产生数据后回滚：必须先导出元数据与对象清单、备份数据库、确认对象存储 Key 保留；禁止直接 drop 有数据表。
- 触发器必须按依赖逆序删除；先删索引/触发器，再删表；不得删除阶段 1 表。
- 对象存储对象不因数据库回滚自动删除；保留策略与清理单独审批。
- 迁移执行、生产回滚需用户单独批准；本文件不授权执行。

### 13.7 迁移测试要求

- Alembic `upgrade head` / `downgrade -1` / 再 `upgrade` 在 PostgreSQL 上通过；SQLite 仅单元测试，不作为验收证据。
- 负向测试：直接 SQL 非法状态更新被触发器拒绝；跨项目外键插入失败；修改 RawAsset 内容字段失败；修改 READY Episode 数据字段失败；删除血缘边失败；血缘成环失败。
- 并发测试：两个 `complete` 并发仅一个成功；两个隔离放行审批不能同一人；唯一内容索引竞争。
- 审计测试：缺少 `ddp.actor_id`/`ddp.request_id` 的状态更新被拒绝；outbox 写入失败回滚业务。
- 项目隔离：跨项目 task/batch/asset/episode/job/lineage 查询与写入全部失败；列表不泄漏。
- 迁移前检查现有 `0001`–`0005` 与阶段 1 审计/outbox 实际状态；若已有同名表，`0006` 必须幂等合并。

## 14. 未决项与未执行

1. **弱网/离线**：本契约只保证分片断点续传与幂等，不定义本地离线队列、IndexedDB/文件系统暂存与冲突合并；PRD AC-COL-12 仍为 `BLOCKED`。
2. **恶意扫描产品**：扫描器、规则库、超时与 SLA 未选型；当前策略是扫描不可用即隔离（fail-closed），不承诺扫描时延。
3. **CSV/JSON mapping schema**：阶段 2 是否接受文本表格未冻结；未提供 mapping 时进入隔离区。
4. **保留策略**：`retention_policy_id` 的具体取值、生命周期与法务要求未冻结；墓碑/物理删除需另行审批。
5. **容量与性能**：未测量大文件上传、Hash、解析、分片数量与并发；本契约不承诺吞吐、时延或存储成本。
6. **同步 Hash 校验**：当前设计为 `complete` 返回 202、异步校验；是否为小文件提供同步校验未决。
7. **Manifest 内联上限**：建议 1 MiB；需前端/数据团队确认。
8. **跨任务内容去重**：当前按内容寻址 + 使用关系；若业务要求“不同任务字节完全隔离”，需新 ADR。
9. **契约位置**：本阶段草案未写入 `packages/contracts/`；待用户批准并实施后，由契约 Owner 升级版本并更新实现快照。
10. **测试与迁移未执行**：本会话无 Bash 工具，`pytest`、`ruff`、Alembic、Redocly、oasdiff、JSON Schema 校验、Markdown lint 全部 `NOT RUN`；不得声称通过。
11. **迁移编号**：`0006`–`0010` 为建议；实际以当前分支最新 revision 为准，避免与并行迁移冲突。
12. **错误码 HTTP 归属**：`asset_quarantined` 使用 403、`asset_tombstoned` 使用 410；如客户端需要统一资源不可用语义，冻结前可调整，但必须走契约变更。
