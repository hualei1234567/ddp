## 5. 上传协议契约

### 5.1 生命周期

```text
1. POST /upload-sessions（Idempotency-Key）
   → 校验项目/任务/批次、内容类型白名单、声明大小、文件名
   → 返回 session（part_size_bytes、max_size_bytes、expires_at、version）

2. POST /upload-sessions/{id}/parts/{part_number}/url
   → 返回短期预签名 PUT URL + 必填请求头（含 x-amz-checksum-sha256）

3. 客户端直接 PUT 分片到对象存储
   → 对象存储校验分片校验头，返回 ETag

4. POST /upload-sessions/{id}/parts/{part_number}/ack
   → 客户端回传 ETag、分片大小、分片 SHA256
   → 服务端落库；同分片同内容幂等；不同内容 409 upload_part_conflict

5. 重复 2–4，可乱序、可重试、可断点续传

6. GET /upload-sessions/{id}
   → 服务端返回本地确认分片 + 与对象存储 ListParts 核对后的缺失分片/已传字节

7. POST /upload-sessions/{id}/complete（If-Match、Idempotency-Key）
   → 校验状态、ListParts、确认记录、连续分片、总大小、内容签名、声明 Hash 一致性
   → 完成 multipart；登记/命中 RawAsset；创建 VALIDATE Job；返回 202

8. VALIDATE Job（Worker）
   → 流式 SHA256、格式探测、可解析性、恶意扫描
   → RawAsset → VALID / QUARANTINED / REJECTED；发 outbox 事件
```

### 5.2 创建上传会话

请求字段（`UploadSessionCreate`）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `collection_task_id` | 否 | 必须同项目；有任务时校验成员/角色 |
| `batch_id` | 否 | 必须属于 `collection_task_id` |
| `original_filename` | 是 | 仅展示；1–255 字符；禁止路径分隔符、控制字符、NUL、`..` 路径段 |
| `declared_content_type` | 是 | 必须在项目白名单；不信任客户端，实际以签名探测为准 |
| `declared_size_bytes` | 是 | >0；不得超过本次会话 `max_size_bytes` |
| `expected_sha256` | 否 | `sha256:<64hex>`；用于完成时一致性与去重提示，不是最终权威 |
| `format_hint` | 否 | 帮助选择解析器；不能替代签名探测 |
| `part_size_bytes` | 否 | 客户端建议值；服务端可覆盖并返回最终值 |
| `metadata` | 否 | 仅允许白名单键；不得包含密钥、Token、客户敏感数据 |

响应（`UploadSession`）除 §3.4 字段外，必须返回：

- `part_size_bytes`、`max_size_bytes`、`allowed_content_types`、`expires_at`；
- `uploaded_bytes`、`uploaded_part_count`、`missing_part_numbers`（服务端核对后计算，不作为最终完成依据）；
- `object_key` 的**项目内可见前缀**可以返回，但不得返回对象存储凭据；完整 Key 可返回用于排障，下载必须走签名 URL。

幂等规则：

- 同 `(project_id, user_id, Idempotency-Key)` 且请求体规范化 Hash 相同 → 返回首次 session，`Idempotent-Replayed: true`；
- 同键不同请求体 → `409 idempotency_key_reused`；
- 幂等记录 TTL 至少 24h；过期后同键视为新请求，但不得对已存在会话产生副作用。

### 5.3 分片 URL 与分片确认

分片 URL 请求：

- `part_number`：1–10000；同一会话内分片号必须从 1 开始连续，不得跳号完成。
- 响应 `UploadPartUrlResponse`：

```json
{
  "part_number": 1,
  "method": "PUT",
  "url": "https://object-store/...",
  "headers": {
    "x-amz-checksum-sha256": "BASE64_SHA256",
    "Content-Length": "16777216"
  },
  "expires_at": "2026-11-08T12:15:00Z"
}
```

- URL 必须短期有效（建议 ≤15 分钟，具体由配置决定；契约只要求返回 `expires_at`）；不得写入日志、审计正文或前端持久化。
- URL 签名必须绑定：对象 Key、`part_number`、`Content-Length`、`x-amz-checksum-sha256`；客户端篡改任一值应被对象存储拒绝。
- 客户端必须将 `x-amz-checksum-sha256` 设为分片字节 SHA256 的 **base64** 值；API 的 `sha256` 字段使用 **`sha256:<64hex>`**，服务端负责转换与比对。

分片确认请求（`UploadPartAckRequest`）：

```json
{
  "etag": "\"9b2cf535f27731c974343645a3985328\"",
  "size_bytes": 16777216,
  "sha256": "sha256:aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
}
```

- 服务端按 `(project_id, upload_session_id, part_number)` 记录；同 ETag/大小/校验和重复确认幂等返回。
- 同分片号但 ETag、大小或 SHA256 不同 → `409 upload_part_conflict`；不得静默覆盖。
- 确认记录不是最终权威；`complete` 必须与对象存储 `ListParts` 交叉核对。

### 5.4 断点续传

客户端恢复流程：

1. `GET /upload-sessions/{id}`；
2. 读取 `uploaded_parts[]`（part_number、size_bytes、etag、sha256）与 `missing_part_numbers`；
3. 对缺失/失败分片重新请求 URL 并上传；
4. 不重传已确认且 ETag/校验和一致的分片；
5. 会话过期返回 `410 upload_session_expired`，必须新建会话；已传分片按对象存储生命周期清理，不承诺保留。

服务端核对规则：

- 本地 `upload_parts` 记录是断点提示；
- `ListParts` 是完成时的权威来源；
- 二者不一致时以 `ListParts` 为准，并将差异写入审计；缺失分片返回 `409 upload_incomplete`，`error.details` 给出 `missing_part_numbers`。

### 5.5 完成上传

请求（`CompleteUploadRequest`）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `expected_sha256` | 是 | 整文件 SHA256；必须与会话 `expected_sha256`（若已设置）一致 |
| `expected_size_bytes` | 是 | 必须等于会话声明大小 |
| `parts` | 是 | 客户端确认的完整分片清单，按 `part_number` 升序；每项含 `part_number`、`etag`、`size_bytes`、`sha256` |
| `metadata` | 否 | 完成阶段补充元数据；不得覆盖服务端字段 |

服务端校验顺序（失败关闭）：

1. 项目/成员/角色；会话属于当前项目；
2. `If-Match` 版本匹配；会话状态为 `CREATED/UPLOADING/COMPLETING`；
3. 未过期；否则 `410 upload_session_expired`；
4. 请求分片清单与本地确认记录一致；不一致 `409 upload_part_conflict`；
5. `ListParts` 与请求清单一致：分片数量、编号连续、大小、ETag；缺失 `409 upload_incomplete`；
6. 总大小等于 `expected_size_bytes` 且等于会话声明；不等 `422 size_mismatch`；
7. 首段/尾段范围读取做内容签名探测；与声明类型/格式不符 `422 file_signature_mismatch`，会话 `FAILED`；
8. `expected_sha256` 与会话声明一致；不一致 `422 hash_mismatch`（客户端自相矛盾，立即拒绝）；
9. 完成 multipart；在对象存储完成成功后，开启数据库事务：
   - 若存在同项目、同 `sha256+size_bytes` 的 `VALID/QUARANTINED/ARCHIVED` 资产：不创建新资产，`deduplicated=true`，记录 `deduplicated_asset_id`；**使用关系在异步验证通过后才建立**；
   - 否则创建 `RawAsset(status=VALIDATING)`，写入对象 Key、大小、Hash、格式提示、来源；
   - 创建 `raw_asset_links`（验证通过后转为有效关联；可先写 `PENDING_VERIFICATION` 状态）；
   - 写审计与 outbox；创建 `VALIDATE` IngestionJob；
10. 返回 `202 Accepted`，包含 session、asset（或既有资产）、`validation_job_id`、`deduplicated`、`replayed`。

完成响应示例：

```json
{
  "upload_session": { "upload_session_id": "...", "status": "COMPLETED" },
  "raw_asset": { "asset_id": "...", "status": "VALIDATING" },
  "deduplicated": false,
  "validation_job_id": "...",
  "replayed": false
}
```

幂等与并发：

- 同 `Idempotency-Key` 重复 `complete` 返回首次响应；若首次仍在处理中，返回 `202` 与相同 `validation_job_id`；
- 两个并发 `complete` 用 `If-Match` 与数据库条件更新 `from_status IN (...)` 保护；只有一个成功，另一个返回 `409 version_conflict` 或首次结果；
- 唯一索引兜底：`raw_assets (project_id, sha256, size_bytes)` 仅对可用状态生效；竞争失败方读取既有资产并标记 `duplicate_of_asset_id`，不得产生第二个可用资产。

### 5.6 整文件 Hash 校验

- 算法：对对象存储中的**精确字节流**计算 SHA-256，不做换行/编码/格式规范化；输出小写十六进制，API 表示为 `sha256:<64hex>`。
- 计算位置：`VALIDATE` Worker，流式读取，分块大小由配置决定；不得在 HTTP 请求线程读取大文件。
- 比对：实际 Hash 必须等于客户端 `expected_sha256`；不等 → RawAsset `REJECTED`，错误码 `hash_mismatch`；已有资产不受影响。
- ETag 不是内容 Hash；多分片 ETag 是对象存储内部摘要，禁止作为 `sha256` 入库或对外返回。
- 大文件 Hash 失败/超时：Job `FAILED`，错误码 `job_timeout` 或 `hash_compute_failed`；可重试；不得标记 VALID。

### 5.7 分片与对象大小限制

以下为协议约束，不是性能或容量承诺；实际 `max_size_bytes` 由项目策略返回：

| 项 | 约束 |
|---|---|
| `part_number` | 1–10000 |
| 单分片大小 | 最小 5 MiB（最后一片除外）；最大 5 GiB |
| 分片大小 | 默认 16 MiB，服务端可覆盖；必须满足对象存储约束 |
| 文件大小 | `>0` 且 `<= max_size_bytes`；超限 `413 file_too_large` |
| 会话有效期 | 默认 24h；返回 `expires_at`；过期 `410` |
| 完成幂等 | `Idempotency-Key` + `If-Match` + 唯一索引 |
| 清理 | 过期/中止会话的分片按生命周期清理；不得承诺长期保留 |

### 5.8 失败、重试与取消

- 可重试：网络中断、分片 5xx、`upload_incomplete`、`size_mismatch`（客户端修正后）、对象存储临时不可用。
- 不可重试：`file_signature_mismatch`、`malware_detected`、`file_type_unsupported`、跨项目/权限拒绝、会话过期。
- `abort` 幂等：已中止/已完成会话重复 abort 返回当前状态，不重复删除对象；终止 multipart 失败写审计并允许后台清理重试。
- 所有失败必须有 `failure_code`、`failure_summary`、`request_id`、审计记录；不得“失败即消失”。

## 6. 校验、格式与隔离区

### 6.1 类型白名单与内容签名

声明类型白名单（示例，最终按项目配置）：

| 格式 | 允许的声明 Content-Type | 允许扩展名（仅展示） | 签名探测 |
|---|---|---|---|
| MCAP | `application/octet-stream`、`application/x-mcap` | `.mcap` | 8 字节 `89 4D 43 41 50 30 0D 0A` |
| ROSBAG2 | `application/octet-stream`、`application/x-rosbag2` | `.db3`、`.mcap` | SQLite 头 `SQLite format 3\0` 或 MCAP 头 |
| HDF5 | `application/x-hdf5`、`application/octet-stream` | `.h5`、`.hdf5` | `89 48 44 46 0D 0A 1A 0A` |
| MP4/MOV | `video/mp4`、`video/quicktime` | `.mp4`、`.mov` | 偏移 4 起 `ftyp` |
| PARQUET | `application/vnd.apache.parquet`、`application/octet-stream` | `.parquet` | 首尾 `PAR1` |
| CSV | `text/csv` | `.csv` | 必须提供 mapping schema；文本签名不作为充分条件 |
| JSON | `application/json` | `.json` | 首个非空白字符 `{` 或 `[`；需 schema |
| ZIP | `application/zip` | `.zip` | `50 4B 03 04`；解压路径穿越检查 |

规则：

1. 扩展名只用于提示，不得作为放行依据；实际以内容签名与解析结果为准。
2. 声明类型与内容签名不符 → `422 file_signature_mismatch`，会话 `FAILED`，不得登记为可用资产。
3. 声明类型不在白名单 → 创建会话时 `415 file_type_unsupported`。
4. 已知但暂不支持的格式 → `QUARANTINED`，错误码 `unsupported_format`；不得伪造解析成功。
5. 文本类（CSV/JSON）必须显式提供 mapping/schema 版本；缺失进入隔离区，不自动猜列/单位。
6. ZIP 必须防路径穿越、压缩炸弹与嵌套深度；超限进入隔离区或拒绝。

### 6.2 文件名与路径安全

- `original_filename` 仅展示；服务端清洗：去除路径分隔符、控制字符、NUL、前后空白；拒绝 `..` 路径段；最大 255 字符。
- 对象 Key **绝不包含** `original_filename`、用户目录、查询参数或客户端路径。
- 对象 Key 由服务端按 §7 生成；生成后不可变；任何客户端传入的 Key 一律拒绝。
- 下载只通过服务端签发短期 URL；签名前再次校验 `project_id` 与资产状态。

### 6.3 隔离区规则

进入 `QUARANTINED` 的稳定原因码：

| 代码 | 含义 | 后续处理 |
|---|---|---|
| `malware_suspected` | 恶意扫描可疑/命中 | 隔离；安全复核；禁止下载 |
| `malware_scanner_unavailable` | 扫描服务不可用，无法判定 | 失败关闭；隔离；恢复后重验 |
| `signature_ambiguous` | 内容签名无法唯一判定格式 | 隔离；人工/解析器复核 |
| `unsupported_format` | 已知但阶段 2 不支持 | 隔离；后续阶段接入 |
| `metadata_conflict` | 原始元数据与声明/设备快照冲突 | 隔离；DE 复核 |
| `parse_failed` | 格式可识别但无法解析 | 隔离；记录解析器与错误 |

隔离区不变量：

- `QUARANTINED` 资产不得被 `IngestionJob`、Episode 使用；下载默认拒绝；
- 放行必须 `release-quarantine`：DE 提案 + QI/PO 批准，提交 `reason`、`scan_report_sha256`、`evidence_refs`；不允许同一人提案并批准；
- 放行后进入 `VALIDATING`，重新执行 Hash/签名/扫描；失败回 `QUARANTINED/REJECTED`，不得直接 `VALID`；
- 放行、拒绝、重新隔离均写审计与 outbox；
- `QUARANTINED` 不是终态；`TOMBSTONED` 是终态。

### 6.4 墓碑与保留

- `tombstone` 必须 PO + QI 双人审批，记录法务/保留依据；普通用户、采集员、数据工程师不得单独执行。
- 墓碑只改 `RawAsset.status=TOMBSTONED`、`tombstoned_at`、`status_reason`；保留元数据、Hash、Key、血缘；对象按保留策略处理，不立即物理删除。
- 墓碑后：下载返回 `410 asset_tombstoned`；禁止新 Job/Episode；既有 Episode 按 §4.7 失效。
- 物理删除对象必须走单独的保留策略任务、dry-run、逐条确认、备份与审计；本契约不授权自动删除。

## 7. 对象存储 Key 规范

### 7.1 存储桶/前缀

逻辑桶名（部署可配置，契约只依赖前缀语义）：

| 逻辑桶 | 用途 | 访问策略 |
|---|---|---|
| `ddp-raw` | 原始资产，不可变 | 私有；仅服务端/签名 URL |
| `ddp-quarantine` | 扫描报告、隔离证据 | 私有；仅 DE/QI/审计 |
| `ddp-canonical` | Canonical Manifest/流数据 | 私有；按项目 |
| `ddp-logs` | Job 日志 | 私有；短期签名 |
| `ddp-temp` | 上传临时/非 multipart 回退 | 私有；TTL 清理 |

### 7.2 Key 模板（服务端生成）

```text
raw/{project_id}/{yyyy}/{mm}/{dd}/{asset_id}/content.{ext}
quarantine/{project_id}/{asset_id}/scan-report.json
quarantine/{project_id}/{asset_id}/evidence/{evidence_id}.{ext}
tmp/uploads/{project_id}/{upload_session_id}/scratch
canonical/{project_id}/{episode_id}/{episode_version}/manifest.json
canonical/{project_id}/{episode_id}/{episode_version}/streams/{stream_id}/part-{chunk_index:05d}.parquet
canonical/{project_id}/{episode_id}/{episode_version}/preview/{preview_id}.{ext}
logs/{project_id}/ingestion/{job_id}/{attempt}.log
```

约束：

- `project_id`、`asset_id`、`episode_id`、`job_id` 使用小写 UUID；日期按 UTC；`ext` 由服务端根据校验后的格式映射，不取自用户文件名。
- `stream_id` 只允许 `[a-z0-9][a-z0-9_-]{0,63}`；`chunk_index` 为 5 位零填充十进制；`evidence_id` 为 UUID。
- 完整 Key 长度 ≤1024 字节；固定段小写 ASCII；禁止空格、反斜杠、连续斜杠、`.`/`..` 路径段。
- 对象 Key 不含用户可控路径、原始文件名、Token、邮箱、客户名称。
- 任何跨项目前缀（Key 的 `project_id` 与资源/令牌项目不一致）一律拒绝并审计。
- 对象元数据写入 `x-amz-meta-project-id`、`x-amz-meta-asset-id`、`x-amz-meta-sha256`，仅用于排障，不作为授权依据。
- 服务端加密默认开启（SSE-S3 或 KMS）；桶禁止公共 ACL；生命周期按 `retention_policy_id`。

### 7.3 机器可读 Key Schema

`object-key.v1.schema.json` 定义每类前缀的正则与示例；应用层和测试必须使用同一 Schema 校验 Key。示例正则（完整以 JSON 为准）：

```text
^raw/[0-9a-f-]{36}/[0-9]{4}/[0-9]{2}/[0-9]{2}/[0-9a-f-]{36}/content\.[a-z0-9]{1,16}$
^canonical/[0-9a-f-]{36}/[0-9a-f-]{36}/[1-9][0-9]*/manifest\.json$
^logs/[0-9a-f-]{36}/ingestion/[0-9a-f-]{36}/[1-9][0-9]*\.log$
```

### 7.4 下载与预览

- 所有下载/预览 URL 必须短期签名（建议 ≤15 分钟），绑定项目、资产、操作者与用途；返回前校验状态与权限。
- 下载、预览、隔离区证据访问、日志访问均写审计：操作者、项目、资源、动作、用途、结果、请求 ID、时间。
- 禁止把对象存储长期密钥、桶内网地址或未授权 Key 返回前端。
