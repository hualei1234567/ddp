## 0. 结论摘要

1. `CalibrationProfile.target_id` 允许为空：空表示“该 `target_type` 的类型级模板”，非空表示“目标级配置”；`SYSTEM` 的 `target_id` 必须等于 `project_id`，不允许为空。
2. 标定记录的 `calibration_version`（业务版本）与 `lock_version`（乐观锁）彻底分离；`profile_version` 是标定配置版本，三者不得复用同一列或同一 API 字段。
3. `profile_version`、`schema_version` 在创建标定草案时从 `CalibrationProfile` 快照写入并不可变；`checksum` 由服务端按固定规范化算法计算；`supersedes_id` 只允许写一次，且必须同项目、同目标、同类型。
4. 证据、`validated_by`、`uncertainty`、`valid_to` 按状态矩阵冻结：DRAFT 可暂缺证据/不确定度；SUBMITTED 起必须齐全；VALIDATED 起必须有校验人与校验时间。
5. Sensor 拥有 `frame_id`、`frame_convention`、`sync_mode`、`sync_group`；`time_base`、`sync_status` 归 Episode/Stream 运行态，不写入 Sensor 主数据。
6. `parameters` 按 `calibration_type + schema_version` 分类型 JSON Schema 校验；未知键、NaN/Infinity、错误单位、缺帧一律失败关闭。
7. `target_id` 完整性采用 **DB 兜底方案**：新增 `calibration_target_refs` 多态目标投影表 + 复合外键；应用层只做前置校验与友好错误，不作为唯一防线。
8. 所有状态迁移必须有前置条件、原因/故障码、角色、审计事件与错误码映射；审计写入失败则迁移失败。
9. `add` 只允许初始状态：Robot/Device/Sensor 仅 `PROVISIONED`，CalibrationRecord 仅 `DRAFT`；`save()` 禁止写状态，状态只能经具名动作迁移。
10. ADR-0009 已于 2026-11-08 经用户长期授权批准；本文件即日生效。当前实现尚未达到本冻结基线，逐项差距与排期见 `docs/architecture/阶段1-设备域冻结字段实现差距与排期.md`。

## 1. 通用冻结规则

### 1.1 标识与序列化

| 项 | 冻结规则 |
|---|---|
| 主键 | 服务端生成 UUIDv7；API/JSON 为 36 字符、小写、带连字符；DB 使用 `uuid` 类型 |
| 业务编码 | `code` 项目内唯一；约束 `(project_id, code)`；不作为外键 |
| 项目隔离 | 所有设备域表带 `project_id`；所有读写经服务端 `ProjectScope`；客户端 `project_id` 不作权威来源 |
| 时间 | DB 使用 `timestamptz`；API 使用 RFC3339 UTC（`Z` 后缀）；进入领域层前统一 `astimezone(UTC)`，禁止 naive datetime |
| 枚举 | 大写下划线；DB 用 `varchar(32) + CHECK`；Domain 枚举为权威；未知值拒绝，不默认成功 |
| JSON | 禁止 `NaN`/`Infinity`；`parameters` 序列化上限 64 KiB、最大深度 8、最大键数 256；`uncertainty` 上限 16 KiB |
| 数值 | `channels` 是整数（≥1），不是字符串数组；`uncertainty` 是对象，不是数字 |
| 传感器类型 | 统一 `RGB_D`，禁止 `RGB-D` |

### 1.2 并发与不可变

- Robot/Device/Sensor 的 `version` **只表示乐观锁**，不表示业务版本；API 字段名保留 `version`。
- CalibrationRecord 使用 `lock_version` 表示乐观锁；`calibration_version` 表示业务版本；不得混用。
- CalibrationProfile 使用 `profile_version` 表示配置版本；Profile 行创建后不可变，不设置状态机，也不使用乐观锁改写。
- 所有动作接口必须带 `If-Match: "<lock_version>"`（Robot/Device/Sensor 为 `version`）；缺失返回 `428 precondition_required`，不匹配返回 `409 version_conflict`。
- `PATCH` 不得修改 `project_id`、各 `*_id`、`status`、`checksum`、`lock_version`、`created_by/created_at`、已冻结的溯源字段。

### 2.1 Robot / Device

| 字段 | 类型/必填 | 冻结说明 |
|---|---|---|
| `robot_id` / `device_id` | UUID / 是 | UUIDv7；服务端生成 |
| `project_id` | UUID / 是 | 服务端强制 |
| `code` | string(64) / 是 | 项目内唯一 |
| `name` | string(200) / 是 | 非空 |
| `robot_type` / `device_type` | enum / 是 | 按 Domain 枚举；厂商差异放 `capability_profile` |

| `calibration_profile_id` | UUID / 否 | 必须指向同项目 Profile；Profile 的 `target_type` 必须匹配实体类型，`target_id` 为空或等于实体 ID |
| `capability_profile` | object / 是 | 允许扩展，但不得替代 `device_type` |

| `status_reason` | string(500) / 条件 | `SUSPENDED`、`RETIRED` 必填；`IN_MAINTENANCE` 进入时必填 |

| `fault_detail` | string(2000) / 否 | `fault_code=OTHER` 时必填 |
| `fault_occurred_at` | timestamptz / 条件 | `FAULT` 必填 |
| `status_changed_at`、`status_changed_by` | timestamptz / UUID / 是 | 最近一次状态变更投影；完整历史在审计 |
| `location_id` | UUID / 否 | 必须同项目；阶段 1 可先不建外键，但契约要求同项目 |
| `owner_user_id` | UUID / 否 | 必须是本项目成员 |
| `version` | int ≥1 / 是 | 乐观锁 |
| `created_at/by`、`updated_at/by` | 审计 / 是 | 由服务端写入 |

> `time_base`、`sync_status` **不是 Sensor 主数据字段**。归属见 §7。

### 2.3 CalibrationProfile

| 字段 | 类型/必填 | 冻结说明 |
|---|---|---|
| `profile_id` | UUID / 是 | UUIDv7；一行代表一个**不可变配置版本** |
| `project_id` | UUID / 是 | 服务端强制 |
| `name` | string(200) / 是 | 版本内不可变 |
| `scope` | enum / 是 | `ROBOT`、`DEVICE`、`SENSOR`、`SYSTEM` |
| `target_type` | enum / 是 | 必须等于 `scope`；禁止再用 scope 常量误填 |
| `target_id` | UUID / 条件 | 空 = 该 `target_type` 的类型级模板；非空 = 目标级配置；`SYSTEM` 必须等于 `project_id`；非空时必须存在于 `calibration_target_refs` |
| `profile_version` | int ≥1 / 是 | 业务版本；同一目标/作用域内唯一；首版为 1 |
| `schema_version` | string(64) / 是 | 例如 `ddp.device.calibration-parameters/1.0.0`；不可变 |
| `required_types` | array<enum> / 是 | 不得重复；只能包含 `CalibrationType` |
| `selection_rule` | object / 是 | 版本化 JSON；不得为空时静默取最新；冲突时失败关闭 |
| `supersedes_id` | UUID / 否 | 指向同项目、同 `scope/target_type/target_id` 的上一版 Profile；首版为空；禁止分叉 |
| `checksum` | string / 是 | 服务端按规范化 JSON 计算的 `sha256:<64hex>`；不可变 |
| `created_by/created_at` | 审计 / 是 | 服务端写入；Profile 无 `updated_*` 语义 |

**版本唯一键（冻结）**：

```sql
UNIQUE (project_id, scope, target_type,
        COALESCE(target_id, '00000000-0000-0000-0000-000000000000'::uuid),
        profile_version)
```

同时：

```sql
UNIQUE (project_id, supersedes_id) WHERE supersedes_id IS NOT NULL
```

- 新版本必须满足 `profile_version = predecessor.profile_version + 1`。
- Profile 行不可更新；修改 `name/required_types/selection_rule/schema_version` 必须新建版本。
- 旧 Profile 不得删除；已被 CalibrationRecord 引用时必须永久可读。

### 2.4 CalibrationRecord

| 字段 | 类型/必填 | 冻结说明 |
|---|---|---|
| `calibration_id` | UUID / 是 | UUIDv7；**一行代表一个不可变修订** |
| `project_id` | UUID / 是 | 服务端强制 |
| `calibration_version` | int ≥1 / 是 | 业务修订号；首版 1；修订必须 +1；不可变 |
| `lock_version` | int ≥1 / 是 | 乐观锁；服务端维护；不得与 `calibration_version` 混用 |
| `profile_id` | UUID / 是 | 指向精确 Profile 行 |
| `profile_version` | int ≥1 / 是 | 必须等于 `profile.profile_version`；创建时快照；不可变 |
| `schema_version` | string(64) / 是 | 必须等于 `profile.schema_version`；创建时快照；不可变 |
| `scope` | enum / 是 | 必须等于 `target_type` |
| `target_type` | enum / 是 | `ROBOT/DEVICE/SENSOR/SYSTEM` |
| `target_id` | UUID / 是 | `SYSTEM` 时等于 `project_id`；其余为目标实体 ID；复合外键指向 `calibration_target_refs` |
| `calibration_type` | enum / 是 | 见 §9 |
| `method` | string(200) / 是 | 工具/方法及版本，可读 |
| `parameters` | object / 是 | 按 `calibration_type + schema_version` 校验；见 §9 |
| `parent_frame`、`child_frame` | string(200) / 条件 | 见 §9 分类型矩阵；必须同时提供或同时为空 |
| `valid_from` | timestamptz / 是 | UTC |
| `valid_to` | timestamptz / 否 | 空 = 长期有效；非空必须 > `valid_from`；`EXPIRED` 必须有值 |
| `status` | enum / 是 | 初始仅 `DRAFT`；迁移见 §8 |
| `evidence_asset_ids` | array<UUID> / 条件 | 去重、按字典序排序；SUBMITTED 起非空；必须同项目且为 `VALID/ARCHIVED` |
| `source` | string(120) / 否 | 建议取值 `MANUAL/TOOL/IMPORT/ADAPTER`，阶段 1 保持字符串 |
| `checksum` | string / 是 | 服务端计算；SUBMITTED 起不可变；见 §5.2 |
| `uncertainty` | object / 条件 | DRAFT 可为空；SUBMITTED 起必填且按类型校验；不是数字 |
| `performed_by` | UUID / 是 | 必须等于服务端主体；不可由客户端指定 |
| `validated_by` | UUID / 条件 | VALIDATED 起必填；必须 != `performed_by`；必须是本项目有校验权限的成员 |
| `validated_at` | timestamptz / 条件 | VALIDATED 起必填；服务端时间 |
| `supersedes_id` | UUID / 条件 | 见 §5.3；同项目、同 `scope/target_type/target_id/calibration_type`；禁止分叉 |
| `status_reason` | string(1000) / 条件 | REJECTED、REVOKED、EXPIRED 必填；SUPERSEDED 由系统写 `SUPERSEDED_BY:<id>` |
| `status_changed_at`、`status_changed_by` | timestamptz / UUID / 是 | 最近状态变更投影；完整历史在审计 |
| `created_at/by`、`updated_at/by` | 审计 / 是 | 服务端写入 |

## 3. D1–D9 冻结决策

| ID | 原问题 | 冻结决策 | 影响 |
|---|---|---|---|
| D1 | CalibrationProfile 缺 `target_id` | 增加 `target_id`，允许为空；空=类型级模板，非空=目标级；`SYSTEM` 必须等于 `project_id`；非空时复合外键到 `calibration_target_refs` | Profile 可复用，也可目标绑定；DB 防跨项目 |
| D2 | CalibrationRecord 缺 `profile_version`/`schema_version` | 两者创建时从 Profile 快照写入，不可变；复合外键保证与 `profile_id` 精确匹配 | Episode 可复现 |
| D3 | evidence/validated_by/uncertainty 必填性冲突 | 按 §6.2 状态矩阵冻结；DRAFT 可暂缺，SUBMITTED 起齐全，VALIDATED 起有校验人 | 前端可按状态展示必填 |
| D4 | 坐标系字段名不一致，缺 time_base/sync_status | Sensor 的 `coordinate_frame` 更名 `frame_id`，新增 `frame_convention`；`time_base`/`sync_status` 归 Episode/Stream | 设备主数据与运行态分离 |
| D5 | `version` 同时承担乐观锁与业务版本 | CalibrationRecord 拆为 `calibration_version` 与 `lock_version`；Profile 用 `profile_version`；Robot/Device/Sensor 的 `version` 仅乐观锁 | 消除语义歧义 |
| D6 | UUIDv7 未实现 | 所有设备域 ID 服务端生成 UUIDv7；API 小写 36 字符；DB `uuid` | 时间有序、可索引 |
| D7 | REJECTED→DRAFT 原地复用 | 禁止原地 reopen；`revise` 创建新 CalibrationRecord（新 `calibration_id`），`calibration_version+1`，`supersedes_id` 指向旧记录 | 历史快照不可覆盖 |
| D8 | 迁移原因/故障码/审计缺失 | 动作命令必须带 `reason`/`fault_code`/`occurred_at`；追加式审计 + outbox；审计失败则回滚 | 可追责、可重放 |
| D9 | 标定引用语义未约束 | 目标一致性由 DB 投影表 + 触发器/复合外键约束；Sensor 内外参、Profile 目标、Record 目标全部校验 | 防跨项目与错类型引用 |

## 4. F2/F3/F5/F6 字段与语义冻结

### 4.1 F2：业务版本与乐观锁分离

| 实体 | 业务版本字段 | 乐观锁字段 | 规则 |
|---|---|---|---|
| Robot/Device/Sensor | 无（`code`/ID 标识业务对象） | `version` | 仅档案编辑与动作迁移递增；不表示修订历史 |
| CalibrationProfile | `profile_version` | 无 | 行不可变；新配置=新行 |
| CalibrationRecord | `calibration_version` | `lock_version` | 修订=新行；同一行内 `lock_version` 递增 |

- `calibration_version` 在同一 `(project_id, scope, target_type, target_id, calibration_type)` 谱系内唯一且连续。
- `lock_version` 只在同一 `calibration_id` 内递增；修订产生新 `calibration_id`，新行 `lock_version=1`。
- Canonical `calibration_snapshot[].version` 必须映射为 `calibration_version`，**禁止**使用 `lock_version`。
- API、DB、领域事件、前端类型必须使用同一命名；禁止别名字段混用。

### 4.2 F3：Profile 快照与分类型参数

- 创建 CalibrationRecord 时，服务端从 `CalibrationProfile` 读取并写入 `profile_id`、`profile_version`、`schema_version`；三者自创建起不可变。
- 修改 Profile 不会改变已创建记录；要使用新 Profile，必须创建新 CalibrationRecord。
- `parameters` 校验顺序：JSON 语法 → 大小/深度/键数 → `schema_version` 注册表 → 按 `calibration_type` 的 JSON Schema → 单位/坐标系/帧规则 → 跨字段规则。
- 未注册的 `schema_version`、未知 `calibration_type`、Schema 校验失败：`422 validation_failed` 或 `422 calibration_invalid`，不得写入。
- 参数 Schema 机器可读草案：`docs/architecture/contract-draft/device/calibration-parameters.v1.schema.json`；注册表：`docs/architecture/contract-draft/device/calibration-parameters.registry.v1.json`。

### 4.3 F5：状态迁移原因、故障码与审计

- 所有状态动作命令统一携带：`reason?`、`fault_code?`、`occurred_at?`、`maintenance_record_id?`、`evidence_refs?`、`Idempotency-Key`。
- 必填性由 §8 矩阵决定；缺失必填项返回 `422 validation_failed`，并在 `error.details` 中给出字段。
- 实体保存最近一次状态变更投影：`status_reason`、`fault_code`、`fault_detail`、`fault_occurred_at`、`status_changed_at`、`status_changed_by`。
- 完整历史写入追加式 `audit_logs` 与事务性 outbox；审计写入失败时整个迁移事务回滚（fail-closed）。
- 审计日志不可更新/删除；跨项目拒绝、权限拒绝也要审计。

### 4.4 F6：时间与坐标系失败关闭

- 入站时间统一 `astimezone(UTC)`；无时区、非法时区、`valid_to <= valid_from` 一律拒绝。
- Sensor 的 `frame_id` 必须符合 §7.2 命名；`frame_convention` 必须显式声明；缺失则不能创建 Sensor。
- 标定帧链必须可解析：`parent_frame != child_frame`；同一项目帧名全局唯一；禁止循环。
- `time_base`、`sync_status` 从 Episode/Stream 读取；缺失或 `UNVERIFIED/FAILED` 时，Episode 不得进入可训练数据集。设备域 API 不接收这两个字段的写入。
- RawAsset/Episode 快照必须记录 `calibration_id + calibration_version + checksum + target_type + target_id`；不得只记录 `calibration_id`。

## 5. 版本、不可变字段与写入规则

### 5.1 CalibrationProfile 写入规则

1. 新 Profile：`profile_version=1`、`supersedes_id=null`、`checksum` 由服务端计算。
2. 新版本：`profile_version=predecessor.profile_version+1`、`supersedes_id=predecessor.profile_id`；`scope/target_type/target_id` 必须与 predecessor 完全一致。
3. `supersedes_id` 唯一，禁止一个版本被两个新版本分叉。
4. 行创建后 `name/scope/target_type/target_id/profile_version/schema_version/required_types/selection_rule/checksum` 均不可变。
5. `target_id` 非空时必须同项目且存在于 `calibration_target_refs`；类型级模板也必须满足 `target_type` 合法。

### 5.2 `checksum` 计算与写入规则

- 算法：`sha256:<64 位小写十六进制>`。
- 规范化：RFC 8785 JSON Canonicalization Scheme（JCS）；数组保持语义顺序，`evidence_asset_ids` 先去重再按字典序排序。
- 参与字段：`calibration_version`、`profile_id`、`profile_version`、`schema_version`、`scope`、`target_type`、`target_id`、`calibration_type`、`method`、`parameters`、`parent_frame`、`child_frame`、`valid_from`（UTC RFC3339）、`valid_to`、`evidence_asset_ids`、`uncertainty`、`performed_by`、`supersedes_id`。
- 不参与字段：`status`、`validated_by`、`validated_at`、`lock_version`、`created_at/by`、`updated_at/by`、`status_reason`、审计字段。
- 写入时机：每次 DRAFT 保存时由服务端重算；`submit` 时重算并冻结；`validate`/`activate` 时重算比对。
- 客户端提交 `checksum` 一律忽略并返回 `422 validation_failed`（防止伪造）；比对失败返回 `422 calibration_checksum_mismatch`。

### 5.3 `supersedes_id` 写入规则

| 场景 | 写入规则 |
|---|---|
| 首版记录 | `null` |
| REJECTED 后修订 | 新记录创建时写入旧 `calibration_id`；旧记录保持 REJECTED、不可变；新 `calibration_version = old + 1` |
| 替代 ACTIVE/EXPIRED/REVOKED | 可在创建时写入预期前驱；也可在激活时由服务端写入当前 ACTIVE 记录 |
| 前驱约束 | 同 `project_id`、同 `scope/target_type/target_id/calibration_type`；前驱不能是 DRAFT/SUBMITTED/SUPERSEDED；禁止自引用 |
| 唯一性 | `UNIQUE (project_id, supersedes_id) WHERE supersedes_id IS NOT NULL`，禁止分叉 |
| 不可变 | SUBMITTED 后不可修改；唯一例外是激活事务中由服务端补写当前 ACTIVE 前驱，并写审计 |

### 5.4 提交后不可变字段

`SUBMITTED` 起以下字段冻结，任何 PATCH/动作不得修改：

`calibration_id`、`project_id`、`calibration_version`、`profile_id`、`profile_version`、`schema_version`、`scope`、`target_type`、`target_id`、`calibration_type`、`method`、`parameters`、`parent_frame`、`child_frame`、`valid_from`、`valid_to`、`evidence_asset_ids`、`checksum`、`uncertainty`、`performed_by`、`supersedes_id`、`created_at`、`created_by`。

`VALIDATED` 起额外冻结：`validated_by`、`validated_at`。

只允许变化：`status`（仅经 §8 动作）、`status_reason`（仅对应动作）、`status_changed_at/by`、`lock_version`、`updated_at/by`。

### 7.2 命名与校验

- 世界：`world`。
- 机器人基座：`<robot_id>/base_link`。
- 末端/工具：`<robot_id>/ee_link`、`<robot_id>/tool0`。
- 相机：`<sensor_id>/link`、`<sensor_id>/optical_frame`。
- IMU：`<sensor_id>/imu_link`。
- 关节：`joint/<joint_name>`。
- 帧名项目内唯一；`frame_id` 不得为空、不得含空白；`parent_frame != child_frame`。
- 相机/深度传感器 `frame_convention` 必须为 `OPTICAL` 或 `RDF`；机器人基座/IMU 推荐 `FLU`；世界系 `ENU/NED` 必须显式。
- `time_base` 缺失、`sync_status=UNVERIFIED/FAILED` 时，Episode 创建/质检必须失败关闭，不得默认通过。

## 8. 状态机、前置条件、错误码与审计

### 8.1 生命周期状态机

```text
PROVISIONED → ACTIVE → IN_MAINTENANCE → ACTIVE
                    ├→ FAULT → IN_MAINTENANCE → ACTIVE
                    ├→ SUSPENDED → ACTIVE
                    └→ RETIRED（终态）
任意非终态 → SUSPENDED / RETIRED（满足前置条件）
```

| 迁移 | 前置条件 | 允许角色 | 必填原因/故障 | 错误码 | 审计事件 |
|---|---|---|---|---|---|
| PROVISIONED→ACTIVE | 档案完整；Sensor 的 `frame_id/frame_convention` 齐全；Profile 目标一致；采集就绪另需有效标定 | Device Operator、Project Manager | 无 | `state_transition_invalid`、`validation_failed`、`calibration_not_active` | `ddp.{robot|device|sensor}.activated.v1` |
| ACTIVE→IN_MAINTENANCE | 无执行中绑定任务，或任务已暂停 | Device Operator | `reason` | `conflict`、`state_transition_invalid` | `...maintenance_started.v1` |
| IN_MAINTENANCE→ACTIVE | `maintenance_record_id` 与复检证据完整 | Device Operator、Quality Inspector | `maintenance_record_id` | `validation_failed`、`state_transition_invalid` | `...maintenance_completed.v1` |
| ACTIVE/IN_MAINTENANCE→FAULT | 故障可上报 | Device Operator、Project Manager | `fault_code`、`occurred_at` | `validation_failed`、`state_transition_invalid` | `...fault_reported.v1` |
| FAULT→IN_MAINTENANCE | 已受理维修 | Device Operator | `maintenance_record_id` | `validation_failed`、`state_transition_invalid` | `...maintenance_started.v1` |
| 任意非终态→SUSPENDED | 管理原因明确 | Project Manager、Project Owner | `reason` | `validation_failed`、`state_transition_invalid` | `...suspended.v1` |
| SUSPENDED→ACTIVE | 原因解除、无未结故障 | Project Manager | `reason` | `validation_failed`、`state_transition_invalid` | `...resumed.v1` |
| 任意非终态→RETIRED | 无在途任务/上传；引用已归档或允许只读保留 | Project Owner + Device Operator | `reason` | `conflict`、`validation_failed`、`state_transition_invalid` | `...retired.v1` |

### 8.2 标定状态机

```text
DRAFT → SUBMITTED → VALIDATED → ACTIVE → SUPERSEDED（终态）
              └→ REJECTED →（revise，新记录）DRAFT
ACTIVE → REVOKED（终态）
ACTIVE → EXPIRED（终态，系统任务）
```

> **关键变更**：`REJECTED→DRAFT` 不再原地迁移；`revise` 创建新 CalibrationRecord，旧记录保持 REJECTED。

| 迁移 | 前置条件 | 允许角色 | 必填原因 | 错误码 | 审计事件 |
|---|---|---|---|---|---|
| DRAFT→SUBMITTED | 证据非空；参数通过 Schema；校验和计算成功；目标存在且同项目；Profile 精确匹配 | Device Operator | 无 | `validation_failed`、`calibration_invalid`、`calibration_target_invalid`、`calibration_checksum_mismatch` | `ddp.calibration.submitted.v1` |
| SUBMITTED→VALIDATED | Schema/单位/帧/证据通过；`validated_by != performed_by`；校验人具备角色；校验和一致 | Quality Inspector 或独立 Device Operator | 无 | `validation_failed`、`calibration_invalid`、`forbidden`、`calibration_checksum_mismatch` | `ddp.calibration.validated.v1` |
| SUBMITTED→REJECTED | 记录驳回原因 | Quality Inspector | `status_reason` | `validation_failed`、`state_transition_invalid` | `ddp.calibration.rejected.v1` |
| REJECTED→（新记录）DRAFT | 前驱为 REJECTED；同目标/类型；版本 +1；`supersedes_id` 合法 | Device Operator | 无 | `validation_failed`、`duplicate_resource` | `ddp.calibration.revision_created.v1` |
| VALIDATED→ACTIVE | `valid_to` 为空或 > now；目标未退役；无同目标 ACTIVE；原子替代旧 ACTIVE | Project Manager、Project Owner、Device Operator（需授权） | 无（系统写 `supersedes_id`） | `calibration_invalid`、`calibration_active_conflict`、`state_transition_invalid` | `ddp.calibration.activated.v1` |
| ACTIVE→REVOKED | 标定错误/设备变更/事故；影响评估完成 | Project Owner + Quality Inspector | `status_reason` | `validation_failed`、`forbidden`、`state_transition_invalid` | `ddp.calibration.revoked.v1` |
| ACTIVE→EXPIRED | 系统时间 >= `valid_to`；`valid_to` 非空 | 系统任务 | 系统写 `VALIDITY_EXPIRED` | `state_transition_invalid` | `ddp.calibration.expired.v1` |
| ACTIVE→SUPERSEDED | 仅由新记录激活事务触发 | 系统 | 系统写 `SUPERSEDED_BY:<id>` | `state_transition_invalid` | `ddp.calibration.superseded.v1` |

### 8.3 故障码

`fault_code` 取值：`DEVICE_OFFLINE`、`SENSOR_NO_SIGNAL`、`CALIBRATION_EXPIRED`、`HARDWARE_FAILURE`、`SOFTWARE_ERROR`、`POWER_FAILURE`、`NETWORK_ERROR`、`OVERHEAT`、`OTHER`。

- `OTHER` 必须填写 `fault_detail`。
- 未知故障码返回 `422 validation_failed`，不得存入。

### 8.4 add 合法初始状态与直写禁令

| 实体 | add 允许的初始状态 | 禁止 |
|---|---|---|
| Robot | `PROVISIONED` | 任何其他状态 |
| Device | `PROVISIONED` | 任何其他状态 |
| Sensor | `PROVISIONED` | 任何其他状态 |
| CalibrationProfile | 无状态；`profile_version=1` 或按 supersedes 规则 | 原地改版本 |
| CalibrationRecord | `DRAFT`；`calibration_version=1` 或修订 +1 | 任何其他状态 |

- 领域实体不暴露可写 `status` 构造参数；`add`/`create` 工厂固定初始状态；从 DB 恢复使用内部工厂。
- Repository `add()` 必须拒绝非初始状态；`save()` 必须**不包含 `status` 列**，并把 `lock_version`/`version` 放进 `UPDATE ... WHERE`。
- 状态动作使用具名方法（`activate/enter_maintenance/report_fault/suspend/retire/submit/validate/reject/activate/revoke/expire`），每个动作带 `from_status` 条件更新。
- DB 兜底：`status` 枚举 CHECK；INSERT 触发器拒绝非初始状态；UPDATE 触发器校验白名单迁移并写审计；非法迁移返回 `409 state_transition_invalid`。
- 禁止通用 `PATCH status`、禁止 SQL 直写状态；违反由契约测试与 PostgreSQL 触发器双重拦截。

## 9. 分类型 parameters JSON Schema

### 9.1 通用规则

- Schema 版本：`ddp.device.calibration-parameters/1.0.0`；注册表按 `calibration_type` 选择 `$defs`。
- 顶层 `additionalProperties=false`；厂商扩展只能放在 `extensions`，键名必须形如 `vendor.agibot`。
- 数值必须有限；数组长度固定；四元数 `[w,x,y,z]` 且归一化误差 ≤ `1e-6`。
- 长度单位 `m`、角度 `rad`、力 `N`、力矩 `N*m`、时间 `ns`（JSON 字符串，避免精度丢失）。
- 未知单位、隐式默认、缺失帧、错误数组顺序一律失败关闭。
- 机器可读 Schema：`docs/architecture/contract-draft/device/calibration-parameters.v1.schema.json`。

### 9.2 分类型必需键

| `calibration_type` | `parameters` 必需键 | 帧要求 | `uncertainty` 必需键 |
|---|---|---|---|
| INTRINSICS | `camera_model`、`image_width`、`image_height`、`fx`、`fy`、`cx`、`cy`、`distortion_model`、`distortion_coefficients`、`unit="px"` | 无 | `fx_px`、`fy_px`、`cx_px`、`cy_px`、`reprojection_rms_px` |
| EXTRINSICS | `translation_m[3]`、`rotation_quat_wxyz[4]`、`transform_type` | `parent_frame`、`child_frame` 必填 | `translation_m`、`rotation_rad` |
| HAND_EYE | `eye_in_hand`、`base_frame`、`tool_frame`、`camera_frame`、`translation_m[3]`、`rotation_quat_wxyz[4]`、`solver` | 顶层 `parent_frame/child_frame` 必填 | `translation_m`、`rotation_rad` |
| IMU | `noise_density`、`random_walk`、`bias`、`gravity_m_s2`、`axis_alignment[3][3]`、`include_gravity` | 含外参时顶层帧必填 | `accel_bias_m_s2`、`gyro_bias_rad_s` |
| JOINT_OFFSET | `joint_order[]`、`joint_types[]`、`offsets[]`（含 `joint_name/value/unit`） | 无 | `offset_values[]`（单位与 offsets 一致） |
| TIME_OFFSET | `sensor_id`、`reference_sensor_id`、`offset_ns`、`method` | 无 | `offset_ns`、`drift_ppm?` |
| FORCE_TORQUE | `six_axis_order`、`bias[6]`、`unit_force="N"`、`unit_torque="N*m"` | `parent_frame`、`child_frame` 必填 | `force_n`、`torque_nm` |
| DEPTH_ALIGNMENT | `depth_sensor_id`、`rgb_sensor_id`、`target_resolution[2]`、`depth_scale_m`、`invalid_value`、`translation_m[3]`、`rotation_quat_wxyz[4]` | `parent_frame`、`child_frame` 必填 | `translation_m`、`rotation_rad`、`depth_m` |

### 9.3 跨字段规则

- `parent_frame == child_frame` 拒绝；`EXTRINSICS/HAND_EYE/FORCE_TORQUE/DEPTH_ALIGNMENT` 缺帧拒绝。
- `TIME_OFFSET.sensor_id != reference_sensor_id`；两者必须同项目且存在。
- `JOINT_OFFSET.joint_order/joint_types/offsets` 长度一致，`joint_name` 唯一且顺序固定。
- `FORCE_TORQUE.six_axis_order` 必须严格为 `["fx","fy","fz","tx","ty","tz"]`。
- `IMU` 出现 `translation_m`/`rotation_quat_wxyz` 任一，则两者与顶层帧都必须齐全。
- `INTRINSICS.unit` 只能为 `px`；`distortion_coefficients` 顺序由 `distortion_model` 固定。
- `valid_from <= captured_at < valid_to`（`valid_to` 为空表示长期）；不满足则 Episode 失败关闭。

## 10. target_id 完整性：冻结选择

### 10.1 选择

**采用 DB 兜底方案（唯一权威防线）：`calibration_target_refs` 多态目标投影表 + 复合外键。**

应用层仍做前置解析（用于友好错误码和提前拒绝），但**不把应用层校验当作完整性保证**；直接 SQL、其他服务、后台脚本同样受 DB 约束。

### 10.2 表结构

```sql
CREATE TABLE calibration_target_refs (
  project_id      uuid NOT NULL,
  target_type     varchar(16) NOT NULL CHECK (target_type IN ('ROBOT','DEVICE','SENSOR','SYSTEM')),
  target_id       uuid NOT NULL,
  lifecycle_status varchar(32) NOT NULL,
  is_retired      boolean NOT NULL DEFAULT false,
  updated_at      timestamptz NOT NULL,
  PRIMARY KEY (project_id, target_type, target_id)
);
```

- Robot/Device/Sensor 创建时由 DB 触发器写入/更新投影；状态变化同步 `lifecycle_status/is_retired`。
- `SYSTEM` 行在项目创建时写入：`target_type='SYSTEM', target_id=project_id`。
- `CalibrationProfile.target_id` 非空时：`FOREIGN KEY (project_id, target_type, target_id) REFERENCES calibration_target_refs`。
- `CalibrationRecord.target_id`：`FOREIGN KEY (project_id, target_type, target_id) REFERENCES calibration_target_refs`。
- 目标退役后：历史记录保留；新建标定在应用层拒绝（`calibration_target_invalid`），DB 触发器同样拒绝新引用。
- 删除目标：只允许软删除/退役；投影行不删除，`is_retired=true`；`ON DELETE RESTRICT`。

### 10.3 其他 D9 语义约束

- Profile 与 Record 的 `scope = target_type`；`SYSTEM` 的 `target_id = project_id`。
- Record 的 Profile 必须满足：`profile.target_type = record.target_type`，且 `profile.target_id IS NULL OR profile.target_id = record.target_id`。
- Sensor `intrinsic_calibration_id`/`extrinsic_calibration_id` 的 `target_type/target_id/calibration_type` 必须匹配；状态必须为 `VALIDATED/ACTIVE`。
- Robot/Device/Sensor 的 `calibration_profile_id` 必须满足 Profile 目标匹配；不得引用他项目 Profile。
- 以上跨行规则由 PostgreSQL 触发器实现；SQLite 仅用于单元测试，不作为验收证据。

## 11. API 契约变更摘要

| 变更 | 内容 |
|---|---|
| 字段更名 | Sensor `coordinate_frame` → `frame_id`；CalibrationRecord `version` → `lock_version`；CalibrationProfile `version` → `profile_version` |
| 新增字段 | Sensor `frame_convention`；CalibrationRecord `calibration_version`、`profile_version`、`schema_version`、`status_reason`；Robot/Device/Sensor `status_reason/fault_code/fault_detail/fault_occurred_at/status_changed_at/by` |
| 类型修正 | `channels` 为 integer；`uncertainty` 为 object；`sensor_type` 为 `RGB_D` |
| 新增动作 | `POST /calibrations/{id}/revise`：创建修订记录，替代 `reopen` 原地语义 |
| 动作请求体 | `validate/reject/revoke/expire/activate` 与生命周期动作统一支持 `reason/fault_code/occurred_at/maintenance_record_id/evidence_refs` |
| 禁止修改 | `PATCH` 禁止 `status/project_id/*_id/checksum/lock_version` 及 SUBMITTED 后冻结字段 |
| 错误码 | 新增 §8.6 中 `calibration_target_invalid`、`calibration_profile_invalid`、`calibration_checksum_mismatch`、`calibration_active_conflict` |
| 幂等 | 写动作支持 `Idempotency-Key`，作用域 `(project_id, user_id, key)`；同键不同体返回 `409 idempotency_key_reused` |
| 并发 | 动作必须带 `If-Match`；缺失 428，失配 409 |
| 审计 | 提供只读审计查询入口或复用平台 `/audit-logs`；不得提供更新/删除 |
