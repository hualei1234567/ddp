## 0. 使用规则

1. 每条验收采用 Given / When / Then，可由第三方复现；不得写“应该可以”。
2. 证据优先级：自动化测试 > 请求/响应 > 数据库/对象存储记录 > 审计日志 > 截图 > 口头说明。
3. 未执行标 `NOT RUN`；环境/外部平台阻塞标 `BLOCKED`；缺少真实证据标 `未验证`。
4. 合成/Mock 数据必须标 `[SYNTHETIC]`/`[MOCK]`，不得进入真实指标分母，不得冒充真实模型效果。
5. 每条验收附测试名、命令、对象 ID、request_id、错误码、报告 Hash 或证据路径。
6. 缺陷等级：S1 越权/跨项目泄漏/已发布版本被改写/评测结论伪造/审计缺失；S2 主链路不可完成且无绕行；S3 局部错误；S4 文案布局。
7. 本轮已在本地真实 PostgreSQL 执行 P0 链路；未覆盖项在 §10 明确标注 `NOT RUN` / `BLOCKED`。

## 2. 模型与版本

### AC-MV-01 模型创建与项目隔离
Given 项目 A 的 EDITOR；When 创建 Model；Then 201 且 `project_id=A`、`status=DRAFT`；项目 B 成员访问返回 404。

### AC-MV-02 版本产物校验
Given DRAFT ModelVersion；When 提交校验且产物 SHA256 与声明一致；Then `READY`；Hash 不一致 → 422 `model_artifact_checksum_mismatch`，不得 READY。

### AC-MV-03 发布不可变
Given READY 版本；When OWNER 发布；Then `RELEASED`；此后 PATCH 产物/运行时报 409 `model_version_immutable`；新变更创建新版本。

### AC-MV-04 发布职责分离
Given 版本创建人；When 同一人尝试发布；Then 403 `model_release_approval_forbidden`（或按契约显式规则）。

### AC-MV-05 归档门禁
Given RELEASED 版本存在 ACTIVE 推理服务；When 归档；Then 409 `model_version_in_use`。

## 3. 评测

### AC-EV-01 评测输入门禁
Given 未冻结或失效 DatasetVersion；When 创建评测；Then 409 `evaluation_dataset_not_ready`。

### AC-EV-02 结论计算
Given 指标与阈值；When 全部指标存在且达标 → PASS；缺指标 → UNKNOWN；任一硬阈值失败 → FAIL；不得默认 PASS。

### AC-EV-03 结果不可变
Given SUCCEEDED 评测；When 修改指标或结论；Then 409 `evaluation_immutable`。

### AC-EV-04 跨项目引用
Given 项目 B 的 DatasetVersion；When 项目 A 创建评测；Then 404/403，不泄漏存在性。

### AC-EV-05 失败可反馈
Given FAIL 评测；When 创建反馈；Then 反馈保存 `evaluation_id` 与维度证据。

## 4. 推理

### AC-IN-01 服务登记与状态
Given 模型版本；When 登记推理服务并激活/停止；Then 状态按状态机迁移，非法迁移 409。

### AC-IN-02 任务结果
Given 推理任务；When 外部失败；Then `FAILED` 且记录错误码；不得 SUCCEEDED。

### AC-IN-03 Adapter 不可用
Given 未配置真实推理 Adapter；When 执行推理；Then 503/`BLOCKED`，不写入成功结果。

## 5. 反馈与缺口

### AC-MF-01 反馈内容
Given 评测/推理；When 创建反馈；Then 问题类型、严重级别、维度、证据必填；状态 OPEN。

### AC-MF-02 缺口聚合
Given 多条 OPEN/TRIAGED 反馈；When 查询 gap-summary；Then 按维度去重聚合，输出目标覆盖与建议补采量；`UNKNOWN` 不被计为 0。

### AC-MF-03 项目隔离与审计
Given 项目 A 反馈；When 项目 B 查询；Then 404；创建/转需求写审计。

## 6. 数据需求闭环

### AC-DR-01 反馈转需求
Given 反馈；When 转为 DataRequirement；Then 需求保存 `source_feedback_ids`，反馈置 `REQUIREMENT_CREATED`，二者可双向追溯。

### AC-DR-02 审批职责分离
Given 提交人；When 同一人审批；Then 403 `data_requirement_approval_forbidden`。

### AC-DR-03 满足门禁
Given APPROVED/IN_PROGRESS 需求；When 标记 SATISFIED 且未关联冻结 DatasetVersion；Then 409 `data_requirement_not_satisfied`；关联后成功。

### AC-DR-04 复测关联
Given SATISFIED 需求；When 创建复测评测；Then 需求记录 `retest_evaluation_ids`，可查询闭环。

### AC-DR-05 终态不可回退
Given CLOSED/REJECTED/CANCELLED；When 再次动作；Then 409 `state_transition_invalid`。

### AC-MF-12 核心闭环（阶段门禁）
Given 模型 FAIL 评测；When 创建反馈 → 转需求 → 审批 → 关联冻结数据集版本 → 创建复测评测；Then 全链路 200/201，需求状态与关联 ID 均可追溯，审计完整。**这是阶段 5 的放行条件。**

## 7. 并发、幂等与治理

### AC-GV-01 乐观锁
Given 版本 `If-Match` 失配；When 动作；Then 409 `version_conflict`；缺失 428 `precondition_required`。

### AC-GV-02 幂等键
Given 相同 `Idempotency-Key` 与相同请求体；When 重复创建/动作；Then 返回首次结果；不同请求体同键 409 `idempotency_key_reused`。

### AC-GV-03 审计与 outbox
Given 发布、评测、反馈转需求、需求审批/满足；When 成功；Then 审计与 outbox 同事务写入；回滚不留半成品。

### AC-GV-04 指标口径
Given PASS/FAIL/UNKNOWN 混合；When 计算通过率；Then UNKNOWN 不入分母；合成数据标注且不入真实分母。

## 8. 前端与页面状态

### AC-UI-01 页面状态
模型/版本/评测/反馈/需求/缺口页面覆盖 Loading/Empty/Error/Forbidden/Partial/Stale/Disabled。

### AC-UI-02 动作渲染
按钮只按 `allowed_actions` 渲染；前端不按状态推断权限。

### AC-UI-03 闭环可视化
评测详情可一键创建反馈；反馈详情可转需求；需求详情展示关联数据集版本与复测。
