## 0. 使用说明

### 0.1 验收规则

1. 每条验收标准采用 Given / When / Then，必须可被第三方复现。
2. 证据优先级：自动化测试 > 接口请求/响应 > 数据库/对象存储记录 > 审计日志 > 人工截图 > 口头说明。
3. 人工截图只能作为辅助证据，**不能单独证明**权限、项目隔离、幂等、不可变、文件安全等属性。
4. 未执行标 `NOT RUN`；环境/设备阻塞标 `BLOCKED`；缺少真实证据标 `未验证`；不得用「应该可以」代替结果。
5. 未跑测试不得声称通过；不得为让测试变绿而放宽断言、删除用例或跳过安全测试。
6. 使用 Mock/合成/注入数据的验收必须标 `[MOCK]` 或 `[SYNTHETIC]`，写明替代范围与未验证项。
7. 每条验收必须附测试名、命令、请求/响应、对象 ID、Job ID、错误码或截图路径；无证据视为未通过。

### 0.2 状态与优先级

| 标记 | 含义 |
|---|---|
| `NOT RUN` | 未执行 |
| `BLOCKED` | 环境、设备、决策或依赖阻塞 |
| `未验证` | 结论缺少真实证据或方案未定 |
| `P0` | 阶段 2 阻断项 |
| `P1` | 可用性增强，可后置但必须列出影响 |
| `[MOCK]` | 使用模拟/注入数据 |
| `[SYNTHETIC]` | 使用合成样例数据 |

### 0.3 缺陷等级

| 等级 | 定义 | 阶段门禁 |
|---|---|---|
| S1 阻断 | 数据丢失、越权/跨项目泄漏、状态损坏、原始数据被覆盖、审计缺失 | 必须修复，阶段不得退出 |
| S2 严重 | 主链路无法完成且无绕行、上传/接入持续失败、任务无法推进 | 必须修复或有用户批准的临时措施 |
| S3 一般 | 局部功能错误、错误提示不清晰、部分状态缺失 | 可后置，但需 Owner 与期限 |
| S4 建议 | 文案、布局、易用性优化 | 可排期 |

### 2.2 合成样例包要求（T2-DATA-01）

1. 至少 2 路视频（H.264/MP4 或等效），分辨率/帧率已知，时长 60–120 秒。
2. 机器人状态 CSV/JSON，至少 10 Hz，包含时间戳、关节位置、末端位姿、夹爪状态。
3. 动作/语言指令元数据，至少 1 条。
4. 标定快照：相机内参/外参、坐标系、单位、有效期。
5. Manifest：文件清单、SHA256、大小、时间范围、传感器通道。
6. 明确标记 `data_source=SYNTHETIC`、来源说明、生成方式。
7. 另提供一份时间偏移/缺通道变体用于负向测试。

### 2.3 Mock 标注与使用规则

1. 页面、记录、验收报告必须显示/标注 `[MOCK]` 或 `[SYNTHETIC]`；不得只靠颜色。
2. 合成数据不得进入真实看板分母；看板默认 `data_source=REAL`，样例视图显式开启。
3. Mock Adapter 只能证明契约路径与错误处理，不能证明真实设备能力、真实心跳与真实故障。
4. 权限、项目隔离、文件安全、Hash、不可变、幂等、审计必须在**真实实现**上验证，不能用 Mock 替代。
5. 网络注入必须记录工具、参数、时间、持续时长与结果。
6. 真实采集验收（AC-E2E-02）不得用合成样例替代；无真实环境时标 `BLOCKED`。

### 2.4 验收证据格式

每条 AC 的 QA 报告至少包含：

```text
AC ID：
测试名/脚本：
环境：local/staging；commit/revision；迁移版本
前置数据：T2-DATA-xx；是否 Mock
操作步骤：
请求/响应 或 页面路径：
期望 vs 实际：
对象 ID / Job ID / 错误码 / request_id：
证据路径：日志、截图、审计查询、对象存储清单
结论：PASS / FAIL / BLOCKED / NOT RUN
缺陷等级与链接：
```

阶段 2 必须同时满足以下条件才可退出：

1. 所有 P0 验收项为 `PASS` 且有真实证据；未执行/阻塞项必须列明原因与影响。
2. P1 项未完成时，必须列出影响、临时措施、Owner 与计划；不得静默带病进入阶段 3。
3. 权限、项目隔离、任务级范围、职责分离、文件安全、不可变、审计测试全部通过。
4. 无 S1/S2 缺陷；S3 缺陷有 Owner 与期限；S4 可排期。
5. 合成样例链路验收（AC-E2E-01）通过，且报告明确标注 `[SYNTHETIC]`。
6. 真实采集验收（AC-E2E-02）若未执行，必须标 `BLOCKED` 并说明缺少的设备/场地/人员；**不得用样例替代真实结论**。
7. 看板指标与明细核对通过；缺失语义与样例过滤生效。
8. 交付物包含：变更摘要、测试命令/结果、未验证范围、风险、回滚点、真实/Mock 边界说明。
9. QA 独立验收通过，用户确认后进入阶段 3。

### 4.1 不得判定为通过的情形

- 只有页面截图，没有接口/自动化/审计证据证明权限、隔离、幂等、不可变。
- 只跑了合成样例，却写「真实采集验收通过」。
- 测试被跳过、断言被放宽、用例被删除。
- 失败被标为「已知问题」但没有 Owner、期限与用户批准。
- 看板缺失数据显示为 0，或样例数据混入真实指标。
- 原始文件被覆盖、Episode 被静默改写、审计缺失。
- 弱网方案未验证却宣称现场可用。
