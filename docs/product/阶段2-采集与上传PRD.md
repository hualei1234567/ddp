## 1. 背景、目标与范围

### 1.1 背景

阶段 1 解决「设备可登记、可标定、可被权限隔离」，但设备档案本身不产生数据价值。阶段 2 必须把上游数据需求转成可执行采集计划，把现场采集数据安全地送入平台，并形成可追溯的原始资产与基础 Episode。否则阶段 3 的标注与阶段 4 的数据集都缺少可信输入。

阶段 2 的核心不是「做一个上传页面」，而是建立一条**可计划、可执行、可恢复、可追溯、失败可定位**的采集生产链路。

### 1.2 阶段 2 目标

1. 数据需求可版本化、可审批、可关联任务、可计算达成度。
2. 采集方案可把场景、动作、视角、设备/传感器、参数、标定要求、SOP、质量标准与安全要求一次说清。
3. 采集任务与批次有明确状态机、前置条件、执行角色、冲突校验与审计。
4. 采集员在低学习成本的工作台中完成任务确认、开工检查、采集、上传、自检、返工与弱网恢复。
5. 上传具备分片、断点续传、幂等、文件安全校验与失败可定位能力。
6. 接入完成格式探测、元数据提取、完整性检查、隔离与基础 Episode 切片。
7. 看板以统一口径展示今日任务、待执行、执行中、已完成、原始数据量、有效 Episode、有效时长、不合格率、异常与项目进度。
8. 明确区分真实采集、合成样例与 Mock，避免用假数据通过阶段验收。

### 1.3 成功定义

阶段 2 成功不是「页面能打开」或「样例能上传」，而是同时满足：

1. 一份数据可从数据需求版本追溯到采集方案/SOP 版本、任务、批次、上传会话、RawAsset 与 Episode。
2. 任务、批次、上传、接入与 Episode 状态一致，非法转换被拒绝，状态变化有审计。
3. 现场断网、上传中断、会话过期、文件损坏、标定过期均有明确恢复路径或失败原因。
4. 权限、项目隔离、任务级数据范围、职责分离与下载审计通过独立测试。
5. 合成样例验收与真实采集验收分开记录；没有真实采集时明确写 `BLOCKED`，不得宣称完成真实采集验收。
6. 看板每个指标有口径、时间范围、来源、Owner 与缺失语义，且能与明细核对。

### 1.6 术语

| 术语 | 含义 |
|---|---|
| 数据需求单 | 描述业务目标、场景/动作、数据量、质量阈值、交付时间与验收标准的上游依据，版本化 |
| 采集方案 | 把需求转成可执行采集配置：场景、动作、视角、设备/传感器、参数、标定、SOP、质量与安全要求 |
| SOP | 标准作业程序；任务执行时记录所用版本，现场必须就近可见 |
| 采集任务 | 一次可审批、可分配、可执行、可质检的采集工作单元 |
| 采集批次 | 任务的子单元；一个任务可拆多个批次，批次状态受任务约束 |
| 开工检查 | 开始采集前的设备、传感器、标定、时间同步、存储、电量、场景与 SOP 检查 |
| 上传会话 | 一次分片上传的上下文；包含分片、幂等键、过期时间与对象前缀 |
| RawAsset | 原始资产：对象存储引用、Hash、大小、格式、来源任务/批次/设备/人员、状态 |
| IngestionJob | 接入异步任务：校验、元数据提取、解析、时间对齐、标定校验、切片、登记 |
| Episode | 一次可标注/可训练的数据片段，关联任务、批次、设备、传感器、时间范围、标定快照与血缘 |
| 隔离区 | 校验不通过、可疑或不可解析数据的暂存区，不得进入可训练数据 |
| 有效 Episode | 通过阶段 2 基础质量门禁、未被标记无效的 Episode；详细口径见看板文档 |
| 合成样例 | 人工构造或回放生成的数据，不是真实设备/场地采集，必须标记 `[SYNTHETIC]` |

### 2.2 假设

1. 沿用单库多项目，所有阶段 2 对象强制带 `project_id`，服务端校验项目范围。
2. 现场原始录制由机器人/采集设备完成；DDP Web 工作台负责任务、SOP、检查、队列、上传、自检与返工，不承担多路原始录制。
3. 阶段 2 可用合成样例包完成链路与契约验收，但真实采集验收必须单独记录。
4. 场地采用最小 `location_id`/文本位置，不建完整基地运营模块；完整场地利用率 `N/A`。
5. 任务、批次、上传、资产、Episode 状态由服务端权威判定，前端不得直接修改状态字段。
6. 任何状态推进必须有前置条件、执行角色、原因（如需要）与审计。

- 只写 `docs/product/**`；不改代码、配置、数据库、契约与测试。
- 不跳过用户确认扩大范围；非目标变更必须由 General Owner 提交并经用户批准。
- 不把「代码存在」当作「功能可用」；不把 Mock 当真实采集。

### 3.3 职责分离硬规则

1. 需求、方案、任务的**创建人不得审批自己的提交**。
2. 质检人不得质检自己参与采集的批次；采集员不得对自己的数据给出最终质量结论。
3. 隔离区放行需至少两人（DE + QI/PO），不得由上传者单独放行。
4. 平台管理员默认不参与项目业务；需要时走 break-glass 并强审计。
5. 数据下载、取消、墓碑、权限变更属于高风险操作，必须二次确认并写审计。

| 标识 | 需求编号 `code`、标题、版本 `version`、状态 | 是 | 编号项目内唯一；版本只增不减；已批准不可原地改 |

| 标签要求 | 标签需求、关键字段、后续标注提示 | 否 | 阶段 2 不建标签 Schema，只记录需求 |

| 关联 | 创建人、Owner、关联任务、关联方案 | 是/系统 | 关联任务用于达成度；方案必须引用需求版本 |
| 版本 | 变更原因、上一版本、生效时间 | 是 | 已批准变更生成新版本；在途任务保留原版本快照 |

**需求状态**：`DRAFT → SUBMITTED → APPROVED → IN_DELIVERY → FULFILLED`；分支 `REJECTED → DRAFT`、`SUPERSEDED`、`CANCELLED`、`ARCHIVED`。详见状态机文档。

### 4.2 采集方案（CollectionPlan）

| 字段组 | 字段 | 必填 | 业务规则 |
|---|---|---|---|
| 标识 | 方案编号、名称、版本、状态、关联需求版本 | 是 | 方案必须绑定需求版本；方案变更生成新版本 |
| 场景 | 场景定义、场景布置、环境条件、进入/退出条件 | 是 | 引用场景库版本；场景变化需重新确认 |
| 动作 | 动作脚本、动作阶段、前置条件、关键步骤、成功条件、失败条件 | 是 | 引用动作规格版本；成功/失败条件可判定 |
| 视角 | 相机位置、视角名称、覆盖范围、必需/可选 | 是 | 与传感器配置和设备能力一致 |
| 设备/传感器 | 机器人/设备类型、能力要求、传感器类型、采样频率、分辨率、同步方式 | 是 | 分配时校验设备状态、能力与标定；不匹配需阻断或显式警告 |
| 采集参数 | 录制格式、帧率、曝光、分辨率、压缩、分片/文件切分、时间源 | 是 | 参数由方案配置，不在前端硬编码 |

| SOP | SOP 版本、必需步骤、自检清单 | 是 | 只能引用已发布 SOP；任务记录快照 |
| 质量 | 质量阈值、检查项、抽检要求、不合格处理 | 是 | 与需求质量阈值一致，不得低于需求 |
| 安全 | 安全等级、人员防护、设备安全、场景风险、应急预案 | 是 | 安全要求必须可执行；安全事件优先级最高 |
| 版本 | 批准人、批准时间、变更原因、上一版本 | 是 | 创建人不得自批；已批准只读 |

**方案状态**：`DRAFT → PENDING_REVIEW → APPROVED`；分支 `REJECTED → DRAFT`、`SUPERSEDED`、`CANCELLED`、`ARCHIVED`。

### 4.3 场景与动作库

- 场景：编码、名称、业务域（家庭/工业/仓储/桌面/厨房等）、说明、环境要求、安全要求、版本、状态。
- 动作：编码、名称、说明、前置条件、关键步骤、成功判据、失败模式、难度、适配机器人、适配设备、所需传感器、标签需求提示、版本、状态。
- 规则：任务只能引用**已发布**的场景/动作版本；未发布版本不得被方案或任务引用；版本升级不自动切换在途任务。

### 4.4 SOP

每份 SOP 必须包含以下章节，缺一不可发布：

1. 目标与适用范围
2. 适用设备/机器人/传感器
3. 设备检查（开工前）
4. 场景布置
5. 标定与时间同步
6. 操作步骤（可勾选）
7. 采集参数
8. 注意事项与安全要求
9. 成功标准与失败处理
10. 异常处理
11. 数据提交要求
12. 自检清单

规则：SOP 版本化；发布记录批准人/时间；任务执行时记录 `sop_version`；SOP 升版不改变历史任务记录；安全章节变化时当前任务必须暂停并重新确认。

## 5. 端到端流程与门禁

### 5.1 全链路

```mermaid
flowchart LR
  R[数据需求<br/>版本/审批] --> P[采集方案<br/>场景/动作/视角/设备/参数/SOP]
  P --> T[采集任务<br/>审批/分配/排期]
  T --> B[采集批次<br/>领取/执行]
  B --> W[现场工作台<br/>开工检查/采集/异常]
  W --> U[上传<br/>分片/续传/幂等/校验]
  U --> A[RawAsset<br/>登记/隔离]
  A --> J[接入 Job<br/>解析/完整性/标定校验]
  J --> E[Episode<br/>切片/关联/质量状态]
  E --> D[看板<br/>最小口径]
```

### 5.2 步骤、输入输出与门禁

| 步骤 | 输入 | 输出 | 门禁 | 责任角色 | 失败处理 |
|---|---|---|---|---|---|
| S1 需求 | 业务目标、场景/动作、数据量、质量、交付、验收标准 | 已批准需求版本 | G1：必填完整、验收标准可检查、非创建人审批 | PM 创建，PO 审批 | 驳回回 DRAFT，填原因，生成新版本 |
| S2 方案/SOP | 需求版本、场景/动作库、设备能力、安全要求 | 已批准方案与已发布 SOP | G2：方案要素完整、SOP 章节完整、设备能力匹配、非创建人审批 | CM 编写，PO 审批 | 驳回逐项修正；未发布版本不得被任务引用 |
| S3 任务/批次 | 方案/SOP 版本、人员/设备/位置、排期 | 已审批任务与批次 | G3：审批通过、资源可用、无冲突、未超目标 | CM 创建/分配，PO/PM 审批 | 冲突提示对象与时段；资源不可用阻断分配 |
| S4 开工 | 任务、SOP、设备/传感器、标定、时间、存储、场景 | 开工检查记录 | G4：所有阻塞项 PASS；UNKNOWN 不得默认通过 | CL 执行 | 失败禁止开始，给出原因与处理建议 |
| S5 采集/异常 | 任务、SOP、设备状态 | 采集记录、异常记录 | 无（执行中持续校验） | CL | BLOCKER 自动暂停/阻塞；安全事件立即停止并上报 |
| S6 上传 | 采集文件、任务/批次、幂等键 | 上传会话、RawAsset（待校验） | G5：分片完整、服务端校验通过、Hash 一致 | CL | 失败分片重试；Hash 不符整体重传；会话过期新建/恢复 |
| S7 接入 | VALID RawAsset、Pipeline/Parser 版本、切片规则 | IngestionJob、Episode | G6：格式/完整性/时间/标定通过；失败进隔离区 | DE/系统 | Job 记录错误码/摘要/重试；隔离资产不可训练 |
| S8 Episode 基础质量 | Episode、标定快照、时间同步、关键字段 | 质量状态、Episode 可用性 | G7：基础质量门禁通过；未跑质检标 Partial | QI/DE | 不合格拒绝/返工；Episode 可 INVALIDATED，不删除 |
| S9 提交/检查 | 上传、自检、批次状态 | 任务 SUBMITTED/DATA_CHECKING | G8：所有非取消批次已提交、上传校验通过、自检完成 | CL 提交，QI 检查 | 驳回生成返工要求；返工后复检 |
| S10 完成 | Episode 验收、异常关闭、目标达成 | 任务 COMPLETED | G9：Episode 验收达标、异常关闭、目标达成或 PO 特批 | CM 完成，PO 例外批准 | 未达标不得完成；例外必须审计 |
| S11 看板 | 业务表、对象存储清单 | 指标快照 | G10：口径版本、时间范围、来源、缺失语义齐全 | CM/DE/QI | 缺失显示 Unknown/Partial/N/A，不显示 0 |

### 5.3 全链路追溯要求

必须支持正向与反向追溯：

```text
需求版本 → 方案版本 → SOP/动作版本 → 任务 → 批次
→ 上传会话 → RawAsset → IngestionJob → Episode
→ 标定快照 → 设备/传感器 → 人员 → 质量结论
```

任何一环缺失，阶段 2 不得判定为「全链路可追溯」。

### 7.2 十种页面状态定义

| 状态 | 定义 | 触发 | 必须展示 | 禁止 |

### 7.4 页面专项要求

#### P-06 数据需求

- 列表显示编号、标题、版本、状态、优先级、交付时间、关联任务数、达成度、更新时间。
- 版本切换必须清晰；已批准/已提交版本只读；编辑已批准需求时引导「创建新版本」。
- 达成度展示分子/分母/单位；缺失目标量显示 `Unknown`，不得显示 0。
- 空态区分「暂无需求」与「筛选无结果」；无权限显示 Forbidden，不显示需求标题。

#### P-07 采集方案

- 分区展示场景、动作、视角、设备/传感器、参数、标定、SOP、质量、安全。
- 发布前逐项校验，缺失项定位到字段；草稿可保存。
- 方案版本对比至少展示变更字段；已批准方案只读。
- 设备能力不匹配、标定要求无法满足时阻断发布，并指出具体设备/传感器。
- 未发布 SOP/动作不得被引用。

#### P-08 采集任务

- 列表显示任务编码、名称、场景/动作、状态、负责人、设备、计划时间、进度、异常数、更新时间。
- 详情 Tabs：概览 / 方案与 SOP / 设备与传感器 / 批次 / 数据与上传 / 异常 / 操作记录。
- 动作按钮基于服务端 `allowed_actions`；禁用必须说明原因。
- 分配冲突显示冲突对象与时段；不允许部分写入。
- 状态变化导致页面过期时显示 Conflict，保留当前输入，要求刷新。

#### P-09 现场工作台

- 步骤：任务确认 → 开工检查 → 采集 → 上传 → 自检提交。
- 首屏即任务、状态、SOP 版本、主操作；主操作路径不超过 3 次点击（不含检查项填写）。
- SOP 固定在侧栏/底部抽屉，可全屏；版本变化明确提示。
- 阻塞项（红）与警告项（黄）分开；阻塞项全部通过前禁止开始。
- 上传与采集并行，不阻塞现场主流程；「上传完成」与「服务端校验完成」必须区分。
- 返工要求置顶；异常上报不打断采集。
- 离线时只允许继续已开始任务与本地队列，不允许离线开始新任务、提交、审批。
- 错误提示四要素：发生了什么、可能原因、用户可以做什么、错误码/request_id。

#### P-10 上传工作台

- 队列状态：等待上传、校验文件、创建会话、上传中、已暂停、续传中、服务端校验中、已登记、隔离待处理、失败、已取消、重复文件。
- 显示总进度、单文件进度、速度、剩余时间；未知总量使用不确定进度。
- 支持暂停/继续/取消/重试；取消只取消上传，不删除本地文件。
- 刷新/重开页面后恢复队列；先向服务端确认会话与已传分片。
- 服务端校验完成前不得显示成功。

#### P-11 原始资产

- 列表显示资产 ID、来源任务/批次、格式、大小、Hash、状态、上传人、校验时间、隔离原因。
- 隔离区资产必须显式标识，不能显示为可训练数据。
- 下载需权限与审计；跨项目不可见。
- Hash、对象 Key、来源设备/人员可查。

#### P-12 接入 Job

- 显示 Job ID、类型、状态、输入资产、Pipeline/Parser 版本、尝试/最大重试、起止时间、错误码、摘要、日志入口。
- 失败不可「消失」；重试只对可重试错误开放；达到上限保持 FAILED。
- 隔离与失败必须区分：隔离是校验结论，失败是执行异常。

#### P-13 Episode

- 列表显示 Episode ID、任务/批次、设备/传感器、起止时长、质量状态、状态、切片规则版本、更新时间。
- 详情展示标定快照、时间语义、Manifest、血缘、质量问题。
- `READY` 不等于 `ACCEPTED`；无效 Episode 不得进入标注/数据集。
- 预览使用代理/抽帧/流式；加载失败有提示。

#### P-21 采集看板

- 每个指标显示名称、口径版本、统计范围、更新时间、来源、Owner、缺失语义。
- 支持项目、日期范围、场景/动作筛选；不支持跨项目聚合。
- 样例/Mock 数据必须显式标识并可排除。
- 分母为 0 显示 `N/A`；来源不可达显示 `Unknown`；部分缺失显示 `Partial`；过期显示 `Stale`。

| 采集数据 | 合成样例包：多相机视频/图像 + 机器人状态 + 时间戳 + 标定快照 | `[SYNTHETIC]`；RawAsset/Episode 带 `data_source=SYNTHETIC`；看板可过滤 | 上传、接入、切片、追溯链路 | 真实采集质量、真实场景覆盖、真实指标 |
| 弱网/断网 | 浏览器 DevTools、代理、网络限速/丢包注入 | 记录注入方式、时间、参数；验收报告标注 `[MOCK]` | 队列、续传、恢复路径 | 真实现场网络与终端表现 |
| 对象存储 | 本地 MinIO 等真实实现 | 标注环境 `local`，不标 Mock | 文件安全、Hash、不可变、下载审计 | 生产对象存储性能/成本 |
| 外部系统 | 阶段 2 不涉及标注/训练平台 | — | — | — |

### 8.2 禁止用 Mock 替代的内容

1. 权限、项目隔离、任务级数据范围、职责分离。
2. 文件类型/大小/签名/SHA256 校验、对象 Key 安全、下载审计。
3. 状态机、非法转换拒绝、审计日志、乐观锁/幂等。
4. 原始文件不可覆盖、Episode 版本化、隔离区不可训练。
5. 真实采集验收结论（AC-E2E-02）。
6. 指标真实值：样例数据不得进入真实看板分母；如需演示，必须使用样例开关并标注。

### 8.3 真实采集定义

同时满足以下条件才算「真实采集」：

1. 由真实机器人/设备/传感器在真实或用户认可的现场产生。
2. 有真实设备 ID、标定记录、采集人员、开始/结束时间、场景/动作。
3. 原始文件可追溯到任务/批次/上传会话，未被人工改写。
4. 通过上传校验、接入检查与 Episode 登记。
5. 验收报告包含设备、人员、时间、场景、文件 Hash 与证据路径。

不满足时，只能结论「样例包链路验收通过，真实采集验收 `NOT RUN`/`BLOCKED`」。

### 8.4 Mock 标注要求

- 页面：样例/Mock 数据旁显示徽标与说明，不得只靠颜色。
- 数据：RawAsset/Episode/任务记录带 `data_source`（`REAL`/`SYNTHETIC`/`MOCK_ADAPTER`）与来源说明。
- 指标：看板支持按 `data_source` 过滤，默认只统计 `REAL`；样例视图必须显式开启。
- 验收：每条使用 Mock 的 AC 标注 `[MOCK]` 或 `[SYNTHETIC]`，写明替代范围与未验证项。
- 报告：不得用「已通过」掩盖「仅样例通过」。
