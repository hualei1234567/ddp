## 1. 背景、目标与范围

### 1.1 产品定位

DDP 是面向具身智能行业的数据生产、治理、资产化与训练支撑平台，不是普通 CRUD 后台或单一文件上传工具。首期只收敛一条可验收的端到端主链路，避免 16 个领域模块同时开工导致长期不可验收（规范 §0.2、§1.3；计划 §1）。

### 1.2 主链路定义

```text
项目与权限基础
  → 机器/设备/传感器纳管与标定
  → 数据需求与采集方案
  → 采集任务下发与现场采集
  → 上传、接入校验与原始资产登记
  → Episode 切片与基础预览
  → 标注任务、标注工作台、审核与返工
  → 数据集构建、版本冻结、LeRobot 导出
  → 训练需求与交付引用
```

主链路的业务目标：**一份数据从设备登记到训练交付，全程可追溯、可复现、可授权、失败可定位**（规范 §1.1、§10.4、§25.1）。

### 1.3 本期范围

| 环节 | 本期纳入（P0） | 本期不做或后置 | 计划阶段 |
|---|---|---|---|

### 1.5 成功定义

本期主链路成功不是「页面能打开」，而是同时满足：

1. 5 个环节均有可执行、可审核的完整业务流程；
2. 一份真实或显式标注的样例数据可从设备登记追溯到训练交付；
3. 每一步失败都能定位到具体对象、Job、错误码与责任人；
4. 权限、项目隔离、审计、原始数据不可覆盖等安全底线通过独立测试；
5. 所有验收附真实命令、测试名、记录或截图，不以自述代替证据（规范 §22.3）。

### 1.6 术语

| 术语 | 含义 |
|---|---|
| RawAsset | 原始资产：上传后登记的文件或文件集合，含 Hash、大小、格式、来源、对象存储引用 |
| Episode | 一次可训练/可标注的数据片段，关联任务、设备、传感器、时间范围与状态 |
| Canonical | 统一实体、时间、坐标系、单位与 Schema 的标准化数据层 |
| 标签 Schema | 版本化的标注字段、类型、约束与取值定义，前端不得写死 |
| DatasetVersion | 数据集的一次冻结版本，含样本清单、划分、Manifest、Hash 与血缘 |
| 隔离区 | 校验不通过或不可解析文件的暂存区，不得进入可训练数据集 |
| Adapter | 外部设备、标注工具、训练平台或存储的适配接口；不支持能力必须返回 Unsupported |
| 最小质量门禁 | 上传完整性、Episode 有效性、时间同步偏差、必填标签缺失四项 |

### 2.1 角色清单

### 2.2 权限原则

1. **服务端强制**：所有权限由服务端 RBAC / Policy 判定，前端隐藏菜单或按钮仅用于体验，不构成权限控制（规范 §19.1）。
2. **项目范围**：平台角色 + 项目角色 + 资源授权；所有查询、更新、删除、下载、导出、搜索与缓存均校验 Project Scope，不信任客户端传入的 `project_id`（规范 §16.4）。
3. **默认拒绝、最小权限**：未显式授权的动作一律拒绝（规范 §19.2）。
4. **职责分离**：标注员不得审核自己的标注；采集员不得审批自己的任务；数据工程师不得单独批准数据集对外交付；冻结版本不可由同一人静默改回。
5. **高风险操作审批**：删除、停用、冻结、导出、下载、权限变更必须二次确认并写审计日志。
6. **审计不可篡改**：审计日志只追加，不允许业务角色删除（规范 §19.2）。

> 本文定义业务权限期望，不定义具体实现。最终权限矩阵由 System Architect 冻结，并在 `backend/app/core/security.py` / `permission_map.py` 单点维护（见 `docs/03` §1.2）。

### 2.4 权限验收要求

- 每个资源至少 1 条「允许角色成功」与 1 条「越权角色被拒绝」测试。
- 每个列表/详情/下载/导出至少 1 条跨项目隔离测试，期望不可见或返回 `403/404`，不得泄漏对象是否存在。
- 权限错误必须有稳定错误码与可读提示，不得显示空白页或静默失败。
- 前端菜单按角色授权，不得默认向所有用户展示全部功能（规范 §18.2）。
- 权限测试证据需包含测试名、请求角色、目标资源、期望状态码与实际结果。

## 3. 端到端流程与关键状态

### 3.1 主流程

```text
[阶段1] 项目创建 → 成员授权 → 设备登记 → 传感器登记 → 标定记录 → 设备可用
   ↓
[阶段2] 数据需求（版本） → 采集方案（引用 SOP） → 采集任务/批次
   → 人员/设备/场地分配 → 采集员领取 → 开工检查 → 现场采集
   → 异常记录 → 上传（分片/续传） → 提交自检
   → 接入校验 → 隔离或通过 → RawAsset 登记 → Episode 切片
   ↓
[阶段3] 标签 Schema → 标注任务 → 标注工作台 → 提交
   → 审核（通过/驳回） → 返工/仲裁 → 最小质检门禁
   ↓
[阶段4] 训练需求 → Episode 筛选 → 去重/划分 → 数据集质量报告
   → DatasetVersion 冻结 → LeRobot 导出 → 交付单 → 训练引用
```

任何一步失败都必须产生可查询的状态、错误码、错误摘要与责任人，不允许「失败即消失」。

### 3.2 采集任务状态机

以规范 §2.3 为基线，最终状态在需求冻结时由用户确认：

```text
DRAFT → PENDING_REVIEW → APPROVED → READY → ASSIGNED
→ IN_PROGRESS → SUBMITTED → DATA_CHECKING
→ ACCEPTED → COMPLETED

DATA_CHECKING → REJECTED → REWORK → SUBMITTED
IN_PROGRESS → PAUSED / BLOCKED / CANCELLED
```

业务规则：

- 仅 `DRAFT` 可编辑核心内容；已下发任务修改必须走变更记录。
- `IN_PROGRESS` 前必须完成开工检查与设备/人员分配。
- `PAUSED` 可恢复；`BLOCKED` 必须填写阻塞原因；`CANCELLED` 必须填写原因并审计。
- `SUBMITTED` 后进入数据检查；`REJECTED` 必须给出问题类型与返工要求。
- 前端不得直接修改状态字段，状态推进必须走服务端动作。

### 3.3 其他关键状态（建议基线，待 Architect 冻结）

| 对象 | 建议状态 | 说明 |
|---|---|---|
| 设备 | REGISTERED → AVAILABLE → RESERVED → IN_USE → MAINTENANCE / FAULT → RETIRED | `FAULT` 不可被分配；停用需审批 |
| 上传会话 | CREATED → UPLOADING → COMPLETED / ABORTED / EXPIRED | 过期后需重新发起，已传分片按策略保留 |
| 接入 Job | PENDING → RUNNING → SUCCEEDED / FAILED / QUARANTINED | 失败必须记录错误码与摘要 |
| Episode | CREATED → VALID / INVALID / QUARANTINED | 只有 VALID 可进入标注与数据集 |
| 标注任务 | DRAFT → ASSIGNED → IN_PROGRESS → SUBMITTED → REVIEWING → APPROVED / REJECTED → REWORK → APPROVED | 仲裁为 REVIEWING 的分支 |
| 数据集 | DRAFT → BUILDING → READY → FROZEN → ARCHIVED | `FROZEN` 后禁止修改 |
| 导出 Job | PENDING → RUNNING → SUCCEEDED / FAILED | Manifest 校验通过才算成功 |
| 训练需求 | DRAFT → SUBMITTED → APPROVED / REJECTED → DELIVERING → DELIVERED → ACCEPTED / REWORK | 变更生成新版本 |
| 交付单 | DRAFT → SUBMITTED → ACCEPTED / REJECTED → REWORK → ACCEPTED | 验收结论与意见必填 |

> 上述状态机为业务需求建议，最终状态名、转换与前置条件以 Architect 冻结的领域模型为准；未冻结前相关验收项标记 `未验证`。

### 3.4 状态通用规则

1. 所有状态变化必须记录：操作人、时间、原状态、新状态、原因、关联对象。
2. 非法状态转换必须拒绝并返回可读原因，不得静默忽略。
3. 状态字段以服务端为权威，前端不得本地推断或覆盖。
4. 终态对象默认不可编辑；需要修改时创建新版本或走审批。
5. 异步任务状态必须包含排队、执行、成功、失败、重试次数与取消（如支持）。

## 5. 可验证验收标准

### 5.1 验收规则与证据等级

- 每条验收标准使用 Given / When / Then 描述，必须可被第三方复现。
- 证据优先级：自动化测试 > 接口请求/响应 > 数据库/对象存储记录 > 审计日志 > 人工截图 > 口头说明。
- 人工截图只能作为辅助证据，不能单独证明权限、隔离、幂等、数据不可变等安全属性。
- 所有「当前状态」默认 `NOT RUN`；实现后由 QA 更新，未跑测试不得写通过（规范 §22.3）。
- 涉及 Mock 的验收必须显式标注 Mock 来源与替代范围，不得冒充真实业务验收（规范 §0.5）。

### 6.2 十种页面状态定义

规范 §18.3 要求每页覆盖 Loading、Empty、Error、Forbidden、Partial、Stale、Disabled、Pending、Success、Failed。业务语义如下：

| 状态 | 定义 | 触发条件 | 必须展示 | 禁止行为 |
|---|---|---|---|---|
| Loading | 首次加载或重新加载中 | 请求未返回 | 骨架屏/加载指示；可取消或超时提示 | 显示旧数据冒充新数据 |
| Empty | 请求成功但无数据 | 列表为空、筛选无结果 | 空态说明、清除筛选、创建入口（有权限时） | 显示 0 或错误 |
| Error | 请求失败且非权限原因 | 网络、5xx、解析失败 | 错误摘要、错误码、request_id、重试按钮 | 空白页、静默失败 |
| Forbidden | 无权限或跨项目访问 | 401/403/404 权限判定 | 无权限说明、返回入口、申请权限路径 | 泄漏对象名称/是否存在 |
| Partial | 部分数据或部分模块缺失 | 某传感器/某字段/某子查询失败 | 已完成部分、缺失范围、影响说明 | 用完整态掩盖缺失 |
| Stale | 数据超过更新周期未刷新 | 超过指标/缓存有效期 | 最后更新时间、刷新按钮、陈旧标识 | 当作实时数据展示 |
| Disabled | 操作暂不可用 | 状态不允许、依赖未满足、无权限 | 禁用原因（悬浮/说明） | 隐藏原因或点击无反馈 |
| Pending | 异步任务排队/执行中 | 上传、接入、切片、导出、审核锁 | 进度、阶段、预计时间、取消（如支持） | 阻塞整页或重复提交 |
| Success | 操作成功 | 创建/保存/提交/审核/导出成功 | 成功反馈、对象链接、下一步 | 仅弹窗无结果定位 |
| Failed | 异步任务失败或操作失败 | Job 失败、提交失败、导出失败 | 错误码、摘要、重试、联系入口 | 丢失失败记录 |

### 6.4 现场工作台专项要求

规范 §18.3、§4.5 对现场端有额外要求，验收时必须单独检查：

1. **低学习成本**：首屏即任务、SOP、开工检查与主操作；关键动作不超过 2 次点击。
2. **SOP 就近可见**：采集过程中可随时展开 SOP，不离开当前任务。
3. **开工检查**：设备、标定、场景、SOP 四项未通过时禁止开始，逐项说明原因。
4. **弱网恢复**：断网时明确提示；已录数据本地保留；恢复后可继续；不得重复上传。
5. **上传进度**：显示已传/总量、速度、剩余时间、当前文件；支持取消与重试。
6. **错误可理解**：使用业务语言说明「发生了什么、怎么办」，同时保留错误码供排障。
7. **提交前检查**：自检清单未完成不可提交；提交后显示待质检状态。
8. **返工入口**：驳回原因、问题类型与返工要求置顶展示。

> 弱网与离线方案尚未验证，相关验收 AC-COL-12 标记 `BLOCKED`，实现前需 Architect/UX 给出方案并由用户确认。

### 6.5 页面通用规则

- 所有页面必须有项目上下文、标题、面包屑、更新时间与状态。
- 列表必须有 Loading、Empty、Error；详情必须有 Forbidden 与 Not Found 区分。
- 无数据不得显示 0；未知显示 Unknown，不适用显示 N/A，过期显示 Stale，部分缺失显示 Partial。
- 破坏性操作必须二次确认，显示对象名称与影响范围；禁止只显示 ID。
- 长任务不得阻塞整页；必须有 Pending 状态与失败记录。
- 状态色、状态文案与图标由 UX 统一，不在各页面自行定义。
- 前端不得根据本地数据推断权威状态；以服务端返回为准。

## 7. 指标口径

### 7.1 通用规则

依据规范 §13.2：

1. 每个指标必须有名称、定义、公式、分子、分母、周期、来源、Owner 与质量状态。
2. 缺失数据不得显示为 0，必须区分 `0`、`N/A`、`Unknown`、`Stale`、`Partial`。

- 所有页面文案、状态与错误提示使用简体中文；技术术语可保留英文。
