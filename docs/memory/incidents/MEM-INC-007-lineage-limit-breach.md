### MEM-INC-007 | 血缘 limit 被投影边吃穿，返回条数超过上限

- **类型与状态**：`INC` | 状态：`ACTIVE`
- **版本与血缘**：当前版本 `v1.0` | 替代旧版 `无` | 生效时间 `2026-11-24`
- **适用范围**：项目 `DDP` | 环节 `Lineage/血缘查询` | 批次/资产 `全部血缘遍历` | 密级 `INTERNAL`
- **核心结论**：血缘查询 `limit=20` 实测返回 **22 条**。根因：遍历时**投影边不计入预算**，且预算耗尽只跳内层循环、外层继续下钻。**分页上限必须是硬边界，不能靠"大概会停"。**
- **关键依据与细节**：
  - 实测：`limit=20` → 22 条边
  - 两个泄漏点：
    1. 投影边（derived=true 的运行时投影）在计数之外
    2. 预算耗尽时 `continue` 跳的是内层，外层 loop 继续
  - 修复：把**剩余预算**传入下层；本层预算耗尽立即停止下钻（不是 continue）
  - 同类风险：任何"递归/多层遍历 + limit"都必须检查「每一层是否都受同一预算约束」
- **影响与后续动作**：
  - 递归遍历类接口必须写测试：断言行数 ≤ limit
  - 投影/派生数据必须与持久化数据共用同一预算池
  - 责任人：后端；**已完成**（PR #108）
