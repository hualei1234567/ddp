# DDP 测试、验收与交付规范

## 1. 验收门禁

| Gate | 内容 | 通过条件 |
|---|---|---|
| G0 需求 | 目标、范围、非目标、验收标准 | 无关键歧义 |
| G1 现状 | 定位已有实现、复用评估、影响分析 | 方案有代码证据 |
| G2 设计 | API、Schema、权限、异常和兼容方案 | 契约明确 |
| G3 实现 | 最小必要改动 | 变更范围受控 |
| G4 测试 | 单元、集成、回归和必要安全检查 | 真实执行并记录结果 |
| G5 交付 | 文档、PR、风险和回滚 | 可审查、可追溯 |

## 2. 测试证据

报告必须记录：
- 执行命令；
- 执行环境；
- 执行时间；
- 通过 / 失败数量；
- 失败用例和原因；
- 未执行的测试及原因。

不能只说“测试通过”，必须有可复核的命令和结果。

## 3. 关键场景

按模块选择适用场景：
- 正常流程；
- 空数据；
- 错误输入；
- 无权限；
- 网络中断；
- 重复请求；
- 超时；
- 部分失败；
- 大文件或边界数据；
- 版本兼容；
- 回滚或恢复。

## 4. 完成定义（Definition of Done）

- [ ] 需求范围实现；
- [ ] 未破坏现有关键功能；
- [ ] 适用测试真实执行；
- [ ] 关键回归通过；
- [ ] 权限和异常处理完成；
- [ ] 文档与代码一致；
- [ ] PR 信息完整；
- [ ] 遗留问题和风险明确；
- [ ] 用户验收完成（需要时）。

## 5. 发布限制

个人验证环境与生产环境必须区分。未经明确批准不得执行生产发布、数据清理、破坏性迁移或真实机器人控制。
