# DDP 项目基线与使用说明

## 1. 项目定位

DDP（Embodied Intelligence Data Platform）是面向具身智能数据业务的数据闭环平台，长期连接数据生产、数据治理、标注质检、数据资产、训练数据构建、模型训练与推理、设备管理、评测回流和经营交付。

## 2. 当前阶段

当前阶段：个人开发、测试和技术验证。

当前重点不是一次性建设完整企业系统，而是：
1. 保留并梳理现有系统；
2. 找出已实现能力和缺口；
3. 以 Hugging Face 公开第一人称数据集验证数据链路；
4. 逐步补齐数据治理、标注、质量和 Dataset 能力；
5. 在验证成熟后再扩展真实采集、模型和经营管理。

## 3. 项目决策基线

| 项目 | 当前基线 |
|---|---|
| 现有代码 | 必须保留，先审计再修改 |
| 研发模式 | 增量迭代，不推倒重来 |
| 代码托管 | GitHub |
| 开发环境 | VS Code + Claude Code CLI / Extension |
| Agent 协作 | General Owner + 6 个专业角色 |
| 数据源 | 当前优先 Hugging Face 公开第一人称数据 |
| 数据格式 | 根据数据源使用 LeRobot、视频、JSON、HDF5、ROS Bag、MCAP 等适配 |
| 架构形态 | 先沿用现有技术栈；没有证据不拆微服务 |
| 开源复用 | 优先官方 SDK 和成熟项目 |
| 真实机器人控制 | 未经授权不接入、不执行 |

## 4. 目标与现状必须分开

本文件包不预设当前仓库使用何种前端、后端、数据库、ORM、消息队列或对象存储。所有技术选型以仓库审计为准。

目标模块不等于现有模块。审计报告必须为每项能力标注状态和证据。

## 5. 决策记录

重要技术或业务决策使用 `templates/ddp/ADR_TEMPLATE.md` 记录。决策被替代时保留历史记录并标记状态，不直接删除。

## 6. 项目边界

DDP 负责具身数据业务平台。多项目 Agent 管理平台负责代码项目、Agent 任务、Worktree 和研发执行管理。两者可集成，但 Agent 运行控制台不应混入 DDP 业务导航。
