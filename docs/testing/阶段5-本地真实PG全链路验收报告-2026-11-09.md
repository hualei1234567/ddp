## 4. 本轮发现并修复的缺陷

真实 PostgreSQL 会话时区为 `Asia/Shanghai` 时，从数据库读回的时间带有 `+08:00`，
而报告 Hash 在创建时以 UTC `+00:00` 计算，导致领域对象复算 Hash 不一致：

| 缺陷 | 影响 | 修复 |
|---|---|---|
| LeakageReport Hash 依赖时区 | `dataset_version validate` 抛“report_sha256 不一致” | `leakage._payload` 统一 `astimezone(UTC).isoformat()` |
| QualityReport Hash 依赖时区 | 同上，质量报告复算失败 | `quality._payload` 同样规范化 |
| Manifest Hash 依赖时区 | `validate` 返回 409 `dataset_manifest_mismatch` | `manifest._hash_payload` 同样规范化 |

回归测试：`tests/unit/test_dataset_domain.py::test_report_hashes_are_timezone_independent`
用同一时刻的 `+08:00` 与 `+00:00` 断言 Hash 一致。此缺陷在 staging（容器默认 UTC）未暴露，
属于真实环境差异，已记录为阶段 4/5 共同修复。
