## 5. 缺陷与风险

### 5.1 DDP-308-D01（CLOSED）

- **复测**：同一会话 2 分片上传完成后，用相同 `If-Match`、不同 `Idempotency-Key`
  并发提交两次 `POST .../complete`。
- **实测**：`[202, 409]`；202 方 `Idempotent-Replayed=false`，409 方
  `version_conflict`（`request_id=afcb78d3…`）；**无 503**。
- **资产**：该会话仅 1 个资产、1 条使用关系；Worker 后唯一资产 `VALID`。
- **结论**：DDP-308-D01 **CLOSED**。

### 5.2 DDP-308-D02（CLOSED）

- Episode / IngestionJob / 血缘 / 下载地址端点已挂载并通过真实 HTTP 验证；
- 成功路径、幂等重放、`If-Match` 428/409、未知动作/额外字段 422、viewer 403、
  外部用户 403、跨项目 404、随机 ID 404 均符合契约；
- 分页游标无重复，非法游标/状态 422；
- **结论**：DDP-308-D02 **CLOSED**。

### 5.3 DDP-311-D01（新发现，P2）

- **现象**：`download_requested` 审计记录 `request_id` 为空；上传、Episode、Job、
  校验审计均带 `request_id`。
- **定位**：`backend/app/api/v1/lineage.py` 的 `get_raw_asset_download_url` 未把
  `request.state.request_id` 传给 `use_cases.downloads.create_download_url(...)`；
  应用层 `downloads.py` 已支持 `request_id` 参数并写入审计。
- **影响**：无法按请求 ID 将“下载地址签发”与网关/访问日志关联；不影响 URL 短时、
  无明文、权限与资产可用性校验。
- **建议**：路由传入 `request_id=_request_id(request)`，补充真实 HTTP 断言
  `download_requested.request_id` 非空；由 Backend Engineer 修复，QA 复测。
- **状态**：OPEN（P2，非核心 AC，不阻断阶段 2 门禁；建议发布前修复）。
