## 2. 质量模型与完成定义

### 2.1 风险优先级

阶段 2 按以下顺序设门禁：

1. **原始数据不被覆盖、不被静默改写**：RawAsset 内容字段不可变；Episode `READY` 后冻结；
2. **跨项目不泄漏**：所有查询/写/下载/血缘带服务端 `project_id`；跨项目统一 404；
3. **上传不失控**：分片、Hash、签名、大小、断点、幂等、过期、并发全部可验证；
4. **状态机不越迁**：非法迁移 409；终态不回退；DB 触发器兜底；
5. **审计不缺失**：状态迁移、上传完成、下载、隔离放行、墓碑、Episode 失效均写审计/outbox；审计失败回滚业务；
6. **时间与切片可解释、可复现**：时间基准显式、同步状态显式、规则版本与配置 Hash 可复现；
7. **失败可定位、可恢复**：错误码稳定、`request_id` 可查、日志/Job 可追、重试有上限；
8. **契约不漂移**：OpenAPI、JSON Schema、状态机、错误码、对象 Key 正则一致。

### 2.2 五种完成状态

| 状态 | 含义 | 必需证据 | 谁可宣布 |
|---|---|---|---|
| Code Complete | 代码写完 | 分支、提交、PR | 开发 |
| Test Passed | 自动化测试通过 | CI run URL + job 日志 + 统计 | 开发/QA |
| QA Accepted | QA 独立验收通过 | 本文件 §8/§9 报告 + 证据归档 + 无开放 P0 | QA |
| User Accepted | 用户确认验收 | 平台交付记录/书面确认 | 用户 |
| Released | 已发布 | 发布记录、健康检查、观察窗口 | 用户批准后由发布执行人 |

**硬规则：** 上一状态不能自动推导下一状态；样例包可复现不等于阶段 2 Test Passed；CI 绿不等于 QA Accepted；用户未批准不得发布。

### 2.3 数据来源与测试替身标注

| 标记 | 定义 | 可用于 | 不可用于 |
|---|---|---|---|
| `[REAL]` | 真实设备、真实人员、真实现场、有效标定 | 真实采集验收 AC-E2E-02 | 用合成数据替代 |
| `[SYNTHETIC]` | 构造的样例包，记录生成器与 SHA256 | 上传、切片、权限、失败路径、E2E 预演 | 冒充真实采集 |
| `[MOCK]` | 网络/故障/外部服务注入或模拟 Adapter | 弱网、故障注入、契约路径 | 真实设备能力、真实心跳、真实故障 |
| `[T3]` | Fake/Stub/Mock Repository 或 Service | 单元、领域、应用层逻辑 | 集成、权限、文件安全验收 |
| `[SYNTHETIC_NEGATIVE]` | 损坏、非法、恶意样本 | 安全与失败路径 | 进入真实数据目录/生产桶 |
| `[MOCK_SPEC]` | 仅参数模板，不直接作为业务数据 | 网络注入、边界参数 | 作为真实请求/响应证据 |

规则：

1. 使用 `[SYNTHETIC]`/`[MOCK]` 的测试必须在用例名、文件头或报告“数据来源”字段显式标注；未标注即视为冒充真实业务验收，QA 判 FAIL。
2. 权限、跨项目隔离、文件安全、Hash、不可变、幂等、审计必须在**真实实现**上验证，不能用 Mock 替代。
3. 合成数据不得进入真实看板分母；看板默认 `data_source=REAL`，样例视图显式开启。
4. 网络注入必须记录工具、参数、时间、持续时长与结果。
5. 真实采集验收（AC-E2E-02）无真实环境时标 `BLOCKED`，不得用样例替代结论。

### 2.4 失败关闭原则

- 未知枚举、未知错误码、缺失时间基准、缺失标定、无法判定同步状态、扫描服务不可用：一律失败关闭或隔离，不得默认成功。
- `UNVERIFIED`/`FAILED` 的时间同步不得进入可训练数据集。
- `QUARANTINED`/`REJECTED`/`TOMBSTONED` 资产不得被 Job/Episode 使用。
- 审计/outbox 写入失败必须回滚业务事务。
- 不能把“页面显示成功”当作业务成功；必须核对资产状态、对象、Hash、审计。

| 正面相机 | `cameras/cam_front.mp4` | RGB，10 Hz，600 帧，60 s | 上传、签名探测、流登记 |
| 腕部相机 | `cameras/cam_wrist.mp4` | RGB，10 Hz，600 帧，60 s | 多相机、时间对齐 |
| 机器人状态 | `robot/robot_state.csv` | 10 Hz，600 行，含 6 关节/末端位姿/夹爪 | 状态完整性、采样率、切片 |
| 语言指令 | `metadata/language_instructions.json` | 2 条，带时间范围 | 元数据，不替代审核标签 |
| 标定 | `metadata/calibration_snapshot.json` | 有效 ACTIVE，内参/外参 | Episode 标定快照 |
| Manifest | `metadata/episode_manifest_synthetic.json` | 3 流、时间基准、provenance | Manifest Schema/切片 |

**断言：**

1. 3 个流全部登记，`stream_id` 唯一，`sensor_id` 同项目；
2. `frame_count`、`sample_rate_hz`、`time_range` 与 Manifest 一致；
3. 缺一路相机或缺夹爪时必须失败/隔离，不得按“流数量大于 0”放行；
4. MP4 为 `SYNTHETIC_CONTAINER_ONLY`，只验证签名与元数据，不验证真实 H.264 解码；真实解码验收需 `[REAL]`/T1 样例，当前 `BLOCKED`。

### 5.2 文件类型、损坏、超大、路径穿越与 ZIP

| 场景 | 样本/参数 | 期望 | 关键断言 |
|---|---|---|---|
| 空文件 | `negative/empty.mp4` | 422/413 | 不登记资产；会话失败原因可查 |
| 截断容器 | `negative/truncated_cam_front.mp4` | 解析失败 | 不得按扩展名放行 |
| 扩展名欺骗 | `negative/text_as_mp4.mp4` | `422 file_signature_mismatch` | 内容签名优先 |
| 未知格式 | `negative/unknown.bin` | `415`/隔离 | 不伪造解析成功 |
| 非法 JSON | `negative/corrupt_manifest.json` | `422 manifest_schema_invalid` | 不生成 READY Episode |
| 畸形 CSV | `negative/malformed_state.csv` | 隔离/返工 | 缺列、NaN、非数值被检出 |
| ZIP 路径穿越 | `negative/zip_path_traversal.zip` | 拒绝/安全重命名 | 目标目录无越界文件 |
| 嵌套 ZIP | `negative/zip_nested.zip` | 深度超限拒绝/隔离 | 不递归爆炸；非压缩炸弹 |
| 恶意文件名 | `metadata/filename_cases.json` | 逐条拒绝/清洗 | 对象 Key 不含原文件名 |
| 超大文件 | `--with-large --large-mib 16` | 413/分片策略 | 不进入仓库固定清单；单独记录 Hash |
| ZIP 炸弹 | 不生成实际炸弹 | 受控参数 + 隔离环境 | 仅记录生成参数与拒绝证据 |

**边界说明：**

- 不生成真实 ZIP 炸弹，避免仓库与测试环境风险；用嵌套 ZIP 与大小/压缩比参数验证深度和压缩比门禁。
- 恶意样本只允许在隔离目录/隔离环境使用；不得进入真实数据目录、生产桶或常规 fixture 上传链路。
- 所有拒绝必须返回稳定错误码、`request_id`、审计记录；不得“失败即消失”。

### 5.3 断点续传、重复上传与并发完成

| 场景 | 步骤 | 期望 |
|---|---|---|
| 断点续传 | 上传 1、3；`GET` 会话；补 2；`complete` | 已确认分片不重传；最终 SHA256 一致；`202` |
| 重复 ack 同内容 | 同分片同 ETag/大小/Hash 两次 | 幂等；分片表一行 |
| 重复 ack 不同内容 | 同分片不同 Hash | `409 upload_part_conflict`；原记录不变 |
| 重复上传同内容 | 同项目同 `sha256+size` | `deduplicated=true`；不新增可用资产 |
| 跨项目同内容 | A/B 各上传一次 | 不去重；两个资产；互不可见 |
| 并发 `complete` | 两个请求同时 | 仅一个成功；另一个幂等或 `409 version_conflict`；无重复可用资产 |
| 过期会话 | `now >= expires_at` | `410 upload_session_expired`；新建会话可恢复 |
| 中止幂等 | `abort` 两次 | 返回当前状态；不重复删除对象 |

**关键断言：**

1. `raw_assets (project_id, sha256, size_bytes)` 的部分唯一索引只对可用状态生效；
2. 竞争失败方读取既有资产并标记 `duplicate_of_asset_id`，不得产生第二个可用资产；
3. `ListParts` 是完成时的权威来源；本地 `upload_parts` 与 `ListParts` 不一致时以 `ListParts` 为准并写审计；
4. 失败分片必须有 `failure_code`、`failure_summary`、`request_id`；可重试与不可重试必须区分。

### 5.4 时间同步

**依据：** Canonical 草案 §3.1–§3.3、阶段 2 契约 §8.2、阶段 2 验收标准 AC-ING-05/AC-PLN-04。

**必须显式：**

- `time_domain`：Canonical 统一时间线为 `UTC`；
- `clock_source`、`sync_method`、`sync_ref`；
- `sync_status`：`VERIFIED`、`DEGRADED`、`UNVERIFIED`、`FAILED`；
- `offset_ns`、`drift_ppm`、`uncertainty_ns`、`residual_ns`、`sample_count`；
- 每个观测保留 `source_time_ns`、`source_time_domain`、`clock_id`、`time_base_ref`。

**验收口径：**

1. `UNVERIFIED`/`FAILED` 不得进入可训练数据集；Episode 必须阻断或 `INVALIDATED`；
2. 无法估计同步关系时不得伪造 `offset_ns=0`，必须保留原因；
3. 对齐后流内时间非递减；重复时间戳标记 `DUPLICATE` 并进入质检；
4. 采样率默认阈值 ±5%（Canonical 草案），但必须按项目配置；测试在 5% 与 6% 两点验证边界；
5. **具体时间偏差阈值（如 2 s 是否超限）尚未冻结**：测试必须从项目配置读取，不得硬编码；未配置时标 `BLOCKED`，不得断言 PASS；
6. 样例提供 0/100 µs/10 ms/+2 s/UNVERIFIED/FAILED/重复/倒退梯度，见 `metadata/time_alignment_cases.json`。

### 5.5 Episode 边界、切片可复现与不可变

| 场景 | 期望 |
|---|---|
| `start=end` | `422 episode_time_range_invalid` |
| `end<start` | `422 episode_time_range_invalid` |
| 超出资产范围 | `422 episode_time_range_invalid` |
| 跨资产缺失时间 | `422`；不得跨缺口切片 |
| 最短非零区间 | 若在资产范围内则允许 |
| 正好等于资产范围 | 允许 |
| 64 个资产 | 允许 |
| 65 个资产 | `422 validation_failed` |
| 重叠且 `allow_overlap=false` | `409 episode_overlap_conflict` |
| 重叠且 `allow_overlap=true` | 允许；DE/QI；记录原因/审批人/审计 |
| 同输入+规则版本+配置 Hash | 边界完全一致，可重放 |
| `READY` 后 PATCH 数据字段 | `409 resource_immutable`；Manifest Hash 不变 |
| 修订 | 新 `episode_id`、`episode_version+1`、`supersedes_id`；旧版不变 |
| 原始资产墓碑 | 非终态 Episode `INVALIDATED`；追加失效边；已 `ARCHIVED` 标记 `quality_status=FAIL` |

**不可变字段：** `start/end/duration`、`time_base`、`calibration_snapshot`、`manifest_key/manifest_sha256`、`pipeline/rule` 版本、`raw_asset_ids`。`READY` 起冻结；`ACCEPTED` 起额外冻结质量结论。

### 5.6 跨项目与权限

**必测路径：**

1. 项目 A 用户访问项目 B 列表：不返回任何条数、标题、状态、文件名；
2. 详情/下载/血缘：统一 `404 resource_not_found`；不得用 403 暴露存在性；
3. 非项目成员访问项目路由：按冻结契约 `403 project_scope_denied`；
4. 项目 A 路由下访问项目 B 资源 ID：`404`；
5. 同 SHA 跨项目：不去重，两个资产；
6. 跨项目 `task_id`/`batch_id`/`target_id`：复合外键/触发器拒绝；
7. 隔离放行/墓碑/Episode 失效：双人审批，提案人 ≠ 批准人；PA break-glass 强审计；
8. 下载/预览/日志签名：短期 URL；记录操作者、项目、资源、用途、结果、`request_id`。

**禁止：** 前端隐藏按钮代替服务端校验；缓存 Key 缺少 `project_id`；对象 Key 由客户端控制；错误详情泄露跨项目 ID。

### 5.7 弱网与失败恢复

**契约承诺边界：**

- 阶段 2 只承诺：分片可乱序、可重试、可断点续传；`complete` 幂等；会话过期可新建恢复。
- 不承诺：本地离线队列、IndexedDB/文件系统暂存、冲突合并、离线开始新任务/提交/审批。
- 因此 `AC-COL-12`、`AC-WKB-12`、`AC-UPL-13`、`AC-E2E-04` 在弱网方案未验证前保持 `BLOCKED`，不得标 PASS。

**弱网 profile：** 见 `metadata/network_profiles.json`，包括延迟 100 ms/1000 ms、丢包 5%/20%、带宽 1 Mbps、断网 30 s、1% 损坏/重复/乱序。

**验收断言：**

1. 已确认且 ETag/大小/Hash 一致的分片不重传；
2. 重试有指数退避与上限；不可重试错误不进入无限重试；
3. 最终对象 SHA256 与声明一致；对象大小一致；
4. 同项目同内容不产生重复可用资产；
5. 每个失败分片/请求有 `failure_code`、`request_id`、审计；
6. 会话过期 `410` 后新建会话可恢复；不得静默丢文件；
7. 页面覆盖 Loading/Empty/Error/Forbidden/Partial/Stale/Disabled；离线横幅、进度、恢复提示可见；
8. 网络注入必须记录工具、参数、时长、结果，标 `[MOCK]`。

### 5.8 审计、outbox、血缘与不可变

| 检查 | 期望 |
|---|---|
| 状态迁移审计 | 操作者、项目、资源、前后状态、`request_id`、时间、结果 |
| 上传完成/中止审计 | 会话、资产、分片数、Hash、结果 |
| 下载/预览/日志签名审计 | 操作者、项目、资源、用途、结果 |
| 隔离放行/墓碑/Episode 失效审计 | 提案/批准人、原因、证据、双人 |
| 跨项目/权限拒绝审计 | 拒绝原因、`request_id`，不泄露存在性 |
| outbox 失败 | 业务事务回滚；状态不变 |
| 血缘只追加 | UPDATE/DELETE 被拒；纠错追加新边 |
| 血缘成环 | 拒绝（`SUPERSEDES` 除外且线性） |
| 跨项目边 | DB 触发器/复合外键拒绝 |

### 5.9 数据质量与 Canonical

- 必填字段缺失、未知枚举、NaN/Infinity、超长 JSON、超深嵌套：失败关闭；
- 单位/坐标系/标定引用显式；禁止隐式默认；
- `captured_at`、`ingested_at`、`processed_at` 分开，不得互相替代；
- 四元数归一化容差 `1e-6`；帧名全局唯一；
- Manifest 中所有引用同项目；`manifest_sha256` 服务端计算，客户端提交忽略；
- 原始文件 Hash 前后不变；产物独立存放；Episode 修订不覆盖旧版。

## 7. 失败与弱网验收口径

### 7.1 通用失败判定

一条失败场景只有在同时满足以下条件时才可判 PASS：

1. 可稳定复现；
2. 返回契约声明的 HTTP 状态码与稳定错误码；
3. 错误体含 `code`、`message`、`request_id`；字段级错误在 `details`；
4. 业务状态不变或进入契约声明的失败/隔离状态，不得“部分写入”；
5. 原始数据、既有资产、既有 Episode 不被覆盖；
6. 审计记录写入成功；若审计失败，业务事务回滚；
7. 不产生可用资产/可训练 Episode（当场景要求拒绝时）；
8. 失败原因、Job 日志、对象 Key（适用时）可定位；
9. 重试语义正确：可重试错误可恢复，不可重试错误不无限重试。

任一条件不满足即 FAIL；无法执行即 `NOT RUN`/`BLOCKED`，不得用“应该可以”代替。

### 7.2 可重试与不可重试

| 类别 | 示例 | 验收 |
|---|---|---|
| 可重试 | 网络中断、分片 5xx、`upload_incomplete`、`size_mismatch`（修正后）、对象存储临时不可用、`job_timeout` | 退避 + 上限；恢复后最终 Hash 一致；无重复资产 |
| 不可重试 | `file_signature_mismatch`、`malware_detected`、`file_type_unsupported`、跨项目/权限拒绝、会话过期、`hash_mismatch` | 立即失败；不得无限重试；不得登记可用资产 |

### 7.3 弱网验收表

| Profile | 注入 | PASS 条件 | 不得判定为 PASS |
|---|---|---|---|
| NET-DELAY-100MS | 100 ms 延迟 | 最终 Hash 一致；进度可见 | 因超时直接失败且无错误记录 |
| NET-DELAY-1000MS | 1 s 延迟 | 不超时；断点可恢复 | 页面伪造 100% 或静默卡死 |
| NET-LOSS-5 | 5% 丢包 | 失败分片重试；无重复资产 | 无限重试、重复资产 |
| NET-LOSS-20 | 20% 丢包 | 有上限；明确失败或恢复 | 静默失败、无 `failure_code` |
| NET-BW-1M | 1 Mbps | 进度按字节；未知总量不伪造百分比 | 假进度、前端卡死 |
| NET-DISCONNECT-30S | 断网 30 s | 已确认分片不重传；恢复续传 | 丢失已传分片、重复资产 |
| NET-CORRUPT-1 | 1% 损坏 | Hash/校验失败被发现；不登记可用资产 | 损坏文件被标 VALID |
| NET-DUPLICATE-1 | 1% 重复 | 分片 ack 幂等 | 分片记录重复/资产重复 |
| NET-REORDER-1 | 1% 乱序 | 乱序分片可完成；无损坏 | 以乱序为由丢弃文件 |

**弱网方案未定项：** 本地离线队列、草稿持久化、离线审批、冲突合并 → `BLOCKED`，不得以“分片续传通过”替代。

### 7.4 断点/重复/并发验收

- 断点：`GET` 会话返回 `uploaded_parts` 与 `missing_part_numbers`；补传后 `complete` 成功；已确认分片不重传。
- 重复：同项目同 `sha256+size` 只保留一个可用资产；`deduplicated=true`；使用关系不重复。
- 并发：两个 `complete` 仅一个成功；另一个返回首次结果或 `409 version_conflict`；唯一索引无竞争泄漏。
- 过期：`410`；旧会话终态；新会话可完成；对象按生命周期清理，不承诺保留。

### 7.5 时间同步验收

- `sync_status` 必须显式；缺失即 `422 time_base_invalid`；
- `UNVERIFIED`/`FAILED` 阻断 Episode/训练数据集；
- 偏移超过项目冻结阈值 → 阻断/隔离；阈值未冻结 → `BLOCKED`；
- 采样率偏差超过项目阈值（默认 ±5%）→ WARN/FAIL；不得默认成功；
- 重复/倒退时间戳 → 质检失败；不得静默去重/排序后放行；
- 不得伪造 `offset_ns=0`。

### 7.6 Episode 边界验收

- 非法范围：`422 episode_time_range_invalid`；字段级 details；
- 重叠：`409 episode_overlap_conflict`；允许重叠必须有 DE/QI、`allow_overlap=true`、原因、审计；
- 资产数量：1–64；65 → `422 validation_failed`；
- 规则复现：同输入+规则版本+配置 Hash → 相同边界；
- `READY` 不可变：PATCH 数据字段 → `409 resource_immutable`；Manifest Hash 不变；
- 修订：新 ID、版本+1、`supersedes_id`；旧版不变；
- 失效：非终态 Episode `INVALIDATED`；追加失效边；不删除历史。

### 7.7 不得判定为通过的情形

- 只有页面截图，没有接口/DB/对象/审计证据证明权限、隔离、幂等、不可变；
- 只跑合成样例，却写“真实采集验收通过”；
- 测试被跳过、断言被放宽、失败用例被删除；
- 失败被标“已知问题”但没有 Owner、期限与用户批准；
- 原始文件被覆盖、Episode 被静默改写、审计缺失；
- 弱网方案未验证却宣称现场可用；
- 时间同步阈值未冻结却断言具体通过/失败；
- 迁移只测 SQLite 就宣称 PostgreSQL 通过。

### 9.3 状态口径

| 状态 | 定义 |
|---|---|
| PASS | 本次实际执行，退出码 0，断言全部通过，证据完整 |
| FAIL | 本次实际执行，断言失败或退出码非 0 |
| PARTIAL | 部分子项通过，逐项列明 |
| NOT RUN | 未执行；或只有历史记录未复跑；或被测对象未实现 |
| BLOCKED | 环境、设备、权限、凭据、决策或方案限制；记录原因、责任人、解除条件 |

补充规则：

- 不使用 `SKIP` 作为最终状态；pytest `skip/xfail` 逐条登记，汇总按 `NOT RUN` 计；
- 历史记录可作背景，本次未复跑不得标 PASS；
- Mock/合成样例通过只能证明逻辑/契约，不能作为真实集成/业务验收；
- 只跑部分用例不得声称全量通过；
- 截图、口头确认、“应该没问题”不构成有效证据；
- 失败不得通过放宽断言、删除用例、跳过门禁、降低扫描级别来“修复”。
