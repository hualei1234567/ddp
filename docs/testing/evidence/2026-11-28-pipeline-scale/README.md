# Pipeline 并发规模探测证据（T2-01/02 阶段 2）

## 任务背景

T2-01/02 要求对处理管线（processing pipeline）做规模化压测。全量 200 demos
的真实样本数据并不存在，因此本批交付的是**全量样本基准的最小化版本**：
用合成规模（每次迭代一个全新 `input_refs` 的 processing run）建立容量模型，
数字只对「并发创建 run 的写容量」这一维度成立，**不代表全量样本基准**。

`backend/tests/api/conftest.py` 的 `seed_identity` 身份基线、
`backend/tests/jwt_support.py` 的真实 HS256 JWT。

## 测什么、不测什么

**测**：并发创建 processing run（`POST /api/v1/projects/{project_id}/processing-runs`，
201，初始状态 `CREATED`）的吞吐与延迟——走真实 JWT 鉴权、项目成员校验、
乐观锁版本、审计行与 `processing.run.requested` outbox 事件落库。

**不测**：Worker 八阶段异步执行链（HTTP 线程创建完即返回）；标注写路径
（`write_path_e2e.py` 的职责）；跨进程横向扩容（单进程内并发，结论只对单实例成立）。

## 实测结果（真实数字，2026-11-28，PG @ localhost:55432，max_connections=100）

被测配置：连接池取**生产默认口径**（`pool_size=10` / `max_overflow=20`），
压测期间未放宽；限流在脚本内关闭。每档每 worker 25 次创建。

| 并发 | 请求数 | 墙钟(s) | TPS | p50 | p95 | p99 | 最大 | 错误 | 锁等待 | 死锁 |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 25 | 0.2153 | **116.11** | 7.3ms | 10.8ms | 32.9ms | 32.9ms | 0 | 0 | 0 |
| 4 | 100 | 0.2909 | **343.71** | 10.8ms | 12.6ms | 31.8ms | 33.8ms | 0 | 0 | 0 |
| 8 | 200 | 0.6854 | **291.78** | 22.4ms | 37.5ms | 140.4ms | 141.3ms | 0 | 0 | 0 |
| 16 | 400 | 1.2166 | **328.78** | 47.9ms | 56.2ms | 76.8ms | 88.4ms | 0 | 0 | 0 |

状态码分布：各档全部 `201`（创建成功），错误率 0%。

### 怎么读这组数

1. **TPS 在并发 4 达到峰值 343.71**，并发 8 出现回落（291.78）、并发 16
   又回到 328.78——单进程内并发 8 档的 p99（140ms）明显高于其他档，
   属于线程调度/GIL 争用的波动，而非数据库瓶颈（锁等待与死锁全程为 0）；
2. **四档错误率全部为 0，死锁 0、锁等待 0**：并发创建 run 的
   「插入 + 审计 + outbox 双写」在并发 1–16 下没有互相打架，
   一致性与锁安全是这次压测最有价值的结论；
3. **p95 全档 < 60ms**，创建路径（落一行 run + 一条 outbox 事件）本身很轻；
   真正的容量风险不在创建，而在 Worker 侧的八阶段执行（不在本次范围）。

## 连接池红线结论

| 项 | 值 |
|---|---|
| API 连接池口径 | pool_size=10 + max_overflow=20 → 单进程上限 30 |
| 实测连接峰值（50ms 采样，42 次） | **14**（并发 16 档） |
| 同实例其他连接 | 12 |
| 投影总占用 | 26 / 100 |
| 占用率 | **26%** |
| 余量 | 74 个连接 |
| **判定** | **safe（不会打满）** |

结论：**并发 16 的创建压力下连接池占用 26%，余量 74 个连接，不会触碰
PG `max_connections=100` 的边界**。采样为 50ms 间隔瞬时峰值，尖峰可能被漏掉，
但即便按 API 单进程理论上限 30 计算，占用率也仅 42%，结论稳健。

## 锁安全证据

- `pg_stat_database.deadlocks` 压测前后差值：**0**（累计计数器，不依赖采样）；
- `pg_stat_activity` 中 `wait_event_type='Lock'` 的连接数：**0**（各档末快照）；
- 错误样本中无 `deadlock detected` 文本。

## 诚实标注

- **合成规模，非全量样本**：全量 200 demos 数据不存在，本探测是 T2-01
  全量样本基准的最小化容量模型，数字不能直接外推为全量基准；
- 单进程并发，结论不覆盖多副本水平扩展；
- 临时库压测结束即删除，数据不落主库。
