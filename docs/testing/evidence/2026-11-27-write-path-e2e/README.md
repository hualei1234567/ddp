## 测什么、不测什么

**测**：真实 HTTP 写接口（`POST /api/v1/projects/{id}/annotation-submissions`
+ `.../actions/submit`）在并发下的吞吐、延迟分位、错误率，以及**连接池红线**。

**不测**：多副本水平扩展、对象存储大文件路径、非标注域的写路径。

每次迭代 = **2 次真实写请求**（建草稿 201 + 提交 200），走完整鉴权 → 校验 →
状态机 → 审计 → outbox → 血缘 → 进度投影 → 幂等记录链路。

---

## 实测结果（真实数字，2026-11-27，生产 PG @ 55432）

被测配置：连接池参数取**生产默认口径**（`pool_size=10` / `max_overflow=20`），
压测期间未放宽；限流在脚本内关闭（否则写请求会被 IP 桶挡掉，测到的不是
业务写容量）。

| 并发 | 请求数 | 墙钟(s) | TPS | p50 | p95 | p99 | 均值 | 最大 | 错误 | 错误率 |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 20 | 1.2523 | **15.97** | 42.9ms | 104.3ms | 132.0ms | 62.6ms | 132.0ms | 0 | **0%** |
| 4 | 80 | 3.0240 | **26.46** | 148.1ms | 256.0ms | 281.5ms | 147.9ms | 281.5ms | 0 | **0%** |
| 16 | 220 | 8.8887 | **24.75** | 551.1ms | 1036.7ms | 1366.7ms | 625.4ms | 1509.3ms | 0 | **0%** |

状态码分布（各档）：`201` 与 `200` 各占一半（建草稿 / 提交），
与「每次迭代 2 个请求」的口径一致。

### 怎么读这组数

1. **TPS 在并发 4 达到峰值 26.46**，并发 16 反而略降到 24.75 ——
   单进程下并发越高争用越明显（p50 从 148ms 涨到 551ms），说明
   **瓶颈在单进程串行段与数据库写争用**，不是纯排队；
2. **三档错误率都是 0** —— 领域规则、唯一键、幂等在并发下没有互相打架
   （这是这次压测最有价值的结论：并发写没有破坏一致性）；
3. **p95 在并发 16 达 1.04s**，若 SLO 定在 p95 < 500ms，则**当前单进程
   写容量上限在并发 4–8 之间**。

## 连接池红线结论

实测（`pg_stat_activity`，50ms 间隔采样）：

| 项 | 值 |
|---|---|
| PG `max_connections` | 100 |
| 压测期间实例连接数峰值 | **17** |
| 压测期间本库连接数 | 11 |
| 按状态 | active 1 / idle 10 |
| 按等待事件 | Client 10 / CPU 1 |
| API 侧单进程连接上限（`pool_size` + `max_overflow`） | 30 |
| 其他连接（演练自身的连接） | 9 |
| **投影总连接** | **26** |
| **占用率** | **26.0%** |
| **余量** | **74 个连接** |

**判定：安全**（不会打满）。

原文结论：

> 不会打满：占用率 26.0%（26/100），余量 74 个连接；API 侧单进程连接上限为 30

> **口径提醒**：连接峰值是 50ms 间隔的**瞬时采样最大值**，尖峰可能被漏掉。
> 本结论适用于**单进程**部署；多副本部署时每副本各占一个连接池，
> 副本数 × 30 需要重新计算。

## 与阶段 4 事务骨架压测的关系

| 维度 | `write_path_probe.py`（阶段 4） | `write_path_e2e.py`（本批） |
|---|---|---|
| 写入方式 | 直接 `INSERT` | 真实 HTTP POST |
| 鉴权 | 无 | 真实 HS256 Bearer JWT |
| 业务校验 | 无 | 完整校验链 |
| 附带写入 | 审计 + outbox | 审计 + outbox + 血缘 + 进度 + 幂等 |
| TPS（可比口径） | 698 → 2548 | 16 → 26（**HTTP 全链路**） |

两者数字不可直接比较：阶段 4 测的是**纯数据库写入能力**（无 HTTP/鉴权/校验
开销），本批测的是**端到端用户可见容量**。阶段 4 的数字是本批的**上界**。

## 安全护栏（硬编码，不可绕过）

1. 只允许本机回环 PG（`ensure_safe_base_dsn`，非 loopback 直接拒绝）；
2. 临时库名必须带 `ddp_perf_e2e_` 前缀（`ensure_safe_perf_db_name`），
   结束后 `DROP DATABASE`；
3. 默认 dry-run，必须显式 `--execute`；
4. **不写主库**：全部数据只落在一次性临时库。

实测确认：演练结束后临时库已删除，主库 `ddp` 未被写入。

---

## 已知边界（如实标注）

| 项 | 状态 | 说明 |
|---|---|---|
| 单进程口径 | `VERIFIED` | 多副本部署需按「副本数 × 30 连接上限」重算红线 |
| 迭代次数较少 | `PARTIAL` | 每 worker 10 次迭代（总 220 请求）——足以看延迟分位与错误率，不足以做长稳态（数小时）压测 |
| 未覆盖对象存储路径 | `MISSING` | 涉及大文件上传/导出的写路径未纳入 |
| 连接采样可能漏尖峰 | `VERIFIED`（口径已注明） | 50ms 间隔瞬时采样 |

  --dsn postgresql+psycopg://ddp:ddp@localhost:55432/postgres \
