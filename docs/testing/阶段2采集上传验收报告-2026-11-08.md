## 5. 缺陷与风险

### 5.1 缺陷

#### DDP-308-D01（P0）并发 complete 失败方返回 503

- **复现**：同一上传会话所有分片确认后，用相同 `If-Match` 版本并发提交两次 `POST .../complete`。
- **实测**：一个 202 COMPLETED；另一个 503 `object_storage_unavailable`（`request_id=afdb9a31…`）。S3 替身记录 `ERROR NoSuchUpload status=404 ...?uploadId=...`。
- **根因**：`UploadCompletionService.complete` 先调用 `list_parts`；赢家完成 multipart 后，输家的 `ListParts` 收到 S3 `NoSuchUpload`，`S3MultipartStorage.list_parts` 将其收敛为 `ObjectStorageUnavailableError`，API 映射为 503，未按“已完成/版本冲突”处理。
- **契约期望**：仅一个成功；另一个返回首次结果（幂等）或 `409 version_conflict`，且不产生第二个可用资产。
- **实际资产**：本次仅 1 个可用资产（未重复登记），但错误码/状态码不符合契约。
- **责任角色**：Backend Engineer（上传完成事务）；QA 复测。
- **状态**：OPEN，阻断阶段 2 上线门禁。

#### DDP-308-D02（P0/P1）Episode/IngestionJob/血缘/下载 HTTP API 未挂载

- **现象**：`backend/app/api/v1/router.py` 仅挂载 platform/devices/sensors/calibrations/collection/uploads；`backend/app/api/v1/` 无 `episodes.py`、`ingestion_jobs.py`、`lineage.py`。
- **契约要求**：附件 B §9.3 的 `/episodes`、`/episodes/{id}/manifest`、`/episodes/{id}/lineage`、`/ingestion-jobs`、`/raw-assets/{asset_id}/download-url` 等端点。
- **影响**：本次 Episode READY/Manifest/修订/质检/血缘结论仅来自真实 PG 上的应用层/仓储/DB 触发器，不能视为 HTTP API 验收；前端/调用方无法按契约使用。
- **责任角色**：Backend Engineer / System Architect（若确认阶段性裁剪，需书面范围说明）。
- **状态**：OPEN；至少阻断 Episode HTTP AC 与阶段 2 上线门禁。

## 6. 是否允许进入下一阶段

### 6.1 结论

**不允许。** 本次结论为 **QA 独立验收不通过（Not QA Accepted）**，不得作为阶段 2 上线门禁通过。

理由：

1. `DDP-308-D01` 为 P0 契约违背：并发 `complete` 失败方返回 503，而不是幂等/409。
2. `DDP-308-D02`：Episode/IngestionJob/血缘/下载 HTTP API 未实现，Episode 无法通过契约端点验收。
3. MinIO 与 s3rver 均不可得，对象存储真实集成仍有 `BLOCKED` 项。

### 6.2 复测准入条件

1. 修复 D01；复测 `API-UPL-06`，要求结果为 `[202, 409]` 或 `[202, 202（replayed=true）]`，且同内容仅 1 个可用资产；
2. 实现 D02，或由 Product/Architect 书面确认阶段裁剪范围并更新契约/验收标准；若裁剪，Episode 结论仍需在真实 PG 上复跑应用层/DB 探针；
