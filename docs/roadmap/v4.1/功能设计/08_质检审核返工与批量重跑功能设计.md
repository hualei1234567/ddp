# 08｜质检、审核、返工与批量重跑功能设计

## 1. 现状
QC Run 生命周期、Submission 后 Outbox→Worker、幂等、CAS、死信和结论路由已 VERIFIED。批量重跑与差异报告后端 VERIFIED，但前端入口未完成。

## 2. 自动质检流程
Submission 成功 → Audit/Outbox → QC Worker → 执行绑定 RuleSet Version → 逐条生成 PASS/WARN/FAIL 和证据 → 汇总结论 → 按现有路由转审核或返工。重复事件不能重复创建相同 QC Run。

## 3. QC 详情
展示 QC Run/Submission/RuleSet 版本、每条规则结果、severity、field path、timestamp range/segment、expected/actual、evidence、remediation hint、执行时间、retry count。

## 4. 批量重跑前端操作
在现有质量/审核页面：
1. 按项目、Schema、RuleSet、时间、QC 状态筛选；
2. 选择 QC Run / Submission；
3. 点击批量重跑；
4. 预览样本数、规则版本、预计任务数和影响；
5. 用户确认；
6. 创建 Batch Rerun Job；
7. 展示排队、执行、成功、失败、取消；
8. 查看差异报告；
9. 只重试失败项。

批量操作必须幂等。规则版本变化时明确选择“按原版本重跑”或“按当前版本重跑”，不能混用。

## 5. 差异报告
按样本/规则展示原结论、新结论、新增问题、已消除问题、仍存在问题、规则版本变化、重跑失败和受影响 Dataset 候选项。不能修改已冻结 DatasetVersion。

## 6. 审核和返工
审核详情同页展示媒体证据、标注结果、三级语义、OUTCOME_SPAN、QC 和历史版本。动作 Accept/Rework/Arbitration/Reject 按现有权限和状态机。返工保留原 Submission、QC、Reviewer、Issue Code、证据区间、原因、Assignee、Due Date、Attempt、Resolution Note。返工后新建提交版本。

## 7. 质量统计
提交量、QC pass/warn/fail、人工接受率、返工率、平均审核时长、规则失败分布、标注人员样本量/质量趋势、批量重跑状态。展示时间窗口和样本量；不足时 N/A。

## 8. 验收
自动 QC；Worker 重试幂等；批量重跑 UI 完整；预览/确认/执行/差异/失败重试；RuleSet 版本明确；返工保留历史；冻结数据不被重写。
