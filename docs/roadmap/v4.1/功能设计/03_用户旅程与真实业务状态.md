# 03｜用户旅程与真实业务状态

## 1. 角色
- 数据负责人：建任务、分配、查看进度、处理异常、验收质量、冻结数据集。
- 采集人员：接任务、检查设备、采集、上传、提交。
- 标注人员：打开被分配任务、审看、标注、保存、提交、返工。
- 质检人员：查看 QC、审核、退回、仲裁、批量重跑。
- 算法人员：查看 DatasetVersion、校验导出、发起训练请求。
- 管理员：账号、权限、Agent、环境和运行监控。

## 2. 真实主链
数据负责人创建 CollectionTask → 采集人员接任务 → Agent 绑定工作站和设备 → Preflight → CaptureSession → Manifest → 复用现有 Upload API → MinIO 校验 → RawAsset → Adapter/Pipeline → Episode + Media + SensorStream + Observation + Action → 创建 Annotation Batch/Task → 指定 Annotator → Workbench 标注 → Submission → 异步 QC → Reviewer Accept/Rework → Dataset Builder → DatasetVersion Freeze → Export → 官方 Loader 验证 → 外部训练平台真实提交（接口可用时）。

## 3. 状态边界
CaptureSession 使用现有状态：`SCHEDULED → RUNNING ↔ PAUSED → COMPLETED / ABORTED`。Upload、Processing、Episode、Annotation、QC、Dataset、Export、Training 各自保留独立状态，不要混成一个万能状态。

## 4. 关键异常旅程
- 断网：Agent 本地 Spool 保留文件，恢复后续传，不重复建 Session/RawAsset。
- 文件损坏：逐文件返回校验结果；必需文件缺失阻止验收；失败文件隔离。
- 部分解析：展示成功/失败/SKIPPED 步骤；重试失败步骤不重复物化成功 Episode。
- 标注冲突：If-Match 冲突时展示本地/服务端版本，不静默覆盖。
- QC 失败：展示 Rule ID、版本、字段路径、证据和恢复动作。
- Dataset 不合格：预览排除项和原因；冻结时重新检查 Gate；冻结后只创建新版本。

## 5. 追溯链
DatasetItem → Episode → ProcessingRun → RawAsset → CaptureSession → CollectionTask → Project/Robot/Device/Sensor/Calibration Snapshot。  
AnnotationResult → AnnotationTask → Assignment → Annotator → LabelSchema Version → ReviewRecord → QCRun。  
AiSuggestion → model/version/prompt/config/input Episode/confidence。
