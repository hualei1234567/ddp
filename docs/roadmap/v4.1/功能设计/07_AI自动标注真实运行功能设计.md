# 07｜AI 自动标注真实运行功能设计

## 1. 现状
事件图契约、三级 level/outcome 映射、AI Suggestion 灌入管道、独立存储、AiSuggestionPanel 和 AI 时间轴轨道已 VERIFIED。真实模型输出仍 BLOCKED，依赖 GroundingDINO/SAM2/VLM 等模型环境。

## 2. 用户流程
数据负责人选择 Episode/Batch → 检查媒体和模型可用性 → 选择模型方案 → 创建 Inference Job → Worker 读取视频/帧/必要数据 → 模型推理 → 输出 `embodied_event_graph_v1` → Adapter 映射 DDP AI Suggestion → 写入现有 API → 标注员审阅 → 采纳/修改/拒绝 → 记录人工决策和模型效果。

## 3. 模型职责
- GroundingDINO：文本条件目标检测；
- SAM2：分割/视频对象跟踪；
- VLM：场景理解、任务语义、动作描述、事件候选；
- 动作识别模型：真实任务数据和评估后再接入。
模型只产生候选建议，人工确认后才能形成最终标注。

## 4. 推理记录
每次记录 inference_job_id、episode_id、model_id/version、weights digest、prompt/preprocess/postprocess version、input asset IDs/hashes、frame sampling、GPU、start/end、status、retry count、output artifact IDs、schema version、error code、latency。

## 5. 执行规则
模型服务不直接写业务库；Worker 经受控 Adapter 调用模型；GPU 不足时排队；同一 Episode + ModelVersion + ConfigHash 幂等；失败可重试/取消；大视频按时间窗口/帧采样；模型不可用显示 BLOCKED/QUEUED，不生成空建议。

## 6. 人工反馈
记录 suggestion、confidence、provenance、accepted/modified/rejected、最终人工结果引用、修改/拒绝原因、处理时间。模型质量指标展示样本量和评估范围，不用单一采纳率代替准确率。

## 7. 验收
部署真实模型权重；真实 Episode 产生非空建议；事件图通过 Schema；建议写入现有后端；前端采纳/修改/拒绝可用；人工结果和 AI 原始结果分离；输入、模型、权重摘要、配置可追溯。无 GPU 时明确 BLOCKED。
