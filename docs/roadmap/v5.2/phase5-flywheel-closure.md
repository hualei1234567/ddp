# 阶段 5：数据飞轮生产化闭环建设方案

> 制定时间：2026-11-27｜基线：`main@88864a1`｜前序：阶段 0–4 完成 + 全项目审计执行完毕
> 前提：不设 staging，全部在 prod 验证；每项必须有实测证据

---

## 一、阶段 5 的定位

前四个阶段解决的是「**平台有没有这些能力**」：
- 阶段 1–3：蓝图 N1–N6 功能面落地（标注载体/派单/质量/导出/飞轮入口/成本）
- 阶段 4：生产化四支柱（可观测/可扩展/可运营/可审计）

**阶段 5 解决的是「这些能力是否真的闭环」**——即数据从产生到被消费、从消费到反馈的
**回路是否闭合**，以及平台是否具备**对外服务与长期治理**的能力。

一句话：**从「功能完备」到「回路闭合」**。

---

## 二、四个判断「闭环」是否成立的硬问题

| # | 问题 | 当前状态 | 阶段 5 要回答 |
|---|---|---|---|
| Q1 | 导出的训练数据，**真的能被训练循环消费**吗？ | 只验证过 `datasets` 库能加载（第三方 PASS），**从未真正训练** | 真实训练循环跑通 + loss 真实下降 |
| Q2 | 标注完成/熔断/回流这些事件，**下游能感知**吗？ | outbox 只在平台内部投递，**无对外通道** | Webhook 出站 + 签名 + 重试 + 熔断 |
| Q3 | 数据从哪来、到哪去，**能追溯**吗？ | 血缘边在写，**无查询能力**；版本间**无差异报告** | 血缘查询 + 版本对比 |
| Q4 | 审计发现的最危险空白（`maintenance.py` 覆盖率 **0%**），**补了吗**？ | 维护任务零测试，改错无人发现 | 覆盖率 ≥70% + 发现真实缺陷 |

四个问题都答"是"，才叫闭环。

## 三、四线并行任务

### Track A：训练侧真实消费闭环（Q1，本阶段核心）

**为什么必须做**：蓝图 N4 的终点不是"能导出"，是"导出数据能被训练"。此前只证明
官方库能**解析**制品结构，从未证明**训练循环能吃它并学到东西**——这是数据飞轮最脆弱的一环。

**交付**：
- numpy 实现的微型训练循环（环境无 torch）
  - SFT：字符级 MLP 语言模型，真实前向/反向/Adam，测 loss 下降
  - DPO：简化 Bradley-Terry 目标，测 chosen>rejected 判对率提升
- 固定种子可复现（同种子两次运行结果一致，写成断言）
- 真实生产数据跑出证据（loss 曲线、生成样本、判对率）

**诚实定位**：这是「数据可用性 + 可学习性」验证，**不是生产级微调**。字符级 tokenizer、
微型模型、小样本——但 loss 下降是真的，可复现是真的。

### Track B：Webhook 出站（Q2，生态对接）

**交付**：
- 迁移 0085 `webhook_subscriptions`（url/secret_hash/event_types/status/失败计数）
- 领域：HMAC-SHA256 签名、连续 5 次失败自动 PAUSED
- 应用：复用既有 outbox 投递器，超时 ≤5s、单事件 3 次尝试
- 开关 `DDP_WEBHOOK_OUTBOUND_ENABLED` **默认 false**（关闭时零行为变化）

**设计要点**：secret 只在创建时返回一次，库里只存 hash；签名带时间戳防重放。

### Track C：维护任务补测（Q4，审计 P1）

**交付**：
- `backend/tests/workers/test_maintenance_worker.py`：每个维护动作至少一条成功 + 一条失败路径
- 覆盖率 **0% → ≥70%**
- 若发现真实缺陷，单独 commit 修复（这是补测的核心价值）

**为什么优先**：审计结论 §四 P1 项——维护任务零测试是**当前最危险的空白**，
因为它直接动数据（删除/归档），出错不可逆。

### Track D：血缘与版本治理（Q3）

**交付**：
- `GET /projects/{id}/lineage/{node_type}/{node_id}`：上游/下游，**深度上限 3（最大 5）、
  节点上限 500，超限显式 `truncated: true`**（不许静默截断）
- `GET /projects/{id}/dataset-versions/{a}/compare/{b}`：条目差异（新增/删除/共同）+
  统计变化 + 质量分变化，复用 `domain/quality/diff.py`
- 零新表、零迁移（只读能力）

## 七、风险与回滚

| 风险 | 缓解 |
|---|---|
| Webhook 出站被下游拖慢 outbox 投递 | 独立超时 ≤5s + 开关默认关闭 + 连续失败自动 PAUSED |
| 血缘查询大图爆炸 | 深度上限 + 节点上限 + 显式 truncated 标记 |
| 版本对比大版本内存 | 条目上限 10000 + 截断标记 |
| 补测时改坏维护逻辑 | 只加测试；如发现缺陷单独 commit 且说明 |
