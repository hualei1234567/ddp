# 质量检查、审核、返工与仲裁闭环

## 1. 质量分层

1. Ingestion QC：文件完整性、Hash、格式和存储；
2. Processing QC：解析、时间、帧、传感器和 Episode；
3. Annotation QC：Schema 完整性、时间边界、标签规则；
4. Human Review：抽检/全检/双人标注对比；
5. Dataset Gate：只有符合规则的结果进入 DatasetVersion。

## 2. 自动 QC

规则包含 rule_id/version、applies_to、severity、deterministic logic、threshold、failure code、evidence path 和 remediation hint。

检测示例：必填标签缺失、枚举值非法、时间片段超出 Episode、必需阶段缺失、同一标签重复/冲突、Episode 未完成基础解析、媒体流缺失、采集 Manifest 不完整、设备标定信息缺失（仅当任务要求时）。

不能把“数据集没有提供某种模态”直接当成失败。规则要区分 REQUIRED / OPTIONAL / NOT_APPLICABLE。

## 3. 审核队列

过滤 Project、TaskSpec、标注员、提交时间、QC 状态、返工次数、风险等级和抽检策略。审核详情必须同时展示原始媒体、时间轴、标注结果、Schema、QC Evidence 和历史版本。

## 4. 审核动作

- ACCEPT：通过；
- REWORK：退回修改；
- ARBITRATION：争议升级；
- REJECT：拒绝（必须定义原因与权限）；
- WAIVE：豁免（仅管理员/指定角色，强制说明原因和审计）。

## 5. 返工闭环

返工必须记录 source_result_version、issue_code、issue_description、evidence_time_range、reviewer_id、returned_at、assigned_to、due_at、rework_attempt 和 resolution_note。

返工生成新的可编辑工作版本，旧提交与审核意见不可删除。重新提交后 QC 重新执行。

## 6. 双标与一致性

V3.1 可先实现可选双标任务结构；IAA 计算须在同一 Schema、同一样本范围、同一标签定义上比较。不要把不同标签类型简单用一个百分比混算。先输出字段级/类别级一致性和样本量，样本不足显示 N/A。

## 7. Dataset Gate

进入训练集候选的 Episode 必须：
- Processing 状态 READY；
- RawAsset 已 VERIFIED；
- 必需媒体/数据流齐全；
- Annotation Result 已提交；
- 必需 QC 规则通过；
- Review 状态 ACCEPTED；
- 无未关闭 P0/P1 QualityIssue；
- Schema / Pipeline / Rule 版本明确；
- 数据来源许可可用。

任何例外必须有 waiver 记录，不能直接绕过。
