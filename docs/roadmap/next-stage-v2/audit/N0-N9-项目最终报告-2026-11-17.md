## 0. 一句话结论

N0–N9 十个阶段的能力已全部落地，**主链从外部数据源导入贯通到模型反馈闭环**，
每一环都有真实数据流过或真实执行证据。本轮补上了此前三处「有写无读」「有表无入口」
「导入后卡住」的结构性缺口，并修掉 6 个只有在真实数据库或真实迁移产物上才暴露的缺陷。

平台现在具备：项目与成员管理、采集素材全生命周期、场地、标注与质量、数据集与血缘、
训练交付、模型评测与反馈、配额与用量报表、**审计日志查询**。

## 2. 本轮新增能力（8 个并行作业）

| 能力 | 解决的问题 | 关键设计 |
|---|---|---|
| **采集素材写路径**（N8） | 四类素材此前只有创建，`ACTIVE`/`ARCHIVED` 枚举值永远不可达 | 状态机 `DRAFT→ACTIVE→ARCHIVED`（终态）；字段可变性按「是否参与执行语义」区分；数据库触发器与应用层共用同一份迁移表 |
| **场地实体**（N9 多基地） | 三张表的 `location_id` 可写任意值，是幽灵引用 | `(project_id, location_id)` 复合外键；迁移清理存量悬空引用并逐行留痕 |
| **跨数据集基线对比**（N6） | 基线此前强制同数据集；直接放开会给出「提升 12%」这类静默错误 | 必须显式声明 `cross_dataset_comparison`；校验 `task_type` 一致；**取不到任务语义按不可比拒绝** |
| **五轴覆盖接入**（N7） | ACTION/LABEL/MODALITY 只能走人工值 | MODALITY←`sensor_ids`；ACTION←`task_id→action_spec_id`（join **被引用版本行**，非 code 谱系）；LABEL←已批准标注记录 |
| **配额与用量报表**（N9 治理） | 「用多少、剩多少、超没超」无法回答 | 5 类写操作**写入前**拒绝；`used=null` 表示未测量而非 0；测不到返回 503（fail-closed） |
| **审计日志查询** | 894 条审计记录**没有任何人能查** | 仅 owner/管理员；时间区间必须带时区；跨项目返回 200+空列表（不泄露存在性）；只读 |
| **项目与成员管理** | `project_id` 是隔离基石，却没有任何 `/projects` 端点 | 创建仅平台管理员且自动成为 owner；不做硬删（CASCADE 会销毁全部业务数据）；至少保留一名 owner |
| **导入后 Episode 自动就绪** | 主链唯一断裂：Manifest 必须手工构造，Episode 停在 PENDING | 10 类阻塞原因显式登记；判不了绝不放行；导入成功 ≠ Episode 就绪，两者可区分 |
| **前端页面** | 采集素材、场地、质量管理、项目、人员、审计日志全无界面 | 全部复用既有 `PageContainer`/`PageState`/`useCursorPage` 等；动作按钮只按服务端 `allowed_actions` 渲染 |

## 6. 部署情况

### 6.1 本地完整栈：可运行

实际启动 **9 个容器全部 Up**：`api` / `web` / `postgres` / `redis` / `minio` /
`worker`（RawAsset 校验）/ `export-worker` / `datasource-worker` / `ingestion-job-worker`。

数据库迁移由 `migrate` 服务在 api 启动前自动执行。本轮验证：从 `0040` 自动升到 `0043`，
此后链推进到 `0049`。

**本轮发现的一个部署边界（已写入演练记录）**：`migrate` 服务用的是**构建时的镜像**。
镜像不重建，新增迁移就不会被应用——`docker compose up` 会因
`depends_on: service_completed_successfully` 让人误以为「迁移跑过了」，实际跑的是
旧镜像里的旧迁移。**生产发布必须把镜像重建与 `migrate` 视为一个原子步骤。**

### 6.2 备份恢复演练：VERIFIED（本轮重做）

## 12. 结论

**能用的部分是真能用的**：主链不是示意图——真实数据走完导入 → Episode → 标注 →
数据集 → 训练交付 → 模型评测 → 反馈 → 需求闭环，每一跳有测试或实测值。

**没做的部分诚实登记**：11 项缺口逐条列出，状态标记区分 `BLOCKED`（无硬件）与
`MISSING`（能做什么没做）与 `PLANNED`（后端没有能力）。

**本轮最重要的收获不是功能数量，而是那批「看起来存在但不生效」的缺陷**：
