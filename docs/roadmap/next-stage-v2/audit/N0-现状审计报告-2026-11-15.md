## 0. 一句话结论

**你的 384 个真实媒体资产止步于 `MediaAsset`，从未进入 DDP 的 Canonical 数据链路。**

导入链路（12 个数据源 / 384 个资产 / 9 条审核）是真实的、可复现的，但它**不产生 `RawAsset`，也不产生 `Episode`**。而 Episode 创建强制要求 `raw_asset_ids`（`episode_schemas.py:49`，`min_length=1`）。因此：

> **当前从 Hugging Face 导入的数据，在法律上无法创建任何 Episode 实体，也就无法进入标注、质检、数据集构建、训练交付的任何一环。**

这不是"功能还没做"，是**主链断在第二段**。V2.0 的 N1→N5 全部依赖这条链打通。

## 2. 主链断点（最关键）

```
HF Repo ──✅──> DataSource ──✅──> ImportJob ──✅──> MediaAsset ──❌──> RawAsset ──❌──> Episode
                                                                        ↑
                                                              这里断了
```

| 环节 | 状态 | 证据 |
|---|---|---|
| HF Repo → DataSource | ✅ VERIFIED | 12 个真实数据源，revision 40 位 sha 校验 |
| DataSource → ImportJob | ✅ VERIFIED | 11 个 SUCCEEDED |
| ImportJob → MediaAsset | ✅ VERIFIED | 384 个资产 + MinIO 回读 sha256 一致 |
| **MediaAsset → RawAsset** | ❌ **MISSING** | `application/datasources/*` 与 `workers/datasources.py` 中 `RawAsset` 出现次数 **0** |
| **RawAsset → Episode** | ❌ **不可达** | Episode 创建强制 `raw_asset_ids`（`min_length=1`），但无 RawAsset 可引用 |

**后果**：N1 的"Episode 生成"未闭环；N2 的 Canonical Schema 无输入；N3 的 Pipeline 无对象；N5 的 DatasetItem 无 Episode 可引。**N1 之后的所有阶段都卡在这一处。**

## 3. 两个 P0 级运行态缺陷（异步链路实际不可用）

现有 384 个资产是**验收脚本直接调用 `ImportRunner`** 导入的，**不是通过产品异步链路**。异步链路有三处硬阻断：

| # | 缺陷 | 证据 | 后果 |
|---|---|---|---|
| P0-1 | **datasource worker 未部署** | `docker-compose.yml` 服务列表只有 `api/worker/export-worker/maintenance-worker`，无 datasource worker；`workers/datasources.py:234` 有 `__main__` 入口但无启动目标 | 通过 API 创建导入任务后**无人消费，永远 PENDING** |
| P0-2 | **镜像缺 `data-platform`** | `infra/docker/api.Dockerfile` 只 `COPY backend/ .`；而 `workers/datasources.py:65,145` 运行时 `import ddp_data` | 容器内启动即 `ModuleNotFoundError` |
| P0-3 | **`httpx` 不在生产依赖** | `httpx==0.28.1` 只在 `backend/requirements-dev.txt:3` | 同上 |
| P0-4 | **重试状态机自锁** | `import_runner.py:143-145` 要求 `status is PENDING` 才执行，但 `_fail()` 在 `:225-229` 已把状态提交为 **FAILED**。worker 重试时必然被拒 → 重试 5 次 → 死信 | 任何一次网络抖动 = 任务永久失败，且 `ImportRunner` 无 worker 测试（`tests/workers/` 零 datasource 用例） |

**这是"以为能用其实不能用"最典型的一类**：脚本路径 PASS，产品路径断。

## 5. N2/N3 关键结论（详见 N2-N3 审计）

### 5.1 蓝图 27 个建议实体：存在 18，缺失 9

**硬缺失（一行代码都没有）**：`Frame`、`Observation`、`Action`。

这是 N3 的根基 —— 没有帧级实体，就没有"多模态数据"可言。`episode.v1.schema.json` 里只有 `frame_count: integer`。

**其他缺失**：`DatasetSource`（被 `data_sources` 吸收）、`Session`（只有 `upload_sessions`，语义不同）、`QualityRule`/`QualityRun`/`QualityIssue`（只有数据集级报告，无 Episode 级规则实体）。

### 5.2 `original_metadata` 是坏的（既有契约违约）

- 契约 `schemas.stage2.yaml:301,324` 要求 `raw_metadata` **required**
- 领域模型 `RawAsset.raw_metadata` 存在（`domain/ingestion/models.py:352`）
- API 出参也声明了（`upload_schemas.py:225`）
- **但 `RawAssetModel` 无该列**（`models/ingestion.py:268-380`），仓储读写均不涉及 → **永远为空 `{}`**

同类问题：`device_ids` / `sensor_ids` / `sensor_snapshot` / `device_time_raw` 五个字段同样是"域有、契约要求、ORM 无列"。这是 N2 ADP-004 的实质缺口。

### 5.3 两套 Pipeline 并存，一套空转

| 表 | 状态机 | 执行方 | 结论 |
|---|---|---|---|
| `ingestion_jobs` | 完整（attempt/retry/log_ref/output_refs/pipeline 版本/config_hash） | **无** | `PARSE_METADATA`/`SEGMENT_EPISODE` 创建即永久 QUEUED |
| `data_source_imports` | 极简（5 态） | 有（ImportRunner） | 真在跑，但无重试/无步骤 |

**解析不是独立阶段**：`ImportRunner.execute()`（101 行单函数）里同步完成 下载→解析→映射→落库，无 Step、无中间产物。

### 5.4 N3 判定：改造 40% + 新建 60%

**可复用**：RawAsset 保护体系（对象键不可变 + 领域断言 + DB 触发器 + 禁删 + Episode 快照）、8 种格式魔数探测、`ingestion_jobs` schema、`time_base` 强校验（本审计中质量最高的一段：9 键白名单 + 失败关闭 + DB CHECK 四层）。

**必须新建**：Step 层、Frame/Observation/Action 三实体、多流对齐、切片规则版本表、Adapter Registry、RawAsset 5 个缺失列。
