# DDP 工程治理、全局复用优先与质量门禁

## 1. 代码与工具基线

- macOS + VS Code + Claude Code CLI；
- Claude Code 原生 Agent 协作；
- Git Branch + Git Worktree 并行开发；
- GitHub 是唯一代码托管、版本管理、PR、Code Review 和 CI/CD 平台；
- 不建立 GitHub / GitLab 双重代码托管；
- 不引入 DSH / DeepSeek Harness；
- 不使用 Codex 作为本项目执行环境；
- 不未经批准更换模型服务、Runtime、数据库、对象存储和部署设施。

## 2. 全局 Reuse First

每个功能开发前必须完成复用评估，顺序如下：

1. 复用 DDP 当前已有页面、组件、API、服务、ORM、任务系统和文件服务；
2. 使用官方 SDK / API；
3. 集成成熟、活跃且许可证兼容的开源项目；
4. 开发轻量 Adapter / Facade；
5. 只有无合适方案时才自研，并写明原因。

### 复用评估表

| 需求点 | DDP 现有能力 | 官方 SDK / 开源方案 | 实际缺口 | 方案 | 是否自研 |
|---|---|---|---|---|---|
| HF 数据接入 | 仓库核验 | huggingface_hub / datasets | 待审计 | 优先复用 SDK | 待定 |
| LeRobot 解析 | 仓库核验 | LeRobot 官方生态 | 待审计 | 薄 Adapter | 待定 |
| 视频处理 | 现有播放器/服务 | FFmpeg / OpenCV | 待审计 | 复用或封装 | 待定 |
| Parquet | 现有处理能力 | PyArrow | 待审计 | 字段映射 | 待定 |
| HDF5 | 现有处理能力 | h5py | 待审计 | 字段映射 | 待定 |
| ROS Bag / MCAP | 现有处理能力 | ROS / MCAP 工具 | 待审计 | Adapter | 待定 |
| 标注 | 现有标注模块 | Label Studio 等 | 待审计 | 集成 | 待定 |
| 图表 / 时间轴 | 现有组件 | 当前 UI 生态 | 待审计 | 复用 | 待定 |

禁止未经评估引入新的前端框架、数据库、消息队列集群、微服务注册中心、对象存储或通用播放器。

## 3. 代码架构约束

- 领域模块边界清晰；
- Presentation / API / Application / Domain / Infrastructure 分层；
- 依赖方向明确，Domain 不依赖 Web、ORM 和第三方 SDK；
- 统一异常、日志、配置、事务、幂等和权限校验；
- Controller 不堆业务逻辑；
- 不把所有逻辑堆到万能 Service；
- 不创建万能 utils；
- 不允许循环依赖；
- 不允许重复业务规则；
- 不硬编码机器人型号、Dataset Repo 和标签；
- 不吞异常、不无限重试；
- 大文件任务异步化；
- Raw 数据不可覆盖；
- Migration 必须可审查、可测试、可回滚。

## 4. GitHub 工作流

```text
Issue / Requirement
  → Feature Branch
  → Local Development
  → Unit / Integration Tests
  → Pull Request
  → GitHub Actions CI
  → Code Review
  → Merge
  → Staging Verification
  → User Acceptance
  → Release / Deploy Approval
```

- 每个 PR 绑定 Issue / Requirement；
- 共享 Schema、API、Migration 指定唯一 Owner；
- Worktree 并行开发不得共享未冻结的数据库迁移；
- 禁止未经批准直接 Push 到受保护主分支；
- 禁止未经批准合并、发布或部署；
- PR 描述包含变更范围、测试、数据迁移、安全影响和回滚方式。

## 5. Agent 协作分工

| Agent | 责任 | 关键交付 |
|---|---|---|
| General Owner | 范围、优先级、冲突和最终验收 | 决策记录、阶段批准 |
| Senior Product Manager | 需求、PRD、流程和验收 | PRD、Backlog |
| System Architect | 架构、Schema、API、ADR | 技术设计、契约 |
| UX Designer | 信息架构、页面、交互和体验 | 页面规范、原型 |
| Senior Frontend Engineer | 前端实现和组件复用 | 页面、组件、前端测试 |
| Senior Backend Engineer | API、领域逻辑、数据和任务 | 服务、Migration、后端测试 |
| QA & DevOps Engineer | 测试、CI、安全、部署和监控 | 测试报告、发布检查 |

每个任务必须指定唯一 Owner、输入、输出、依赖、修改范围和验收标准。多个 Agent 不得同时无协调修改同一核心 Schema、Migration 或公共接口。

## 6. 测试门禁

至少覆盖：
- Unit / Domain；
- API / Contract；
- Integration；
- Database / Migration；
- File Processing；
- Dataset Adapter；
- Time Sync / Episode；
- Annotation / Quality；
- Permission / Security；
- E2E；
- Performance（关键大文件和列表）；
- Recovery（上传中断、任务重试、部分失败）。

未执行测试标记 `NOT RUN`；环境阻塞标记 `BLOCKED`；失败如实报告。

## 7. 安全与数据治理
- HF Token 和其他 Secret 只存服务端安全配置，不进入前端、日志和 Git；
- 数据集 License、Gated 条件、来源和 Revision 必须记录；
- 下载数据和缓存默认不提交 GitHub；
- 上传文件校验类型、大小、Hash 和路径；
- 防止路径穿越、未授权文件访问和跨项目越权；
- 原始数据和处理产物权限明确；
- 记录关键操作审计；
- 生产数据变更和部署单独审批；
- 备份恢复按真实基础设施能力制定并演练。

## 8. 可观测性
关键链路记录结构化日志、任务状态、耗时、失败原因和资源使用。按适用场景关联：
`request_id`、`trace_id`、`project_id`、`dataset_id`、`episode_id`、`job_id`、`asset_id`。

监控 API 错误、导入失败、解析失败、Worker 状态、队列积压、存储容量、Pipeline 耗时、导出失败和数据质量趋势。

## 9. Definition of Done
- 需求和验收标准明确；
- 复用评估完成；
- 代码边界清晰；
- 自动化测试通过；
- 权限、安全和数据来源检查通过；
- 文档、API、Schema 和 Migration 同步；
- GitHub PR 审查通过；
- 运行证据和验收记录完整；
- 回滚或恢复方案明确。
