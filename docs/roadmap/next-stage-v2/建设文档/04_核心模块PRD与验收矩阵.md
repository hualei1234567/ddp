# DDP 下一阶段核心模块 PRD 与验收矩阵

## 1. 模块一览

| 模块 | 用户 | 核心价值 | 依赖 |
|---|---|---|---|
| 数据源与导入 | 数据工程/平台管理员 | 多来源数据稳定接入 | Connector / Storage |
| Adapter 与 Schema | 数据工程/算法 | 格式统一、来源可追溯 | Canonical Schema |
| Pipeline / Episode | 数据工程/算法 | 多模态解析和标准化 | Worker / Parser |
| 标注中心 | 标注员/审核员 | 标签生产和审核 | Label Schema |
| 质量中心 | QA/数据负责人 | 质量规则和返工闭环 | Quality Engine |
| 数据资产 | 数据负责人/算法 | 检索、版本、血缘 | Metadata / Dataset |
| 训练支撑 | 算法团队 | 稳定数据集交付 | Dataset Version |
| 模型反馈 | 算法/数据负责人 | 评测问题回流 | Evaluation |
| 真实采集与设备 | 采集员/设备管理员 | 现场数据进入标准链路 | Device Adapter |
| 规模化运营 | 管理者/运营 | 多项目、多基地协同 | 上述模块稳定 |

## 3. 统一异常体验
所有模块统一支持：
- Loading；
- Empty；
- Partial Success；
- Failed；
- Retryable / Non-retryable；
- Permission Denied；
- Cancelled；
- Stale Data；
- Blocked。

异常必须展示错误原因、影响范围、是否有副作用、下一步处理建议和关联日志/记录。

## 4. 通用验收要求
- 所有展示数据必须来自真实接口或明确标记为测试数据；
- 每个功能有权限验证；
- 每个异步任务有状态、日志、取消/重试策略；
- 每个数据转换保留来源和版本；
- 每个核心操作有审计记录；
- 每个模块有单元、集成和关键 E2E 测试；
- UI 不能伪造后端不存在的状态和能力。
