# DDP 具身智能数据闭环平台｜下一阶段建设蓝图包

**蓝图版本：** V2.0 Next-Stage Blueprint  
**基线规范：** `DDP_具身智能数据闭环平台建设总规范_V1.0_FINAL.md`  
**专项承接：** `DDP_数据接入与样本验收中心_PRD_V1.3_全局复用优先版.md`  
**执行环境：** macOS + VS Code + Claude Code CLI  
**代码管理：** GitHub（唯一代码托管与版本管理平台）

## 本包定位

本包用于指导 DDP 在既有 V1.0 建设成果上的下一阶段增量建设。不是新项目立项，不是重新搭建，不替代 V1.0 总规范，也不代表未经审计的功能已经完成。

## 文件清单

1. `01_DDP下一阶段建设蓝图_V2.0.md`：总目标、范围、总体架构、原则与阶段承接。
2. `02_下一阶段路线图与里程碑.md`：阶段顺序、依赖、优先级、交付物和验收门禁。
3. `03_数据架构与Canonical_Schema演进规范.md`：数据分层、核心实体、Adapter、血缘与版本。
4. `04_核心模块PRD与验收矩阵.md`：各阶段功能范围、用户场景、验收标准。
5. `05_工程治理复用优先与质量门禁.md`：复用策略、代码架构、GitHub、测试、安全和运维。
6. `06_Claude_Code下一阶段建设总Prompt.md`：可直接交给 Claude Code 的执行话术。
7. `07_V1.0现状审计与阶段准入模板.md`：核对已有功能和确认下一阶段起点。

## 推荐使用方式

1. 将本包放入当前 DDP GitHub 仓库的 `docs/roadmap/next-stage-v2/`（目录名可按现有规范调整）。
2. 让 Claude Code 先读取 V1.0 总规范、V1.3 数据接入 PRD 和本包全部文件。
3. 先执行只读审计，建立 VERIFIED / PARTIAL / UNVERIFIED / MISSING / BLOCKED 功能矩阵。
4. 将已完成能力冻结为基线，只对差距项排期。
5. 经用户批准后，按里程碑分支开发、测试、PR 和验收。

## 重要边界

- 现有系统和已验收功能必须保留，不得推倒重建。
- V1.0 是产品、架构和工程治理基线；V2.0 是下一阶段实施蓝图。
- V1.3 的 Hugging Face / 第一人称数据集接入方向作为当前 PoC / MVP 的承接依据。
- 当前优先打通真实数据链路；多供应商、多基地、商务结算等规模化能力后置。
- 所有技术方案必须先做复用评估；不为“架构完整”而提前引入微服务、Kubernetes、新数据库或消息队列集群。
- 不得把设计文档中的目标状态当成仓库中已经存在的实现。
