# 12｜标注工作量分配与人员负载提示

## 1. 目标
FR-020 当前后端工作量能力完整，但分配前实时负载提示未接。V5.1 做透明的分配辅助，不引入黑箱自动派单。

## 2. 分配前展示
候选人员当前进行中任务数、剩余估算工时、逾期任务数、近 7/30 天提交量、QC 首次通过率（展示样本量）、返工率、任务类型/机器人类型经验、是否可分配、ProjectScope 和 Assignment 权限、最近活跃时间（如可合法采集）。

## 3. 负载计算
以预计剩余工时为主要负载，而非简单任务数。工时估计来源：历史同类型任务中位数、Episode 时长、任务复杂度、人员历史处理时长。样本不足时显示“数据不足”，不得生成伪精确排名。

## 4. 操作流程
选择任务 → 选择候选人员 → 负载对比 → 查看原因 → 手动确认分配。支持批量分配预览；确认后复用现有 Assignment API 和状态机。

## 5. 公平与防滥用
质量指标不作为唯一考核；不同任务难度分层；不公开不必要的个人信息；管理者可覆盖建议但必须记录理由；低样本量不自动给出负面评价。

## 6. 验收
负载展示与后端实际任务一致；并发分配后重新计算；无权限人员不可被分配；缺少数据时明确 N/A；人工覆盖有审计记录。
