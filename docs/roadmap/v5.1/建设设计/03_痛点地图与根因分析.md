# 03｜V5.1 痛点地图与根因分析

## 痛点一：平台有 Episode，但 Episode 还不是训练样本
表现：RawAsset、Episode、DatasetVersion 已有数据量，但 SensorStream / Observation / Action 没有真实逐帧生产；LeRobot 只验证 metadata。根因：Adapter 的格式识别/元数据读取与 payload 逐帧解析没有形成可验证边界；Canonical 类型定义不代表真实生产者落地；时间戳、单位、坐标系、标定和同步缺少实样本验证。解决：先拿真实样本建立 fixture 和解析证据；逐帧 payload、shape/dtype、时间域、视频解码和动作数据作为验收核心。

## 痛点二：不同机器人数据格式无法形成稳定统一标准
表现：已有 hdf5 / rosbag / mcap / parquet / lerobot / droid / media Adapter，但真实能力不一致。根因：Adapter Registry 容易把 detect/inspect 误认为“完整支持”。解决：每种格式定义 DETECT、INSPECT、PAYLOAD_PARSE、STREAM_EXTRACT、EPISODE_BUILD、ROUND_TRIP 六级能力，每级有真实 fixture、测试和限制说明。

## 痛点三：数据质量靠上游和人工兜底
表现：DATA_CLEANING 显式 SKIPPED。根因：缺少规则版本、输入输出差异、清洗证据和人工复核边界。解决：只实现可解释的确定性规则；RawAsset 不变；清洗产物版本化；自动修复与隔离分开。

## 痛点四：标注人员被冲突和分配不均拖慢
表现：If-Match 能拒绝冲突，但缺完整恢复流；分配后才发现负载不均。解决：冲突时保存双方版本、差异比较、复制本地草稿、人工合并；分配前展示负载、技能/权限、逾期、返工和历史质量，不做黑箱自动派单。

## 痛点五：QC 结果可见，但证据定位成本高
解决：QC 规则结果点击后定位 Episode 时间轴；高亮区间、字段路径、帧/数值证据；支持从审核页直接创建返工任务。

## 痛点六：系统能运行，但灾难恢复没有完整演练
解决：建立 Runbook、恢复演练、数据一致性校验、RPO/RTO 指标和演练报告。

## 痛点七：权限逻辑有测试，浏览器真实路径缺证明
解决：Collector / Annotator / Reviewer / Dataset Reader / Project Admin 等角色真实登录，验证 UI 隐藏与 API 拒绝双层边界。

## 痛点八：冻结数据集引用关系风险
解决：冻结版本建立引用保护；删除先做影响预览；默认禁止物理删除被引用对象；保留合规归档/软删除路径。

## 验收哲学
每个“已支持”都回答：输入是什么？真实处理了什么？输出是什么？异常怎么办？如何追溯？有什么 E1/E2/E3 证据？
