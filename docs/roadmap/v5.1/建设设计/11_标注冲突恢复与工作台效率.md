# 11｜标注冲突恢复与工作台效率

## 1. 现状
If-Match 乐观锁和冲突展示已存在；FR-019 PARTIAL，缺复制草稿和人工合并完整恢复流。V5.1 不重做 Workbench 播放器和时间轴。

## 2. 冲突发生时
暂停自动提交当前冲突版本；本地草稿进入只读保护态；获取服务端最新版本；展示冲突对象、字段、时间区间和修改人；标记双方新增/删除/修改；用户选择刷新放弃本地、复制本地草稿、逐项合并；合并后重新运行 Schema 和 L1/L2/L3/OUTCOME_SPAN 校验；使用最新 If-Match 提交；记录 Conflict Resolution Record。禁止自动 last-write-wins 覆盖。

## 3. 草稿恢复记录
保存 draft_id、assignment_id、episode_id、local_version、server_version、conflict_at、field diff、resolution choice、resolved_by、resolved_at、result submission version。

## 4. 页面状态
Saved / Saving / Save Failed / Conflict / Local Draft Protected / Merge Required。离开页面、关闭浏览器、重新登录后应能恢复未解决草稿（遵循现有草稿存储策略和权限范围）。

## 5. 工作台性能
大 Episode 按需加载和时间窗口读取；切换轨道不重复拉取整个媒体；自动保存有 debounce 但提交前必须 flush；播放器和时间轴交互不被后台 QC/AI 请求阻塞。

## 6. 验收
两个用户同时编辑同一 Assignment；后提交者得到 Conflict；本地草稿未丢；差异可读；人工合并后服务端校验通过；审计记录完整。
