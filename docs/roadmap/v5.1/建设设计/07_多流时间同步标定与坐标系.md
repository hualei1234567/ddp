# 07｜多流时间同步、标定与坐标系

## 1. 核心问题
播放器都从 0 秒开始不代表多流同步。相机、关节状态、力传感器、IMU、控制指令可能有不同 clock、采样频率、延迟和漂移。

## 2. 时间模型
保留 `timestamp_raw`（源数据原始时间戳）、`timestamp_normalized`（统一时间域）、`timestamp_wall`（可选墙钟时间）。每个流关联 `time_base_id`，记录 clock source、unit、epoch、monotonic/wall-clock 属性、同步方法、offset、drift、uncertainty 和 evidence。

## 3. 同步策略
优先级：硬件共同触发/共享时钟；设备时间同步协议或 clock mapping；数据集官方同步元数据；明确记录的人工校准偏移；无可靠证据则标记 UNSYNCED。不能默认用视频帧率推导所有传感器时间，也不能将最近邻匹配伪装成原始同步。

## 4. 同步算法设计
每个 sync group 选择 reference clock；计算各流 offset；对足够时间跨度估计 drift；输出匹配误差分布、最大误差、P95 误差和不确定度；按任务要求设置 tolerance；超限标记 WARN/FAIL，不静默修正。插值/重采样是衍生数据，记录方法和参数。

## 5. Calibration
Calibration Snapshot 关联设备、传感器、有效时间、版本、标定参数、坐标系、来源和文件 Hash。Episode 固定引用使用时的 Calibration Version，不能动态指向“当前最新标定”。

## 6. 坐标系
采用明确的 frame graph / parent-child 关系。记录 frame 名称、方向约定、单位、右手/左手系、变换矩阵、时间有效范围和来源。缺少变换时不猜测。

## 7. UI
Episode Explorer 展示同步组、各流时间范围、offset/drift、误差分布、同步状态；时间轴可切换原始时间/归一化时间；人工调整生成新的 sync configuration version，不覆盖原始值。

## 8. 验收
使用至少两条真实流验证共同时间区间、offset/drift、容差和匹配结果；注入时间跳变/漂移/重复时间戳后能告警；校准快照可追溯；未同步流明确显示 UNSYNCED。
