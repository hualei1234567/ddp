## 2. 边（依赖）与理由

| 从 | 到 | 类型 | 理由 |
|---|---|---|---|
| N0 | N1–N9 | 硬依赖 | 事实基线、能力矩阵、No-Go 未冻结前不得排期 |
| N2-01 数据源 | N2-02 导入中心 | 硬依赖 | 导入任务必须引用已登记数据源 |
| N2-02 导入中心 | N3-02 Adapter 发现 | 硬依赖 | Adapter 由导入流程调用；无导入则 Adapter 无触发点 |
| N3-01 Canonical 实体 | N3-02 Adapter 契约 | 硬依赖 | Adapter 输出必须映射到稳定 Canonical |
| N3-02 | N4-01 Processing Run | 硬依赖 | Pipeline 每一步都读写 Canonical |
| N4-01 | N4-02 时间同步 / N4-03 切分 / N4-04 质量 | 硬依赖 | 三个子能力都需要 run 上下文与重试 |
| N4-04 质量引擎 | N5-03 Manifest 的 quality 字段 | 硬依赖 | Manifest 要固定 quality rule version |
| N2-03 Raw Asset | N5-01 Asset Catalog | 硬依赖 | Catalog 的主体是 RawAsset/Episode |
| N3-01 Episode | N5-02 Dataset Version | 硬依赖 | 版本成员是 Canonical Episode |
| N5-02 | N5-03 Manifest | 硬依赖 | Manifest 是版本的冻结内容 |
| N5-01/02 | N5-04 Lineage | 硬依赖 | 血缘边连接资产与版本 |
| N2-04 Episode Explorer | N6-02 Annotation Task | 硬依赖 | 标注对象来自 Episode |
| N6-01 Schema Registry | N6-02/03/04 | 硬依赖 | 标签结构未定则任务/建议/一致性都无契约 |
| N6-04 QA | N6-05 Rework | 硬依赖 | 返工由 QA 不通过触发 |
| N5-02/03 | N7-01 Training Grant | 硬依赖 | 训练必须引用 FROZEN 版本 |
| N7-01 | N7-03 Training Run | 硬依赖 | Run 需要授权范围 |
| N7-03 | N7-04 Evaluation | 硬依赖 | 评测对象是模型版本 + 数据版本 |
| N7-04 | N7-05 Data Gap | 硬依赖 | 缺口来源含评测失败 |
| N7-05 | N7-06 闭环 | 硬依赖 | 缺口 → 需求 → 新数据 |
| N1 全部 | N8-06 安全 | 软依赖 | 安全审计覆盖设备域鉴权与标定链 |
| N2/N4 | N8-01 Metrics / N8-02 Trace | 软依赖 | 指标与追踪要挂到真实导入/处理链才有意义 |
| N8-03 性能 | N9 | 硬依赖 | 规模化前必须先有 1K/10K 基线 |
| N8-05 staging | N9 | 硬依赖 | 真实机器人接入必须在可发布环境验证 |
| N2-05 Review / N2-06 Quality UI | N7-04 Evaluation 的可解释性 | 软依赖 | 评测失败证据常需回看视频 |

## 3. 可并行分组（供 Agent 团队开工）

| 组 | 可并行任务 | 前置 | 说明 |
|---|---|---|---|
| P0 | N1-01…N1-07 | N0 | 设备域收口，互不阻塞；同一迁移文件需串行 |
| P1 | N2-01/02/03/04/05/06 | N0 | 六项可分头推进；N2-02 先冻结导入状态机 |
| P2 | N3-01/02 + N4-01 | N2-02 | Canonical 与 Adapter 契约先定，Pipeline 再落 |
| P3 | N4-02/03/04 | N4-01 | 三条子线可并行，共享 run 上下文 |
| P4 | N5-01/02/03/04 | N3/N4 | Manifest 与 Lineage 可并行；Dataset Version 状态机单 Owner |
| P5 | N6-01…N6-05 | N2-04 + N5-01 | Schema Registry 先定 |
| P6 | N7-01…N7-06 | N5-02 + N6-04 | 严格串行度最高 |
| P7 | N8-01…N8-06 | N1 + N2 | 横切，可全程并行；staging 受外部主机阻塞 |
| P8 | N9-01…N9-05 | N8-03/05 | 硬件 BLOCKED 时只做 Mock/回放 |

## 4. 关键路径

```text
N0 → N2-01/02 → N3-01/02 → N4-01 → N4-04 → N5-02/03 → N7-01 → N7-03 → N7-04 → N7-05 → N7-06
```

关键路径上的任何延期都会直接推迟「模型反馈驱动数据生产」的最终闭环。
N1 与 N8 不在关键路径上，但 N1 的 G-16/G-11 是**出口门禁**，N8-05 是发布门禁。

## 5. 阻塞与外部依赖

| 节点 | 阻塞源 | 解除条件 |
|---|---|---|
| N8-05 staging | 主机不可达 | 用户提供 SSH 别名/地址 |
| N9-01/02/04 真实设备 | 无硬件 | 用户提供设备或明确 Mock 验收口径 |
| N7-03 真实训练 | 外部训练平台未配置 | 提供 Adapter endpoint 或维持 Local/Mock/Dry Run |
| N4-04 视觉规则 | 需要 FFmpeg/解码环境 | 本机已具备；CI 需补依赖 |
