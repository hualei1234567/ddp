# ADR-0039 处理运行产物目录（`processing_artifacts`）

- 状态：**ACCEPTED**
- 日期：2026-11-22
- 决策者：System Architect + 后端；批准人：用户（长期授权）
- 关联：ADR-0014（复用优先）、ADR-0038（Episode 可训练口径与 Canonical 版本）、V31-016
- 约束：不新增依赖、不改既有 `output_refs` 语义、不引入跨域依赖

## 1. 背景

`ProcessingRun.output_refs` 是 `list[str]` 的 JSON 数组，只有对象 key。
它能回答"这次运行产出了哪些对象"，但回答不了：

- 产物是**哪个阶段**、**哪次尝试**产出的（重试后历史产物无法区分）；
- 产物**类型**（元数据 / Canonical / 时间对齐报告）；
- 产物**多大**、**内容摘要**是否与登记时一致（无法做完整性校验）；
- 产物的**来源输入**是哪个对象（血缘断在 key 上）。

继续往 JSON 数组里塞结构化对象，会让"数组里既有字符串又有对象"成为常态，
读取方必须同时兼容两种形状——这正是 V3.1 要消除的漂移。

## 2. 候选方案

| 方案 | 做法 | 问题 |
|---|---|---|
| A. 继续用 `output_refs`，元素改为对象 | 改列类型为 `list[object]` | 破坏既有契约与调用方；读取方要兼容两种形状；无唯一键，重试会重复 |
| B. 新建 `processing_artifacts` 表 | 一等的产物目录，`output_refs` 退化为兼容投影 | 新增一张表与迁移 |
| C. 复用接入域 `CaptureSessionArtifact` | 直接投影 | 它是**只读视图**（不落库），把两张权威表投影成列表；处理产物有阶段归属、尝试序号与级联删除语义，合并会让两种职责互相污染 |

## 3. 决策

**选方案 B。** 理由：

1. **兼容优先**。`output_refs` 保持原样（继续累积 key），既有调用方与契约
   不变；新表是权威记录，投影关系单向（目录 → `output_refs` 的 key 集合）。
2. **唯一键表达重试语义**。`(run_id, stage, attempt, kind, object_key)` 唯一：
   同一阶段同一次尝试对同一对象只登记一次；重试换 `attempt`，历史产物保留
   可查。方案 A 的 JSON 数组做不到。
3. **完整性可校验**。`checksum_sha256` + `size_bytes` 让"产物是否被篡改/截断"
   可回答；摘要只接受 64 位小写十六进制，短串或大小写不符即拒绝。
4. **生命周期边界清晰**。`run_id` 外键 `ON DELETE CASCADE`：运行是产物的
   边界，删除运行即删除其产物记录（对象存储中的对象由保留策略处理，不在
   本表职责内）。

## 4. 产物类型只覆盖对象存储对象

`ProcessingArtifactKind` 只有 `METADATA` / `CANONICAL` /
`TIME_ALIGNMENT_REPORT` 三个取值。

**`QUALITY_PRE_CHECK` 的 `quality-run/<id>` 不在此列**：它是数据库记录引用
（质量结论已落 `quality_runs` 表），不是对象存储对象。把它塞进来会让"产物"
同时指两种东西——一种在对象存储里可下载，一种只能在数据库里查。

## 5. 阶段如何产出

阶段处理器是纯函数，返回 `StageOutcome.artifacts: tuple[StageArtifact, ...]`；
`StageArtifact` 只描述产物（类型 / key / Schema 版本 / 内容类型 / 字节数 /
摘要 / 来源输入），**不**知道项目 / 运行 / 尝试 / 操作者——这些由编排器从
上下文补齐。这样阶段无需依赖仓储，也不会因为"忘了传 project_id"而写出
跨项目行。

编排器在 `_finish_step` 的同一事务内登记产物：步骤说成功、目录却没有产物，
会让"产物在哪"变成只能翻对象存储才能回答的问题。重复执行同一阶段（崩溃
恢复）会跳过已登记行而不是撞唯一键。

## 6. 实现拆分

| 步骤 | 内容 | 状态 |
|---|---|---|
| 1 | 领域 `ProcessingArtifact` + 枚举 + 校验 | 本 ADR 一并落地 |
| 2 | 迁移 0069 + ORM 模型 + 仓储 | 本 ADR 一并落地 |
| 3 | 编排器登记 + 阶段处理器返回 `StageArtifact` | 本 ADR 一并落地 |
| 4 | 只读 API `GET .../processing-runs/{id}/artifacts` + 契约 | 本 ADR 一并落地 |

## 7. 回滚

`git revert` 迁移 0069 与相关代码。`output_refs` 不受影响，既有读取路径
仍可用；升级后登记的产物记录会丢失，但它们只是运行产物的元数据，对象本体
仍在对象存储中。
