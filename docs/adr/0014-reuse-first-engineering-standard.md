# ADR-0014 复用优先与代码质量标准接入决策

- 状态：**ACCEPTED**
- 日期：2026-11-14
- 决策者：System Architect；批准人：用户（长期授权）
- 关联：`docs/DDP_具身智能数据闭环平台建设总规范_V1.0_FINAL.md` §14/§15/§16/§20；`CLAUDE.md`；`AGENTS.md`；ADR-0002、ADR-0006
- 边界：本 ADR 只记录「规范如何接入现有体系」，不新增业务规则；不修改代码、契约或迁移。

## 1. 背景

《DDP 全局研发规范：复用优先与代码质量标准 V1.0》要求纳入项目最高级研发约束，
覆盖全部 Agent、模块与后续任务。用户同时明确要求：**先检查现有 CLAUDE.md、项目文档
与 Agent 配置，融入现有体系，不重复创建规则文件**。

## 2. 现场审计（2026-11-14）

| 资产 | 现状 | 与规范的差距 |
|---|---|---|
| `CLAUDE.md` | 已有基线、代码边界、数据安全、验证、Git 章节 | 缺"开发前审计/复用优先/依赖评估/统一技术栈"强制条款 |
| `AGENTS.md` | 已有角色、输入输出、协作纪律 | 同上，且未声明违规打回机制 |
| 总规范 §14–§16、§20 | 已定义目录、反屎山、契约、Commit/PR | 未以「入口规则」形式约束 Agent |
| `packages/contracts` | OpenAPI 单一入口 + 冻结基线 + lint/oasdiff | 已满足统一契约要求 |
| `make check` | ruff/pytest/vitest/tsc/build/secret 扫描 | 已满足自动闸口要求 |
| ADR 目录 | 0001–0013 | 缺"研发标准接入"决策记录 |

结论：**不新建规则文件**；把规范并入 `CLAUDE.md` 新增章节 `## 复用优先与代码质量标准`，
在 `AGENTS.md` 增加同步摘要与打回条款，并在本 ADR 记录决策。

## 3. 决策

1. `CLAUDE.md` 新增七节强制条款：开发前审计、官方 SDK 优先、依赖评估、统一架构
   /API/DB/UI、模块边界与反屎山、测试审查与版本管理、执行方式。
2. 在 `CLAUDE.md` 文首声明该规范与总规范**同等最高效力**，禁止另立规则文件。
3. `AGENTS.md` 增加同源摘要，明确"违反即打回，不得合并"与三道闸口
   （`make check` → 代码审查 → QA 独立验收）。
4. 复用判定顺序固定为：**复用 > 扩展 > 组合 > 新建**；审计结论必须进入任务与 PR。
5. 技术栈唯一化：httpx / Pydantic v2 / SQLAlchemy 2 / Alembic / antd 5；
   新增依赖需评估用途、替代方案、版本固定、许可证与安全复核。

## 4. 影响

- 正向：所有 Agent 共享同一套研发标准；新建模块必须先证明"不能复用"，
  减少平行实现与技术债；评审有可执行清单。
- 成本：PR 需增加"复用审计结论"与"依赖评估"两段，单次交付文档成本略增。
- 风险：条款过多导致形式化。缓解：只保留可验证要求（审计结论、依赖清单、
  测试命令、闸口），不追加无法核查的口号。

## 5. 执行与验证

- 自动闸口：`bash scripts/check.sh`（ruff、pytest、vitest、tsc、build、secret 扫描、
  Agent Bash 守卫）。
- 人工闸口：代码审查按总规范 §15.16 清单；QA 独立验收按各阶段验收标准。
- 违规处理：已合并的违规登记技术债务（Debt ID、位置、影响、根因、Owner、修复版本）。
