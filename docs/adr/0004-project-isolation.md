# ADR-0004 多项目隔离

- 状态：已提议（待用户批准）
- 日期：2026-11-08
- 关联：规范 §16.4、§19

## 背景

DDP 支持多项目、多基地、多供应商，客户数据必须隔离。仅靠前端隐藏或客户端传入 `project_id`
会产生 IDOR 与跨项目泄漏。

## 决策

- 所有业务表带 `project_id`（或通过所属聚合可推导）。
- 所有查询/更新/删除/下载/导出/搜索/缓存在服务端强制校验 project scope。
- 权限 = 平台角色 + 项目角色 + 资源授权；默认拒绝。
- 缓存 Key 必须包含项目上下文。
- 跨项目共享必须显式授权并留审计。
- 文件下载必须审计；对象存储路径按项目隔离。

## 后果

- 每个 Repository/Application Service 都要带项目上下文，不能提供"无项目"的默认路径。
- 测试必须覆盖越权读写删与跨项目泄漏。
- 后台任务需要显式携带 project scope。

## 替代方案

- 单库单项目：无法支撑多项目，否决。
- 每项目独立库：运维成本高，首期不采用。
