# ADR-0045 质检批量重跑与差异报告：入队不伪造结论、差异按对象对齐

- 状态：**ACCEPTED**
- 日期：2026-11-22
- 决策者：System Architect + 后端；批准人：用户（长期授权）
- 关联：ADR-0042（生命周期与结论正交）、ADR-0043（异步边界）、ADR-0044（结论路由）、V31-030…V31-033
- 约束：不新增表、不新增迁移、不新增错误码、不改既有单次质检语义

## 1. 背景

V31-031 让质检可以异步执行，V31-032 让结论驱动标注提交。但运维重跑一批
Episode 之后，没有任何手段回答「这次重跑改变了什么」：

- 单次 `POST /quality-runs` 一次只能检查一个对象，重跑 100 个要发 100 个请求；
- 两次运行的结论只能分别查 `findings` 列表，人工比对；
- 两个总数（`error_count` 从 3 降到 1）无法定位到具体规则与对象。

## 2. 候选方案

| 方案 | 做法 | 问题 |
|---|---|---|
| A. 批量端点复用同步语义 | 一次请求里同步跑完所有对象 | 请求时长与对象数成正比；100 个对象会撞网关超时，且失败时无法判断"跑到第几个" |
| B. 批量端点只入队（本方案） | 每个对象一条 `QUEUED` 运行 + 投递事件，Worker 领取执行 | 响应里没有结论，调用方要理解"排队 ≠ 通过" |
| C. 差异报告在前端算 | 前端拉两次 findings 自行比对 | 分类规则（`NOT_APPLICABLE` 与 `PASS` 的区别、`subject_ref` 对齐）会散落到每个客户端 |

## 3. 决策

**批量重跑选 B，差异报告选服务端（B 的配套）。**

### 3.1 批量端点只入队，响应使用独立 schema

`POST /quality-runs/batch` 返回 `QueuedQualityRun` 列表，**没有** `status` /
`score` / 六类聚合 / 起止时间。

为什么不复用 `QualityRun`：那个 schema 的 `status` 是必填字符串，排队运行
只能填 `null` 或伪造一个值。前者会让客户端把 `null` 读成"没通过"（与
ADR-0042 要消除的误读同源），后者是伪造结论。独立 schema 让「这条运行
还没有结论」成为类型事实，而不是约定。

### 3.2 差异按 `rule_id + subject_ref` 对齐

`subject_ref` 区分同一规则作用于多个对象（一个 Episode 下的多条标注记录）。
只用 `rule_id` 会把「记录 A 通过、记录 B 失败」错算成「规则状态变化」，
差异报告会给出错误结论。

四个分类：

| 分类 | 含义 |
|---|---|
| `NEW` | 只在候选运行出现——重跑新引入的问题 |
| `RESOLVED` | 只在基线运行出现——重跑修复的问题 |
| `UNCHANGED` | 两次都有且状态相同 |
| `CHANGED` | 两次都有但状态不同 |

`has_regression` **只把 `NEW` 算作回归**：`CHANGED` 可能是 `FAIL → PASS`
（修好），把它算进回归会让报告在"问题减少"时报警。

### 3.3 `NOT_APPLICABLE` 与 `PASS` 必须分开

`NOT_APPLICABLE` 是「规则没有结论」（缺上下文、不适用），`PASS` 是「判过
且通过」。把两者混为一类会让「规则这次没运行」被读成「规则这次通过了」——
与 ADR-0042 的 `INCOMPLETE` 处理同一原则。

### 3.4 不可比的情况显式拒绝

| 情况 | 行为 | 理由 |
|---|---|---|
| 任一运行 `lifecycle != SUCCEEDED` | 422 `validation_failed` | 没有可信结论就没有可比性 |
| 两次运行检查不同对象 | 422 `validation_failed` | 不同对象的结论差异没有业务含义 |
| 同一侧出现重复 `(rule_id, subject_ref)` | 领域层拒绝 | 数据缺陷；不猜"该用哪一条" |
| 空列表 / 重复对象 / 超过 1000 个 | 422 `validation_failed` | 静默成功会让"重跑 0 条"看起来像已完成 |

### 3.5 整批一次提交

批量入队在**同一事务**里完成：要么全部入队，要么全部回滚。不出现「排了
一半」——那会让运维无法判断哪些对象真的被重跑了。

## 4. 后果

- 新增 `domain/quality/diff.py`（分类判定）与 `application/quality/diff.py`
  （差异编排）；批量入队复用 `QualityRunUseCases.rerun_batch`。
- 契约新增 4 个 schema（`QueuedQualityRun` / `QualityRunBatchCreate` /
  `QualityFindingDiff` / `QualityRunDiff`）与 2 个路径，版本 1.30.0。
- 不新增表、不新增迁移、不新增错误码。
- 前端批量重跑与差异报告入口不在本 ADR 范围（后端契约已就绪）。

## 5. 残余风险

| 风险 | 说明 |
|---|---|
| 差异报告一次取全量 findings | 单次运行 findings 受规则数约束（有界），未分页；若未来规则数激增需改游标 |
| 批量上限 1000 是硬编码 | 与单对象资产/记录上限同口径；调整需同时改契约 `maxItems` |
| 前端未接入 | 契约已就绪，前端入口另立任务 |
