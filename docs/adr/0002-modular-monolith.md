# ADR-0002 模块化单体 + 异步 Worker

- 状态：已提议（待用户批准）
- 日期：2026-11-08
- 关联：规范 §3.1、§3.3、§15.11

## 背景

DDP 领域多（采集、接入、处理、标注、质检、资产、训练），但当前是单团队、单仓库、无真实规模证据。
规范明确禁止为追求复杂度而过早微服务化。

## 决策

- 首期采用**模块化单体**：一个后端进程 + 一个 Worker 进程 + 共享数据库。
- 领域模块按 `api / application / domain / infrastructure` 分层，模块间只通过公开 Application API、Contract 或领域事件交互。
- 大文件处理、转码、解析、切片、导出全部进 Worker，不占用 HTTP 线程。
- 只有当出现真实的部署隔离、团队边界或性能瓶颈时，才评估拆分服务，并必须先有 ADR。

## 后果

- 初期部署简单，事务边界清晰。
- 需要严格执行模块边界，避免退化成一个大泥球。
- Worker 与 API 共享领域代码，但入口分离。

## 替代方案

- 微服务：当前无收益，运维成本高，否决。
- 纯单体无 Worker：大文件处理会阻塞请求，否决。
