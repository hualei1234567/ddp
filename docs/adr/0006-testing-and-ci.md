# ADR-0006 测试策略与 CI 门禁

- 状态：已提议（待用户批准）
- 日期：2026-11-08
- 关联：规范 §22

## 背景

平台涉及权限、文件、异步任务、数据血缘与训练交付，任何一处静默失败都会污染数据集。
必须在合并前用自动化门禁挡住。

## 决策

- 测试分层：单元、接口、契约、集成、文件处理、权限、E2E、性能、安全、恢复。
- CI 必过：ruff、pytest、alembic 升级、tsc、eslint、vitest、build、Secret 扫描、依赖扫描。
- 契约检查：OpenAPI 与前端类型/客户端保持一致。
- PR 必须附测试命令与真实结果；未执行标 `NOT RUN`，环境阻塞标 `BLOCKED`。
- 严格区分 Code Complete / Test Passed / QA Accepted / User Accepted / Released。

## 后果

- 阶段 0 即建立 CI，后续每个阶段只增不减。
- 测试失败不得通过放宽断言、跳过用例或删除测试解决。
- 关键业务（状态机、上传恢复、时间同步、数据集冻结、权限隔离）必须有专门用例。

## 替代方案

- 先开发后补测试：会累积不可验证的领域逻辑，否决。
