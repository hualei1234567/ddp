## 五、执行过程中发现的**额外**问题（审计报告之外）

这 3 项不是审计报告里列出的风险，但执行中被真实暴露，已在各自 PR 中修复：

1. **本地 GREEN ≠ CI GREEN**：测试引用仓库根非包目录（`scripts/`）时，本地 `PYTHONPATH` 巧合通过、CI 直接 `ModuleNotFoundError`。已修复并在代码注释中说明（#156）
2. **Promtool 抓到真实语法错误**：初版告警表达式 `and on() (time()-0)>0` 被拒绝，改为 `absent(...)` 后语义更准确（#155）
3. **跨平台 lock 失效**：macOS arm64 生成的 lock 在 Linux CI 安装即红，需在目标平台重新生成（#159）

## 五之二、供应链漏洞（审计执行中新发现，非 R1–R12 登记项）

| 包 | 当前版本 | 修复版本 |
|---|---|---|

| `PyJWT` | 2.10.1 | **≥ 2.12.1** |

**处置**：已定位**最小的可修复组合**——`fastapi 0.133.1`（引入 `starlette 1.10.0`，
这是 starlette 首个修复版本），配合 `PyJWT 2.15.1`、`python-multipart 0.0.34`。
fastapi 从 0.115.6 跨大版本升级到 0.133.1 属**高风险变更**，需全量回归验证
API 兼容性（响应模型/依赖注入/异常处理），已在独立 PR 中执行。

**这是审计执行最重要的增量发现**：审计报告原写「依赖漏洞仅告警」为中风险，
但实际扫描出的漏洞规模（48 条）远超预期，直接驱动了一次跨大版本的依赖升级。

## 七、诚实边界（再次声明）

- **写路径压测是「事务骨架」级别**：审计+outbox 双写，**不代表**端到端 HTTP 写接口延迟（业务校验耗时与跨表事务未覆盖）
- **覆盖率只有行覆盖**，未启用分支覆盖（会显著更低）
- **索引审计是单机小数据量**（最大表 240 行），「0 个可删」不代表大数据生产环境下同样成立——`index_audit.py` 可在数据增长后重跑
- **Semgrep 27 条误报分诊是人工判断**，`# nosemgrep` 理由已写，但误报判定本身有主观成分
- **Semgrep registry 随上游漂移**：semgrep.dev 不可达时该步会失败，无离线兜底（已写入代码注释）
- **监控栈的外部接收端投递未验证**：本地只证明规则能触发、告警能进 UI
