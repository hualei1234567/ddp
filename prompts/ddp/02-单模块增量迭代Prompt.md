## 执行要求

1. 先检查 Git 状态和当前分支，保护所有未提交改动。
2. 定位当前模块已有页面、组件、API、服务、数据表和测试。
3. 说明哪些能力可直接复用，哪些确实需要补齐。
4. 输出实施计划、文件影响范围、API / Schema 影响、权限影响和风险。
5. 如果涉及公共架构、破坏性 Migration 或范围扩张，先等待我确认。
6. 获准后只做最小必要改动，不顺手重构无关模块。
7. 沿用现有 UI、代码风格、技术栈、认证、存储和任务机制。
8. 执行适用测试与关键回归测试。
9. 更新对应文档和 PR 描述。
10. 汇报真实修改文件、测试命令及结果、遗留问题。

## 禁止事项

禁止重建已有模块、复制一套平行实现、替换技术栈、虚构测试结果、删除失败测试或使用假数据冒充真实功能。

完成后按 Definition of Done 汇报，不要自行合并受保护分支。
