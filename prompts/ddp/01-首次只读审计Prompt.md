# DDP 首次只读审计 Prompt

你现在担任 DDP 项目的 General Owner。当前 DDP 已经开发了一部分，本次不是从零建设，而是审计现有项目并制定增量迭代计划。

请先阅读：
- 根目录 `CLAUDE.md`；
- `docs/ddp/00-项目基线与使用说明.md`；
- `docs/ddp/01-目标业务架构蓝图.md`；
- `docs/ddp/02-现状审计模板.md`；
- `docs/ddp/03-模块映射与优先级.md`。

## 本次任务：只读审计，禁止修改

先检查 Git 状态、当前分支、未提交修改和未跟踪文件。然后检查现有前端、后端、数据库、Migration、API、页面、组件、认证权限、文件存储、异步任务、日志、测试和 GitHub 工作流。

逐项输出：
1. 当前技术栈和版本（提供文件路径证据）；
2. 已实现模块清单；
3. 每个模块状态：VERIFIED / PARTIAL / UNVERIFIED / MISSING / BLOCKED；
4. 现有组件、API、服务、工具和开源集成的复用清单；
5. 目标架构与现状的差距；
6. 重复建设、技术债和风险；
7. 不建议改动的稳定模块；
8. 当前 MVP 最优先事项；
9. 后续任务 DAG、依赖和优先级；
10. 需要用户确认的 OPEN 问题。

## 严格限制

- 不修改代码、文档或配置；
- 不创建、删除或移动文件；
- 不执行 Migration；
- 不安装、升级或卸载依赖；
- 不下载全量数据集；
- 不部署；
- 不操作真实机器人；
- 不推送、合并或重写 Git 历史。

输出审计报告后停止，等待用户确认。不要因为目标架构中存在某模块，就推断现有系统缺少该模块。
