执行顺序：
1. 检查 Git 状态，保护未提交改动。
2. 定位调用链、相关代码、配置和数据。
3. 尽可能稳定复现，区分根因与表面症状。
4. 检查是否已有相似问题或已有修复。
5. 提出最小修复方案和影响范围。
6. 修复根因，不绕过业务规则。
7. 添加或更新回归测试。
8. 执行相关测试和关键回归。
9. 汇报根因、修改文件、测试结果和遗留风险。

禁止通过吞异常、跳过校验、放宽测试断言、硬编码特例或删除功能来掩盖问题。
